# 现场运行与故障排查手册

> 本文面向现场操作、联调和故障分析。任何恢复操作都必须以设备实际安全状态为前提，不能用复位、重启或断开网络代替机械安全确认。

## 1. 日志位置与追踪方法

程序日志保存在工程目录的 `Log` 子目录，文件名为“当天日期 + ` log.txt`”，编码为 UTF-8。界面只保留最近 200 行，分析较早故障时应读取日志文件。

任务日志优先按以下顺序定位：

1. 查找任务前缀 `[T#任务号 S工位号][阶段]`。
2. 确认整线状态：`Idle`、`Running`、`ReturningHome` 或 `Error`。
3. 确认任务状态：`Pending`、`Running`、`Succeeded`、`Failed` 或 `Canceled`。
4. 沿 AGV、机械臂、视觉、扫码、码垛或充电前缀向前查找第一条异常。
5. 不要把后续清理失败误认为最初故障原因。

现场反馈至少保留：

- 故障发生时间；
- 任务号和工位号；
- 完整日志文件；
- 主调度和当前任务状态截图；
- AGV 当前站点、导航站点、导航状态和电量；
- 机械臂实际 TCP、运动状态、暂停状态和控制器状态文本；
- 视觉候选摘要、`frame_id` 和 `timestamp`；
- 涉及充电时的输出电压、电流、输入字、输出字、事件字和故障字。

## 2. 启动前检查

### 2.1 软件和配置

- 确认当前运行程序版本与预期一致。
- 确认机械臂、AGV、视觉、扫码器、客户系统和充电桩地址。
- 确认工位到 LM 的映射和示教函数与现场一致。
- 确认手眼矩阵、TCP、UCS 和视觉服务使用同一套标定关系。
- 确认运行参数和充电参数已成功加载，没有回退警告。
- 确认码垛区未满，LM16、LM17 已按现场实际配置核对。

### 2.2 设备状态

- AGV 已连接，定位状态正常，没有被外部抢占控制权。
- 机械臂已连接，处于自动、待机、就绪或空闲语义，不在暂停或运动中。
- 视觉 `/status` 可访问，推理响应包含预期字段。
- 扫码器网络可达，生产扫码与测试扫码没有并发占用。
- 自动充电启用前，AGV 监控快照完整且未过期。
- 充电桩开始前执行实时只读预检，不能使用旧界面状态代替。

## 3. 正常运行基线

正常生产主线应表现为：

1. 主调度从 `Idle` 经人工启动进入 `Running`。
2. 缺料事件进入 FIFO，产生独立任务号。
3. 没有充电派单保持且执行器空闲时取出队首。
4. 单任务依次完成取料导航、视觉抓取、扫码、倒料和空箱码垛。
5. 普通任务失败且安全收姿态成功时，可继续下一任务。
6. 系统级错误进入 `Error`，停止设备并清理待执行任务。
7. 队列为空后 AGV 返回 LM1，主调度保持 `Running` 等待缺料。

## 4. 整线状态排查

| 现象 | 首查证据 | 当前语义 | 允许的恢复 |
|---|---|---|---|
| 点击开始无反应 | `LineManager` 日志 | 可能不在 `Idle`、旧流程运行或机械臂被测试占用 | 先消除互斥原因 |
| 缺料已发生但不入队 | 工位号、整线状态 | 非 1～12 被忽略；`Error` 时拒绝新缺料 | 修正输入或完成错误复位 |
| 已入队但不派单 | 充电保持、执行器忙碌、整线状态 | 保持只阻止新队首，不清 FIFO | 等待当前动作或安全结束充电 |
| 队列空但 AGV 未回 LM1 | AGV 完整快照、返航日志 | 可能正在返航或没有可靠快照 | 不要重复派单，先确认导航状态 |
| 系统处于 `Error` | 第一条“系统报警”日志 | 设备或状态不可安全解释 | 排除原因后调用错误复位，再重新启动 |

`resetError()` 只把整线恢复到 `Idle`，不会恢复被取消的任务，也不会自动重新开始。

## 5. AGV 故障排查

### 5.1 导航不启动

检查：

- Modbus TCP 是否连接；
- 目标 LM 是否正确；
- `ctrlSeized` 是否为真；
- 导航状态是否仍为 `Waiting`、`Running` 或 `Paused`；
- 是否存在充电返航或其他导航所有者；
- 业务 LM 到物理站点的映射是否一致。

禁止：

- 在生产任务、返航或自动充电已拥有导航时，从调试界面再次派单；
- 把写目标站点成功视为已开始或已到达。

### 5.2 到站但流程不推进

任务导航和返 LM1 都不能消费上一次残留的 `Arrived`。必须先观察到本轮进入 `Waiting` 或 `Running`，再接受：

- `navStatus=Arrived`；
- `navStation` 等于目标 LM；
- `curStation` 等于目标 LM。

三者不一致时，保存完整 AGV 快照并检查地图站点配置。

### 5.3 导航失败或超时

`Failed`、`Canceled`、`Timeout` 都不是安全到站证据。返 LM1 超时会进入整线 `Error`。检查现场障碍、地图、控制权、定位状态和仙工系统任务记录后再复位。

## 6. 机械臂和视觉故障排查

详细逻辑见《华沿机械臂视觉抓取与运动判断》。

| 现象 | 首查证据 | 判断重点 |
|---|---|---|
| SDK 调用返回成功但机械臂未动 | moving、pause、FSM、命令编号 | SDK 返回零只表示接口接受 |
| 机械臂已停但流程不推进 | blending 变化、实际 TCP、目标位姿 | 不能只看 `moving=false` |
| 一直等待命令就绪 | `ProgramStopped`、`RobotInMoving`、暂停状态 | 门控最长等待 8 秒 |
| 视觉无目标 | 候选摘要、ROI、相机画面 | 初始阶段可搜索下移，验证阶段必须失败 |
| 目标突然切换 | 锚点、锁定距离、丢失帧数 | 闭环不能切到相邻目标 |
| XY/Rz 反复修正 | 工具系方向、精修次数、真实新帧 | Y 和 Rz 方向与视觉量相反 |
| Z 一直不稳定 | 五帧数据、核心极差、窗口耗时 | 只统计真实新帧，4～8 秒窗口 |
| Z 下探被拒绝 | 视觉深度、工位余量、计划下探量 | 超过硬上限必须拒绝 |

视觉或联合对准失败后，禁止使用上一帧坐标继续抓取，也禁止绕过 `HuayanScheduler` 手工补发运动。

## 7. 扫码故障排查

检查：

- 扫码 IP、端口和网络；
- 超时、最大尝试次数和重试间隔；
- 当前结果状态和实际尝试次数；
- 生产扫码是否在夹紧前安全暂停点触发；
- 测试扫码是否占用厂商 SDK；
- 条码原始数据的编码和清理结果。

扫码失败后的搜索移动属于阶段一内部补救动作。未经现场旋转空间安全确认，不得开启 180° 工具旋转补救。

## 8. 码垛故障排查

检查：

- 当前工位对应的码垛区域；
- 码垛区 LM、基准函数和松爪函数；
- `PalletScheduler` 当前已放置数量；
- 候选位置是否只预览、尚未提交；
- 机械臂是否完整完成松爪和回运行安全位。

机械臂放置失败时不得手工增加已放置数量。只有 `palletPlaceCompleted` 后才能 `commitPlaced`。

## 9. 自动充电故障排查

### 9.1 低电后不开始充电

依次确认：

- 自动授权是否真正通过预检并生效；
- 主调度是否已启动且不在 `Error`；
- AGV 快照是否完整、未过期；
- 当前生产任务是否仍在执行；
- 派单保持是否已建立；
- AGV 是否已到 LM1；
- 导航是否为 `None` 或 `Arrived`；
- 充电控制器是否空闲且状态可解释；
- 即时只读预检是否通过；
- DO0 是否明确确认高电平。

### 9.2 充电结束后不恢复派单

这是保守行为。检查：

- 会话来源是否为 `Automatic`；
- 充电桩是否报告 `SafeComplete`；
- 输出电流、工作位和继电器是否明确关闭；
- 推杆是否明确缩到位；
- 最终完整查询是否成功；
- DO0 关闭是否已尝试；
- 当前电量是否达到允许接单阈值。

不得通过手工解除派单保持绕过不安全终态。

### 9.3 状态为 `Fault` 或 `Unknown`

`Fault` 表示已知故障，`Unknown` 表示写命令或现场状态无法证明。两者都不能当作安全完成。应保留日志和五组快照，执行唯一控制器的安全停止或保守恢复；仍不能证明安全时必须人工检查。

## 10. 应用退出

若充电桩仍可能有输出、机构未缩回或写命令结果未知，程序关闭会被冻结并请求安全收尾。不得通过结束进程、断网或强制关机代替：

1. 停止输出；
2. 确认无输出；
3. 缩回机构；
4. 释放缩回命令；
5. 复位；
6. 最终完整安全查询。

如果自动充电未参与主调度，且没有手动/自动充电会话、没有 DO0 置高或保持高电平、没有应用关闭收尾在途，也没有 `Fault` / `Unknown`，仅仅因为控制器尚无 `SafeComplete` 安全基线时，关闭窗口不会被充电安全逻辑拦截。此时若还存在尚未进入 DO0 的预检意图，程序会取消该意图，迟到的查询结果不能继续启动充电动作。

如果曾经进入手动充电、自动充电、DO0 打开、保守恢复，或重连后已经发现 `Fault` / `Unknown`，仍按真实设备安全事实处理，不能用“自动充电未开启”作为关闭放行依据。

若现场必须强制退出，必须保留强制退出确认日志，并由人员确认设备实际状态。

## 11. 禁止性操作

- 不得同时运行 `LineManager` 和旧 `LineOrchestrator`。
- 不得在设备动作中途直接修改运行参数或充电参数。
- 不得使用旧 AGV 快照、旧视觉请求或旧坐标推进新任务。
- 不得把 SDK/Modbus 写响应当作物理动作完成。
- 不得绕过调度器直接并发调用设备原语。
- 不得在充电状态未知时恢复生产派单。
