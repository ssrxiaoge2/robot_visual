# `robot_visual` 项目认知入口

> 适用版本：项目版本 `0.3.0`
> 事实来源：当前 `src`、`tests`、`CMakeLists.txt` 与 `AGENTS.md`

## 1. 本文档的用途

本文档是开发人员和智能体理解工程的首要入口。处理具体问题时，应先根据下表确定阅读范围，不要默认遍历整个 `src`、`tests` 和历史设计文档。

项目当前生产主线是 `LineManager + TaskExecutor`。`LineOrchestrator` 是保留的旧单工位参考流程，不是 12 工位连续补料主线。任何改动前都必须先区分这两条路径。

## 2. 推荐阅读顺序

1. 阅读本文档，判断改动属于哪个调度域。
2. 阅读《系统架构与模块职责》了解所有权和依赖边界。
3. 阅读《核心调度与业务流程》定位正常流程、状态变化和信号链。
4. 涉及异常、停止、恢复、充电或设备动作时，阅读《状态机与安全约束》。
5. 涉及机械臂移动、视觉抓取或到位判断时，阅读《华沿机械臂视觉抓取与运动判断》。
6. 现场故障、联调或恢复操作，阅读《现场运行与故障排查手册》。
7. 涉及协议字段、单位、寄存器、外部信号或跨系统数据，阅读《外部接口信号与数据字典》。
8. 修改任何核心行为前，阅读《关键业务不变量与现场约束》。
9. 根据《代码符号与测试索引》只打开相关源文件和测试。
10. 需要追溯设计原因时，最后再查阅 `docs/superpowers/specs`、`plans` 和 `reports`。

## 4. 当前系统一句话模型

外部或模拟缺料事件由 `LineManager` 转为 FIFO 任务，`TaskExecutor` 顺序协调 AGV、机械臂、视觉、扫码和码垛；`AutoChargeCoordinator` 根据业务快照产生暂停派单、返航、充电或安全停止意图，所有真实设备对象和跨模块接线统一归 `DeviceManager` 管理。

## 5. 当前最重要的边界

- `DeviceManager` 是设备对象和跨线程工作对象的唯一所有者与接线中心。
- `LineManager` 拥有生产主线生命周期、FIFO 派单、返 LM1 和系统级错误语义。
- `TaskExecutor` 一次只执行一个任务，不管理整线队列，也不负责自动充电。
- `AutoChargeCoordinator` 只产生业务意图，不直接操作队列、AGV 或充电桩。
- `ChargePileController` 独占充电桩协议状态机和安全收尾。
- `HuayanScheduler` 独占机械臂 SDK 调度、视觉对准和动作完成判断。
- `MainWindow` 只负责展示、输入和信号转发，不应拥有设备协议或调度规则。
- `LineOrchestrator` 与 `LineManager` 不得同时控制 AGV 和机械臂。

## 6. 历史文档的使用方式

`docs/superpowers` 下的设计、计划和报告用于解释某项功能当时为何这样实现，但它们不自动代表当前代码。若历史文档与本目录或当前代码冲突，以当前代码为事实依据，并在提交前修正本目录下的项目认知文档。
