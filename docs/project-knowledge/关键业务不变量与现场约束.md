# 关键业务不变量与现场约束

> 本文是修改代码前必须阅读的安全底线。若需求确实要改变其中一条，必须先明确新的系统级设计、测试和现场验证方案，不能把它当作普通局部优化。

## 1. 调度与任务

1. `LineManager + TaskExecutor` 是当前 12 工位生产主线。
2. `LineOrchestrator` 是旧单工位兼容流程，不是新缺料功能入口。
3. 两个顶层调度器不能同时控制 AGV 和机械臂。
4. 同一时间最多一个生产任务处于 `Running`。
5. `TaskQueue` 只保存 `Pending`，当前任务由 `LineManager` 单独保存。
6. 同一工位的每次合法缺料当前都代表独立任务，不自动去重。
7. `Error` 状态拒绝新缺料事件。
8. 普通任务失败只有在安全收姿态成功后才能继续 FIFO。
9. 系统级错误必须停止设备、取消待执行任务并进入 `Error`。
10. 错误复位只回到 `Idle`，不会恢复被取消的任务。

## 2. 设备所有权

1. `DeviceManager` 是设备对象和跨线程工作对象的唯一所有者与接线中心。
2. UI、调度器和对话框不得创建第二个 AGV、机械臂、扫码或充电控制器。
3. 调度层只能调用设备高层接口，不能散落 Modbus、HTTP 或华沿 SDK 原语。
4. 跨线程结果必须通过 Qt 信号槽返回。
5. 生产扫码和测试扫码必须隔离结果，厂商 SDK 访问必须串行。

## 3. AGV

1. 只有完整 `AgvMonitorData` 快照能用于跨字段决策。
2. 任务到站不能只看 `Arrived`，必须先看到本轮导航运动，再核对导航站点和当前站点。
3. 自动充电返航必须通过 `LineManager` 的唯一返航入口。
4. `Paused`、`Failed`、`Canceled` 和 `Timeout` 不是导航空闲或到站证据。
5. 自动充电只能在 LM1 且导航状态为 `None` 或 `Arrived` 时继续启动判断。
6. AGV 写命令成功不等于导航或 DO0 物理状态已完成。
7. DO0 必须通过只读状态确认；确认失败时占位值不能参与安全判断。

## 4. 机械臂和视觉

1. `HuayanScheduler` 是华沿 SDK 动作的唯一调度器。
2. 已有待命令或活动命令时，不得覆盖或并发下发新命令。
3. SDK 返回零只表示接口接受，不表示机械臂到位。
4. 视觉运动完成必须有本轮 blending 变化或实际 TCP 到达目标的证据。
5. `moving=false` 不能单独证明新命令完成。
6. 旧视觉请求、旧帧和旧坐标不能推进新任务或新阶段。
7. 运动后的视觉帧必须满足 `frame_id` 和 `timestamp` 同时严格递增。
8. 目标锁定后不得静默切换到相邻目标。
9. 验证阶段目标丢失、被拒绝或视觉错误时不得使用旧坐标继续抓取。
10. 首次视觉平面对准使用一条绝对 `MoveJ`，精修使用一条工具系联合 `MoveL`。
11. 联合 X/Y/Rz 精修不得拆成多个独立运动。
12. 大角度 Rz 必须经过两个真实新帧确认，同一目标周期最多实际执行一次。
13. 最终 Z 下探必须先检查未截断计划值，超过硬上限直接拒绝。
14. 稳定 Z 只统计真实新帧，使用固定观察窗口和稳健深度。
15. 联合对准失败信号发出前调度器已停止，上层不得再次启动冲突清理动作。

## 5. 扫码和抓取

1. 生产扫码发生在夹紧前安全暂停点。
2. 扫码通过前不得夹紧料箱。
3. 扫码搜索补救不能破坏暂停中的阶段一状态。
4. 180° 工具旋转补救默认关闭，只有现场清空旋转空间并确认人员隔离后才能启用。
5. 夹紧后的离开路径由工位 `AfterGripMode` 明确决定，不能默认复用拍照函数。

## 6. 码垛

1. `PalletScheduler` 的候选位置与提交占用必须分离。
2. 读取下一位置不能改变已放置数量。
3. 只有机械臂完整放置成功后才能 `commitPlaced`。
4. 动作失败、超时或取消不能消耗码垛位置。
5. 主流程和配置界面必须共用同一个 `PalletScheduler`。

## 7. 自动充电

1. `AutoChargeCoordinator` 只产生意图，不直接控制队列、AGV 或充电桩。
2. 自动充电只阻止取新队首，不打断正在执行的安全任务动作。
3. 正在执行的任务低电时允许完成，随后保持 FIFO 并返 LM1。
4. 自动开始必须经过业务门禁、即时只读预检、DO0 确认和唯一充电控制器。
5. 手动会话与自动会话所有权不能混淆。
6. 关闭自动授权不等于立即解除派单保持。
7. 停止输出、确认无输出、缩回、复位和最终查询完成前不能报告安全完成。
8. `Fault` 和 `Unknown` 都不是安全终态。
9. 写命令结果未知时不得重复相同危险写命令，必须走保守恢复。
10. 自动会话不安全结束时必须保留所有权，不能释放生产派单。
11. 充电期间 AGV 监控失效必须安全停止并升级系统错误。
12. 程序退出不能通过断网或析构代替充电安全收尾。
13. 关闭窗口时，只有缺少安全基线且没有真实充电责任、自动策略未参与主调度时才允许不拦截；`Fault`、`Unknown`、活动会话、自动会话、DO0 置高或应用关闭收尾在途仍必须拦截。
14. 关闭窗口被放行时，尚未进入 DO0 的充电预检意图必须取消，迟到结果不得继续启动 DO0 或充电动作。

## 8. 配置和现场值

1. 工位 LM、示教函数和夹后路径以 `lineconfig.h` 为当前代码事实来源。
2. LM16、LM17 仍带现场待替换语义，投产前必须核对。
3. TCP、UCS、手眼矩阵和视觉坐标变换必须作为一套整体校验。
4. 运行参数和充电参数只能通过校验、持久化和应用事务更新。
5. 在途任务、充电会话或恢复阶段不得热改会破坏一致性的参数。
6. 现场验证后的硬上限不能为临时调试随意放大。

## 9. 当前尚未实现或尚未确认

- 客户系统日数据目前不会自动生成缺料任务。
- 真实缺料信号的幂等、去抖、重发确认和事件有效期尚待设计。
- `TaskSource::CustomerSystem` 是预留来源，当前入队仍使用 `UiMock`。
- LM16、LM17 必须与现场地图重新核对。
- 旧 `LineOrchestrator` 仍保留兼容性，不能误认为已经删除。

## 10. 修改本文件中约束的要求

改变任一不变量前必须：

1. 指出要改变的条目和业务原因。
2. 画出改变前后的状态或时序。
3. 分析正在执行任务、Pending FIFO、自动充电和应用退出的组合状态。
4. 增加正常、失败、超时、重复回调和恢复测试。
5. 更新所有受影响的项目认知文档。
6. 完成相应设备的现场验证后再宣布约束改变完成。
