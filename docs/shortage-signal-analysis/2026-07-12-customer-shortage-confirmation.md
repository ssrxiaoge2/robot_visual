## 1. 总结论

客户已确认：现场缺料判断以上位机软件计算为准。

这意味着上位机不是简单显示缺料信号，而是要维护一套完整的库存账本。后续产线运行时，每个工位当前还有多少料、是否低于安全库存、是否需要继续补料，都以上位机记录和计算结果为准。

因此，对上位机有较高要求：

- 必须准确保存每个工位当前库存。
- 必须准确记录每个工位已补料、正在补料、待补料状态。
- 必须在断电重启、程序重启、通信断线恢复后找回之前状态。
- 必须能配置和保存客户最新安全库存表参数。
- 必须能按照最新 Sheet3 的用量和安全库存上下限进行计算。

如果上位机状态丢失或计算错误，就可能直接导致误补、漏补或重复补料。

## 2. 已确认事项

### 2.1 以上位机软件库存为准

客户确认，缺料判断以上位机软件计算结果为准。

也就是说，后续不再把“客户真实库存接口”或“新增硬件料位信号”作为当前主方案。上位机需要根据现场生产数量、产品模式、配置参数和机器人倒料结果，持续维护库存。

### 2.2 现场初始状态为 0

客户确认，实际产线运行前，会提前把所有工位的料都清空，保持现场为 0 的状态。

所以上位机初始状态也必须保持为 0。

这点非常重要。之前讨论过“安全库存 + 一箱”的初始估算方式，现在不再作为正式运行方案。

正式运行开始时应理解为：

```text
现场所有工位物料 = 0
上位机记录所有工位库存 = 0
```

然后由上位机安排机器人先补料，把需要补料的工位补到安全库存最高位以上。

### 2.3 断电重启、通信断线、程序重启必须保存状态

客户确认，断电重启、通信断线、上位机程序重启后，上位机必须记录并恢复之前所有状态。

需要保存的状态包括：

- 每个工位当前库存。
- 当前产品和生产模式。
- 每个工位最低安全位和最高安全位。
- 每个工位每箱数量。
- 每个工位在当前模式下的用量。
- 已经加入队列但还没执行的补料任务。
- 正在执行的补料任务。
- 已经倒料但任务还没完全结束的任务。
- 最近一次已经处理到的生产数量。
- 当前是否处于初始补料阶段。
- 当前某个工位是否正在连续补料到最高位。

如果这些状态不能保存，程序重启后就不知道现场真实进度，不能直接继续自动运行。

### 2.4 用量策略以最新安全库存表 Sheet3 为准

客户确认，用量策略以安全库存表格中的 Sheet3 为准。

不再以 Sheet2 为准，也不再使用 Sheet2 空值回退 Sheet1 的规则。

Sheet3 中已经对三种模式下每个工位的用料数量做了详细列举：

- L/R：左右。
- L/L：目前只有左。
- R/H：只有右。

其中 L/L 和 R/H 这两种模式下，有的工位不消耗物料。对于这些工位，上位机不应扣减库存，也不应因为该模式触发这些工位补料。

### 2.5 安全库存改为最低位和最高位

客户确认，安全库存不再是一个单独的阈值，而是一个范围：

- 最低安全位。
- 最高安全位。

运行规则：

```text
库存低于最低安全位 -> 必须开始送料
库存达到或超过最高安全位 -> 停止送料
```

也就是说，系统不是补一箱就结束，而是要补至达到或超过最高安全位才停止。由于现场是一箱一箱倒料，如果倒入一箱后超过最高位，这是允许的。

### 2.6 初始补料规则

客户确认，初始状态所有工位库存都是 0。

因此正式运行前，系统应先进入“初始补料阶段”：

1. 所有启用工位库存从 0 开始。
2. 上位机根据 Sheet3 配置判断哪些工位需要补料。
3. 机器人按上位机任务补料。
4. 每次倒料成功后，该工位库存增加一箱。
5. 直到该工位库存达到或超过最高安全位，才认为该工位初始补料完成。

客户已确认初始补料期间产线允许同时生产。因此初始补料阶段不能理解成“先静态补满，再开始扣料”，而应理解成“动态建库”：倒料成功时库存增加，产量增加时库存同步扣减。

### 2.7 同一工位持续缺料时，先补完该工位

客户确认，如果一个工位一直缺料，加入队列后，应该先把同一工位送完料，再送其他工位。

通俗理解：

如果工位 A 低于最低安全位，系统不能只给 A 补一箱就马上切去补 B，而是要先把 A 补至达到或超过最高安全位。A 达到目标后，再处理其他工位。

这样做的好处：

- 能保证已经缺料的工位尽快恢复到安全范围。
- 避免同一工位长期处于低库存状态。

需要注意：

- 如果多个工位都已经低于最低安全位，则按触发时间排序，谁先低于最低位谁先补。
- 这个规则会影响整体补料顺序和节拍，但符合客户最新确认的优先策略。

### 2.8 Sheet3 配置需要做成可视化页面

客户确认，Sheet3 中所有数据都需要做成单独的可视化配置页面。

原因：

现场参数可能会因客户数据调整而改变，我们也需要能在现场修改。

配置页面至少需要支持：

- L/R、L/L、R/H 三种模式。
- 每种模式下 12 个工位的用量。
- 每个工位每箱数量。
- 每个工位最低安全位。
- 每个工位最高安全位。
- 每个工位是否启用。
- Sheet3 中新增的临时 NO、T。
- 上位机代码工位和现场 12 个料口的对应关系。
- 保存参数按钮。
- 参数保存到文件。
- 下次启动加载最新保存的配置。

配置页面需要有基本校验：

- 最高安全位必须大于最低安全位。
- 每箱数量必须大于 0。
- 用量不能为负数。
- 启用工位必须有有效工位映射。

### 2.9 Sheet2 空值回退 Sheet1 规则废弃

客户确认，之前 Sheet2 空值被代码回退成 Sheet1 值的逻辑不再使用。

后续以 Sheet3 为准。

这意味着：

- 不再从 Sheet2 判断用量。
- 不再因为 Sheet2 空值去找 Sheet1。
- Sheet1、Sheet2 只作为历史参考，不作为正式上位机缺料计算依据。

### 2.10 工位映射确认

客户确认：

- Sheet1 图表中工位 8 和 10 之间的空工位不用。
- Sheet3 中新增了临时 NO、T。
- 这 12 个料口和上位机代码中的对应关系是确定的。
- 后续上位机代码工位可能会根据仙工 RDS 和 M4 调度整体修改。
- 目前先保持代码中的工位不变。

因此，当前阶段应按现有上位机代码工位运行，但配置页面中需要清楚展示“代码工位”和“现场料口”的对应关系。

### 2.11 换型策略

客户确认，换型时采用：

```text
旧任务完成后，再派新任务
```

也就是说，当前已经进入队列或正在执行的旧模式任务，应先执行完。旧任务没有完成前，不应自动派新模式任务。

客户补充确认：换型很快，换型期间产线上有 5 个空托盘用于占位，这 5 个占位托盘不增加 `actualQty`，也不占用物料消耗。所以上位机不需要额外识别这 5 个占位托盘，只需要在产品/模式信号稳定后切换后续消耗配置。

换型后不清空工位物料，上位机沿用当前库存，只切换后续产品和模式对应的用量。

### 2.12 `actualQty` 清零只按数值序列判断

工控机时间可能与现场存在误差，因此不使用“每天 20:00”作为清零判断条件，只观察 `actualQty`：

- `1000 → 2 → 5`：确认进入新周期，按新周期从 0 到 5 的累计产量扣减；库存本身不清零。
- `1000 → 900 → 500 → 0 → 2 → 5`：900、500、0 只用于持续更新更小的清零候选，不在下降过程中扣减；第一次从 0 回升到 2 时确认新周期，随后累计到 5，合计只按新周期产量 5 扣减。
- `1000 → 2 → 1005`：把 2 视为毛刺，只按旧基线到 1005 的增量 5 扣减。
- 第一次看到回退值时先进入候选状态，不立即覆盖旧基线，也不立即扣减；候选期继续回退时只更新所见最小候选值。

离散采样可能只看到 `1000 → 2`，但现场实际在两次采样之间经历了若干旧周期尾数、0、2。当前上位机无法凭离散 `actualQty` 追回未采到的旧周期尾数，必须在日志和现场验收单中明确记录这项误差边界。若客户不能接受，需要额外提供清零信号、清零前最终计数或持续不清零的计数器。

## 3. 新的完整运行逻辑

### 3.1 第一步：配置加载

上位机启动后，先加载保存的配置文件。

配置内容来自最新 Sheet3，包括：

- 模式。
- 工位。
- 每箱数量。
- 用量。
- 最低安全位。
- 最高安全位。
- 是否启用。
- 工位对应关系。

如果配置文件不存在、损坏或参数不合法，上位机不能进入自动运行。

### 3.2 第二步：状态恢复或新建初始化

上位机启动后要判断：

1. 是否存在上次保存的运行状态。
2. 是否需要恢复上次状态。
3. 是否由客户确认现场已清空，要重新从 0 开始。

如果是恢复状态：

- 读取上次每个工位库存。
- 读取上次任务状态。
- 读取上次生产数量基线。
- 继续之前的运行逻辑。

如果是新建初始化：

- 必须由现场确认所有工位已清空。
- 上位机把所有启用工位库存设为 0。
- 开始初始补料。

### 3.3 第三步：初始补料

初始补料阶段，上位机的目标是把所有启用工位补至达到或超过最高安全位。

示例：

```text
某工位当前库存 = 0
最低安全位 = 500
最高安全位 = 1000
每箱数量 = 300

机器人每倒料成功一箱，库存 +300
0 -> 300 -> 600 -> 900 -> 1200
1200 已超过 1000，停止该工位补料
```

### 3.4 第四步：正常生产扣减

产线正常生产时，上位机读取生产数量变化。

每次生产数量增加后，上位机按当前模式和 Sheet3 用量扣减各工位库存。

示例：

```text
生产数量增加 10 件
某工位当前模式用量 = 2
该工位库存扣减 20
```

如果当前模式下某工位用量为 0，则该工位不扣减。

### 3.5 第五步：低于最低位触发补料

当某工位库存低于最低安全位时，上位机创建补料计划。

补料目标不是“补一箱”，而是：

```text
补到库存达到或超过最高安全位
```

### 3.6 第六步：倒料成功后库存增加

机器人实际倒料成功后，上位机给该工位库存增加一箱。

如果增加后仍未达到最高安全位，则继续给该工位安排下一箱。

如果已经达到或超过最高安全位，则该工位本轮补料完成。

### 3.7 第七步：同工位优先补满

如果某工位正在补料，并且还没有补到最高安全位，则应继续优先补该工位。

只有该工位补至达到或超过最高安全位后，才处理其他工位；如果其他工位已经低于最低安全位，则按触发时间进入紧急补料顺序。

## 4. 异常情况处理

### 4.1 通信断线

通信断线时，上位机不能丢失当前库存状态。

建议规则：

- 通信断线时不清空库存，不丢弃任务状态。
- 保存当前所有库存和任务状态。
- 已经在执行的机器人任务按主调度安全规则处理。
- 通信恢复后，根据保存状态继续。
- 通信断线超过 10 分钟报警。

客户已确认：断线期间不允许换产品、不允许换模式。通信恢复后，上位机按断线前后 `actualQty` 的差值自动补扣库存。

边界条件：如果后续客户系统规则发生变化，允许断线期间换产品或换模式，则不能继续自动补扣，必须增加人工确认或额外识别信号。

### 4.2 程序重启

程序重启后不能自动重新从 0 开始，除非现场确认所有工位已经清空。

正常情况应：

1. 加载上次保存的状态。
2. 显示恢复结果。
3. 由操作人员确认继续运行。

如果状态文件丢失或损坏：

- 上位机不能直接自动运行。
- 应优先从备份状态和操作日志恢复。
- 如果备份和日志都无法恢复，需要人工确认现场库存，或重新清空所有工位后从 0 初始化。

客户希望由上位机尽量保证状态数据可靠。因此建议上位机采用主状态文件、备份状态文件、操作流水日志三层保护，降低断电或异常退出导致状态不可恢复的风险。

### 4.3 断电重启

断电重启和程序重启类似，但风险更高。

要求：

- 每次库存变化都应尽快保存。
- 每次任务状态变化都应保存。
- 保存文件应尽量防止写一半损坏。

断电恢复后，系统必须能知道：

- 哪些工位库存是多少。
- 哪些任务已经入队。
- 哪些任务正在执行。
- 哪些任务已经倒料但还没完整结束。

### 4.4 换型

客户确认旧任务完成后再派新任务。

换型时建议上位机进入“换型等待”状态：

- 旧任务继续完成。
- 新任务暂不派发。
- 旧任务全部完成后，再根据新模式配置继续运行。

客户已确认换型期间有 5 个空托盘占位，并保证这 5 个占位托盘不会增加 `actualQty`。换型后现场不清空工位物料，上位机沿用当前库存，只切换后续产品和模式对应的用量。

边界条件：如果未来占位托盘也计入 `actualQty`，客户需要提供识别方式，否则上位机会把占位托盘误当成真实产品并扣减库存。

## 5. 对上位机软件的新要求

### 5.1 库存状态必须可靠

上位机要记录每个工位当前库存，并保证每次变化都保存。

库存变化来源只有两类：

- 生产数量增加，按 Sheet3 用量扣减。
- 机器人倒料成功，按每箱数量增加。

### 5.2 任务状态必须可靠

上位机要记录：

- 哪些工位正在等待补料。
- 哪些补料任务已经加入队列。
- 哪些任务正在执行。
- 哪些任务已经倒料。
- 哪些任务失败或取消。

任务失败时，需要根据是否已经倒料区分：

- 倒料前失败：库存不增加。
- 倒料后失败：物料已经进入工位，库存不应回滚。

### 5.3 配置必须可编辑和可保存

Sheet3 参数不能长期写死在程序里。

需要配置页面：

- 能看。
- 能改。
- 能保存。
- 下次启动能加载。
- 参数错误能提示。

### 5.4 必须有人工恢复入口

因为上位机是库存事实源，所以现场必须允许授权人员修正异常状态。

例如：

- 状态文件损坏。
- 现场人工移动了物料。
- 某次倒料实际失败但系统认为成功。
- 某次倒料实际成功但系统没有记录。

这类情况需要有人工确认和修正流程。

| 2 | 最高位停止条件 | 库存达到或超过最高安全位即停止补料。 | 已确认 | 一箱倒入后超过最高位属于正常现象。 |

## 7. 建议的现场验证步骤

### 阶段 1：配置验证

- 导入或录入最新 Sheet3。
- 检查 12 个工位、三种模式、上下限、每箱数量、用量是否正确。
- 检查 L/L、R/H 下不消耗物料的工位是否正确。

### 阶段 2：初始化验证

- 客户清空所有工位。
- 上位机新建初始化，所有工位库存为 0。
- 机器人执行初始补料。
- 验证每个启用工位是否补至达到或超过最高安全位。

### 阶段 3：生产扣减验证

- 产线低速运行或模拟产量增长。
- 检查上位机是否按 Sheet3 用量扣减库存。
- 检查用量为 0 的工位是否不扣减。
- 分别输入或等待 `1000→2→5` 和 `1000→2→1005`，检查清零与毛刺判断。
- 记录离散采样尾数误差，并由客户确认是否接受当前边界。

### 阶段 4：缺料补料验证

- 让某工位库存低于最低安全位。
- 验证系统开始补料。
- 验证同一工位持续补料至达到或超过最高安全位。
- 验证补完该工位后再处理其他工位。

### 阶段 5：异常恢复验证

- 测试通信断线恢复。
- 测试程序重启恢复。
- 测试断电重启恢复。
- 测试任务倒料前失败。
- 测试任务倒料后失败。
- 测试换型等待旧任务完成。

## 8. 当前建议

当前客户已确认采用上位机软件库存方案，因此后续重点不是继续讨论是否接真实库存或硬件料位，而是确保上位机状态机足够可靠。

建议开发和验收重点放在：

1. Sheet3 可视化配置页面。
2. 0 初始库存和初始化补料流程。
3. 最低位/最高位补料逻辑。
4. 同工位优先补满策略。
5. 状态持久化和恢复。
6. 通信断线、程序重启、断电重启后的状态一致性。
7. 人工修正和异常恢复流程。

只有这些能力完成并通过现场验证后，才建议开放 12 工位真实自动补料。
