# 现场真实缺料信号内部原因分析

日期：2026-07-12
更新：2026-07-13，补充客户最新确认后的目标逻辑

用途：内部工程分析。本文面向后续修正代码逻辑、补测试、准备现场联调，不作为给客户确认的直接材料。

## 1. 结论摘要

当前真实缺料接入方向需要按 2026-07-13 客户确认结果重新收敛：最终以上位机软件计算库存和缺料为准，不接客户真实库存作为主依据，也不先依赖新增硬件料位信号。客户会在正式运行前清空所有工位物料，使现场和上位机都从 0 库存开始，后续库存完全由上位机根据配置、产量、补料任务和倒料成功结果维护。

这意味着上位机从“辅助估算”升级为“库存事实源”，可靠性要求显著提高。当前代码仍不适合直接上产线，原因分为两类：

1. 客户规则已经发生变化：初始库存从“安全库存 + 一箱”改为 0；安全库存从单阈值改为最低位/最高位区间；用量策略从 Sheet2/PLC 分歧改为 Sheet3；Sheet2 空值回退 Sheet1 废弃；补料顺序从全局 FIFO 改为同一工位缺料时优先补完该工位到最高位。
2. 实现存在高风险缺口：真实缺料派单被主调度拒收后没有可靠自动重试；系统级 ERROR 时当前真实任务可能没有向 `ShortageMonitor` 释放占用，导致同工位后续不再派单。

客户已确认的核心结论：

- 以上位机软件计算缺料为准。
- 现场运行前，客户会把所有工位物料清空，保持真实库存为 0。
- 上位机初始库存也必须为 0。
- 断电重启、通信断线、程序重启后，上位机必须保存并恢复之前所有库存和任务状态。
- 用量以最新安全库存表格 Sheet3 为准。
- Sheet3 中 L/R、L/L、R/H 三种模式下每个工位用量均已列举。
- 安全库存改为最低位和最高位区间：库存低于最低位必须送料，库存达到或超过最高位停止。
- 配置必须做成可视化页面，可保存到文件，下次启动加载最新配置。
- 初始补料期间允许产线同时生产，上位机必须一边处理倒料入账，一边按 `actualQty` 增量扣减消耗。
- 多个工位都低于最低位时，按触发时间进入紧急补料队列。
- 通信断线期间客户保证不换产品、不换模式；恢复后按 `actualQty` 差值自动补扣。
- 换型期间客户用 5 个空托盘占位，且保证这 5 个占位托盘不增加 `actualQty`，所以上位机不需要额外识别和排除。
- 报警停机后允许现场人员手动指定工位补料，但手动补料必须同步进入上位机库存台账和日志。

建议把旧实现视为“历史验证版本”，后续应围绕上述新规则重新设计缺料计算、配置、持久化和队列策略。

## 3. 当前实现的主逻辑

### 3.1 真实缺料数据来源

当前生产态真实缺料监听由 `ShortageMonitor` 驱动，每轮读取：

- MES 日产量：`actualQty`
- PLC 产品位：`L71/L72/L73`
- PLC 生产方式位：`L68/L69/L1998`

当前轮询行为：

- 轮询周期：5 秒。
- 单轮超时：3 秒。
- 每轮必须收齐 1 个 MES 响应和 3 个 PLC 响应。
- 过期轮次、迟到响应、失败响应都不能混入新轮。
- 产品位必须三选一。
- 生产方式位必须三选一。
- 产品和方式都需要连续两轮稳定后才作为有效生产状态。

代码入口：

- `src/shortagemonitor.cpp`
- `src/customSysScheduler.cpp`

### 3.2 当前库存模型

`ShortageCalculator` 维护 12 个工位的预计库存。

当前初始化：

```text
estimatedAvailable = safetyStock + boxQuantity
```

当前扣减：

```text
productionDelta = currentActualQty - previousActualQty
consumption = productionDelta * usage
estimatedAvailable -= consumption
```

当前缺料判断：

```text
estimatedAvailable <= safetyStock
```

当前补料入账：

```text
实际倒料成功后，estimatedAvailable += boxQuantity
```

注意：这个库存不是客户系统给出的真实库存，是程序内部估算值。

### 3.3 当前派单闭环

生产态真实缺料闭环如下：

```text
ShortageMonitor 判定某工位缺料
  -> dispatchRequested(stationId)
  -> DeviceManager 调 LineManager::reportShortageWithId(stationId, CustomerSystem)
  -> LineManager 创建真实任务并加入 FIFO
  -> ShortageMonitor 记录 taskId，认为该工位已有未倒料任务
  -> TaskExecutor 执行取料、倒料、收尾、码垛
  -> ArmUnload 成功完成时发 materialUnloaded
  -> ShortageMonitor 给对应工位库存加一箱
  -> 如果仍缺料，且没有未倒料任务，再追加下一箱到 FIFO 队尾
```

关键边界：

- `UiMock` 模拟任务不能改变真实库存。
- 同一工位存在尚未倒料的真实任务时，不能重复派单。
- 已倒料但任务尚未完整收尾时，允许该工位下一箱先进入 FIFO 等待。

## 4. 与早期方案的关键差异

### 4.1 2026-06-25 / 2026-07-02 阶段

早期阶段更接近“累计消耗达到安全库存阈值就生成任务，任务成功入队后扣除一个阈值”。这种模型的问题是：入队成功不等于物料已经送到工位；如果任务失败，计算侧已经认为缺料被处理，业务会失真。

### 4.2 2026-07-03 之后的生产闭环

当前更接近“预计库存模型”：

- 产量增长导致预计库存下降。
- 预计库存触及安全线后派单。
- 只有实际倒料成功才加一箱。
- 加箱后仍缺料才继续派下一箱。

这个方向更适合真实产线，但也要求系统明确“初始库存是什么”“一箱是多少”“倒料成功如何判定”“异常后如何恢复”。

## 5. 历史备选方案与当前已确认方向

本节保留 2026-07-12 对“真实库存接口”和“硬件料位信号”的方案分析，作为后续客户若改变条件时的备选参考。但 2026-07-13 客户已经确认：当前项目结论是以上位机软件计算缺料为准，客户现场会先把所有工位料清空，上位机从 0 库存开始独立维护库存状态。

因此，后续实现方向不是接客户真实库存，也不是新增硬件料位作为主触发，而是把上位机做成可靠的库存状态机。真实库存接口和硬件料位检测仍然是技术上更精准的方案，但在本轮客户确认后不作为当前实施主线。

### 5.1 历史备选：接入客户真实库存

目标：

客户系统直接提供每个工位、每个物料的当前库存，机器人系统只负责根据真实库存和安全库存判断是否需要补料。

理想接口字段：

```text
stationId        工位
materialCode     物料品号
productModel     当前产品或适用产品
currentQty       当前真实库存数量
safetyStock      安全库存
boxQuantity      一箱数量
timestamp        库存数据时间
changeoverState  是否换型中
dataVersion      库存数据版本或流水号
```

如果客户系统还能提供“在途库存/已叫料未到达数量”，则更好：

```text
inTransitQty     已发起补料但尚未入库的数量
reservedQty      已占用但尚未消耗的数量
```

从技术上它能解决的问题：

- 启动初始库存不再需要假设。
- 程序重启后可以重新读取真实库存。
- 断线恢复后不用追算断线期间产量，只要读取最新库存。
- 换型时可以按客户系统真实库存重新判断。
- Excel 空值和用量策略不再决定库存主判断，只作为配置参考。
- 连续补料是否需要多箱，可以由真实库存差额直接计算。

仍需确认的问题：

- 客户库存是否实时、准确。
- 库存扣减是在客户系统里发生，还是仍由本系统根据产量扣减。
- 机器人倒料成功后，客户库存由谁更新。
- 客户库存数据延迟超过多少秒时不得自动派单。

推荐架构：

```text
客户真实库存接口 -> 库存快照校验 -> 缺料判断 -> 主调度 FIFO
机器人倒料成功 -> 回传补料完成 -> 客户库存更新或本地对账
```

在该方案下，`ShortageCalculator` 不应再用 `actualQty` 作为库存主来源，而应变成：

- 读取真实库存快照。
- 判断 `currentQty <= safetyStock`。
- 根据 `boxQuantity` 和 `currentQty` 计算建议补几箱。
- 使用产量推算作为诊断或异常交叉校验，而不是主判断。

当前状态：

客户本轮没有选择该方向。原因不是技术上不可行，而是客户确认现场会清空所有工位并让上位机从 0 开始维护状态。因此该方案只保留为后续优化备选。

### 5.2 历史备选：现场料位或重量硬件检测

如果客户系统没有真实库存，建议考虑在工位料仓、倒料口或线边料位位置增加硬件信号。硬件不一定能给出精确数量，但能提供比纯估算更可靠的“是否真的低料/缺料”。

可选硬件方案：

1. 低料位开关  
   在每个工位料仓或倒料口设置一个低料位检测点。检测到低于安全线时，输出缺料信号。

   优点：
   - 逻辑简单。
   - 适合作为自动派单触发条件。
   - 不依赖 MES 产量估算。

   局限：
   - 只能判断“是否低于某个位置”，不能精确知道剩余多少。
   - 需要现场确认安装位置等于安全库存线。
   - 物料堆积形状不稳定时可能误判。

2. 多点料位或连续料位传感器  
   例如超声、激光、距离传感、3D 视觉等，估算料仓高度或体积。

   优点：
   - 能比单点开关提供更多余量信息。
   - 可以区分“接近缺料”和“已经缺料”。

   局限：
   - 对物料形状、反光、粉尘、料面倾斜、遮挡比较敏感。
   - 需要现场标定，不一定能稳定换算成精确数量。

3. 称重传感器  
   在料仓或工位料盒下增加称重模块，用重量估算剩余数量。

   优点：
   - 如果单件重量稳定，精度通常比料位高度更好。
   - 可以估算数量，而不只是判断高低。

   局限：
   - 机械安装成本更高。
   - 受振动、支撑结构、料仓接触、零点漂移影响。
   - 不同物料重量不同，需要按品号标定。

4. 视觉检测  
   用相机判断料仓是否接近空料或低料。

   优点：
   - 改造灵活，可以做非接触检测。

   局限：
   - 对光照、遮挡、料面形态敏感。
   - 更适合辅助确认，不建议单独作为首版生产主触发。

5. 现有 PLC 低料位信号  
   如果客户设备本身已有低料位、缺料、料满等 PLC 信号，优先接入已有信号。

   优点：
   - 改造最少。
   - 客户现场已有维护经验。

   局限：
   - 需要确认信号含义、刷新周期、异常状态和是否覆盖全部 12 工位。

推荐用法：

```text
硬件低料位信号 = 自动派单主触发
产量估算 = 提前预警或合理性校验
倒料成功信号 = 补料完成确认
```

硬件方案能解决的问题：

- 不需要知道启动时准确库存。
- 不需要追算断线期间产量。
- 能直接反映现场是否真的低料。
- 可降低 Excel 用量错误导致的误派。

硬件方案仍解决不了的问题：

- 如果只用低料位开关，无法知道应补几箱，只能按一箱一箱补。
- 传感器故障、污染、安装位置错误仍会导致误判。
- 仍需要确认倒料完成后是否真的进入料仓。

当前状态：

客户本轮没有选择新增硬件作为主判断。若后续发现上位机状态和现场实际频繁偏离，可重新把低料位、称重或客户现有 PLC 缺料信号作为校验信号接入。

### 5.3 过渡备选：估算库存 + 关键节点校验

如果短期无法接真实库存，也不能马上安装完整料位硬件，可以采用折中方案：

```text
MES actualQty 推算消耗
+ 人工确认初始库存
+ 倒料成功确认
+ 可选低料位/料满信号做校验
```

适用场景：

- 客户暂时没有真实库存接口。
- 硬件改造周期较长。
- 需要先做有限范围试运行。

建议规则：

- 系统估算只能作为“建议缺料”。
- 如果有低料位信号，则以低料位信号作为最终派单依据。
- 如果没有低料位信号，则必须设置连续补料上限和异常报警。
- 程序重启后必须人工重新确认库存。

当前状态：

旧的“安全库存 + 一箱”初始化方案已经不符合客户最新确认。客户确认的起点不是“假设已有安全库存加一箱”，而是“现场真实清空，上位机库存从 0 开始”。

### 5.4 当前已确认：上位机软件库存事实源

客户已经确认：以上位机软件计算缺料为准。因此后续目标模型应改为：

```text
上位机库存 = 持久化库存状态
初始正式运行前，现场所有工位清空
上位机所有工位库存初始化为 0
系统先为各工位补料，直到库存 >= 最高安全位
生产过程中按 Sheet3 用量扣减库存
某工位库存 < 最低安全位时触发补料
持续补该工位，直到库存 >= 最高安全位
断电、重启、通信断线后必须恢复之前保存的上位机库存和任务状态
```

该方案的本质变化：

- 上位机不再只是“估算工具”，而是库存状态的主账本。
- 初始库存不再假设为 `安全库存 + 一箱`，而是明确为 0。
- 产线开始前必须先执行补料建库，把每个需要补的工位送到最高安全位以上。
- 安全库存不再是单点阈值，而是上下限区间。
- 低于最低位时开始补料。
- 达到或超过最高位时停止补料。
- 同一工位持续缺料时，需要先把该工位补到目标高位，再处理其他工位。
- 所有状态必须持久化，否则断电、程序重启或通信恢复后，上位机账本会丢失。

该方案解决了旧模型中的一部分问题：

- 不再担心现场实际没有 `安全库存 + 一箱`，因为客户会清空并从 0 开始。
- 不再需要 Sheet2 空值回退 Sheet1，因为客户确认以 Sheet3 为准。
- L/L、R/H 模式下某些工位不消耗物料，可以由 Sheet3 配置明确表达。
- 初始补料阶段和正常生产阶段使用同一套上位机库存账本。

但该方案对上位机提出更高要求：

- 必须实现可靠持久化。
- 必须记录每个工位、每种模式、当前库存、目标上下限、在途任务、已倒料未完成任务、最后处理的产量基线。
- 必须能在通信断线期间保持状态，不乱扣、不乱补。
- 必须能在程序重启后恢复到断电前状态。
- 必须有配置页面维护 Sheet3 中所有参数。
- 必须有异常对账机制，至少允许人工修正上位机库存。

推荐内部定义：

```text
库存扣减来源：MES actualQty 增量 * Sheet3 当前模式用量
库存增加来源：真实补料任务倒料成功
初始库存来源：客户清空现场后，上位机初始化为 0
安全区间来源：Sheet3 配置页面
任务触发条件：库存 < 最低安全位
任务停止条件：库存 >= 最高安全位
状态恢复来源：本地持久化文件
```

### 5.6 代码修改点与 spec/plan 的文档边界

## 6. 当前必须重点修正的问题

### P0-1：派单被主调度拒收后没有可靠自动重试

现象：

`ShortageMonitor::reevaluateStation()` 在缺料时会把工位加入 `m_waitingStations`，然后发出 `dispatchRequested`。如果 `LineManager` 当时处于 Error，`reportShortageWithId()` 返回 0，`confirmDispatch(... accepted=false)` 只记录日志，并保留 `m_waitingStations`。

问题：

后续即使主调度 Reset 并恢复 Running，`reevaluateStation()` 会因为 `m_waitingStations.contains(stationId)` 直接返回，不会再次发 `dispatchRequested`。该工位会停在“等待入队”状态。

影响：

真实产线中只要某次缺料刚好遇到主调度 Error 或拒收，就可能永久不再自动补该工位。

建议修正：

- 给 `WaitingForQueue` 增加明确重试机制。
- 当主调度状态从 Error/Idle 恢复到 Running 时，重新尝试所有 `WaitingForQueue` 工位。
- 或者在 `accepted=false` 时不要把工位长期留在 `m_waitingStations`，而是用独立的 rejected/pending-retry 状态，下一轮继续尝试。
- 增加测试：LineManager 拒收 -> Reset/Start -> 同一工位应自动重新入队。

### P0-2：系统级 ERROR 时当前真实任务可能不释放占用

现象：

`TaskExecutor::raiseSystemError()` 发出 `systemError(m_task, reason)`。`LineManager::onExecutorSystemError()` 当前忽略 `task`，直接进入 `enterError(reason)`。

问题：

`ShortageMonitor` 依赖 `taskFinished` 来移除 `m_tasks` 中的真实任务记录。如果系统级 ERROR 路径没有转发当前任务终态，真实缺料监控会一直认为该工位有尚未倒料任务。

影响：

同工位后续会被 `hasNotYetUnloadedTask(stationId)` 阻挡，不再自动派单。

建议修正：

- `LineManager::onExecutorSystemError()` 应对当前任务发出明确终态通知，至少对 `CustomerSystem` 任务要保证 `taskFinished` 到达 `ShortageMonitor`。
- 终态语义需要区分：
  - 倒料前失败：不加库存，释放占用，后续仍缺料时允许重新派。
  - 倒料后失败：库存已经加一箱，不回滚，但任务终态仍要释放占用。
- 增加测试：真实任务执行中触发系统级 ERROR 后，`ShortageMonitor` 应释放任务记录并在恢复后按库存状态重新评估。

### P0-3：初始库存逻辑必须从“安全库存 + 一箱”改为“0”

当前实现用 `安全库存 + 一箱数量` 作为初始预计库存。该策略来自测试面板阶段，是为避免启动即集中派单的临时假设。

问题：

- 客户最新确认要求现场所有工位先清空，上位机库存也从 0 开始。
- 旧初始化逻辑会让上位机账本从第一秒就偏离客户确认的现场状态。
- 初始阶段不应等待产量消耗触发缺料，而应主动补料建库。

建议修正：

- 删除真实模式中的 `安全库存 + 一箱` 初始库存语义。
- 新正式运行流程应先执行“初始化补料阶段”：所有需要物料的工位库存为 0，并按最高安全位目标生成补料任务。
- 初始化补料完成后，进入正常生产消耗阶段。
- 测试面板可以保留旧策略用于历史对比，但生产态真实缺料不能继续使用。

### P0-4：Sheet2 回退 Sheet1 规则废弃，必须改为 Sheet3 配置

`安全库存.xlsx` 的 `Sheet2` 中存在空值：

- 88 产品的位置 11：用量/安全库存为空。
- 88R 产品的位置 10：用量/安全库存为空。
- 92 产品的位置 10：用量/安全库存为空。

当前代码把这些空值按共同主品号回退到 `Sheet1`。

问题：

客户已经确认：后续不用 Sheet2 回退 Sheet1，以最新 Sheet3 为准。Sheet3 中 L/R、L/L、R/H 三种模式已经列出每个工位用量；L/L 和 R/H 下有些工位不消耗物料，应由 Sheet3 明确配置为 0 或禁用。

建议修正：

- 移除生产态真实缺料对 Sheet1/Sheet2 的硬编码依赖。
- 新增 Sheet3 配置模型，包含模式、工位、用量、最低安全位、最高安全位、每箱数量、是否启用。
- 用量为 0 或工位禁用时，不应因产量增长扣减该工位库存，也不应为该模式触发该工位补料。
- 保留 Sheet1/Sheet2 仅作为历史资料或迁移参考，不作为正式生产计算来源。

### P0-5：用量策略已确认，以 Sheet3 为唯一来源

PDF 中曾经提到“目前有分歧”：

- 方案 A：使用 Excel `Sheet2` 的“用量”列。
- 方案 B：使用 PLC 生产方式：`L68/L69` 每个工位消耗 2，`L1998` 每个工位消耗 1。

当前代码默认 `SHORTAGE_USAGE_STRATEGY = UsageStrategy::Spreadsheet`，即使用 Excel 用量。

问题：

客户最新确认后，旧分歧已经不适用。正式生产必须以安全库存表格 Sheet3 为准，Sheet3 已对 L/R、L/L、R/H 三种模式下各工位消耗数量做详细列举。

建议修正：

- 废弃 `SHORTAGE_USAGE_STRATEGY` 这种编译期切换作为生产方案。
- 用量不应写死在代码里，应由可视化配置页面加载和保存。
- 模式映射需要明确：PLC 生产方式信号映射到 Sheet3 的 L/R、L/L、R/H。
- L/L、R/H 下不消耗某些工位时，配置为 0 或禁用，计算时跳过。

### P0-6：安全库存必须从单阈值改为上下限区间

当前实现是：

```text
estimatedAvailable <= safetyStock -> 缺料
```

客户最新确认是：

```text
库存 < 最低安全位 -> 必须开始送料
库存 >= 最高安全位 -> 停止送料
```

问题：

- 单阈值无法表达“低位触发、高位停止”的补料区间。
- 如果仍按单阈值处理，可能补一箱后仍在低位附近反复触发，也无法准确知道应补到什么程度。

建议修正：

- 配置模型中每个工位、每种模式都必须包含 `minSafetyStock` 和 `maxSafetyStock`。
- 缺料触发条件改为 `stock < minSafetyStock`。
- 补料目标改为 `stock >= maxSafetyStock`。
- 每次倒料成功后增加一箱库存，然后重新判断是否仍未达到最高位。
- 停止条件已确认使用 `stock >= maxSafetyStock`，即达到或超过最高位就停止补料。

### P0-7：补料队列策略必须支持同工位优先补满

当前主调度队列是全局 FIFO。客户最新确认：

> 如果一个工位一直缺料，加入队列的话，先同一工位送完料，然后再送其他工位。

问题：

- 全局 FIFO 只能保证先来先服务，不能保证同一工位连续补到高位。
- 若多个工位同时缺料，旧策略可能在工位 A 仍低于高位时切去补工位 B。

建议修正：

- 需要新增“补料计划层”，不能直接把每次缺料都当作同等 FIFO 任务。
- 当某工位库存低于最低位时，应生成该工位的补料计划，目标为 `stock >= maxSafetyStock`。
- 在该补料计划完成前，同工位后续箱任务应优先排在其他工位之前。
- 同时要评估对 AGV/机械臂整体效率的影响：同工位连续补料可能增加某些工位等待，但符合客户确认的缺料优先策略。

### P0-8：断电重启、通信断线必须持久化所有状态

客户已确认：断电重启、通信断线、上位机必须记录保存之前的所有状态。

需要持久化的最小状态：

- 当前配置版本。
- 当前产品/模式。
- 每个工位当前上位机库存。
- 每个工位最低安全位、最高安全位、每箱数量、用量、启用状态。
- MES `actualQty` 基线和最后一次已处理的产量。
- 已经入队但未执行的真实补料任务。
- 正在执行的真实补料任务。
- 已倒料但未完整收尾的真实补料任务。
- 当前是否处于初始化补料阶段。
- 当前每个工位是否处于“补到最高位”的连续补料计划中。

建议修正：

- 增加原子写入的状态文件，避免断电写坏。
- 每次库存变化、任务入队、任务开始、倒料成功、任务终态、模式切换、通信恢复都要落盘。
- 程序启动时必须先加载状态，不允许直接重新初始化为 0，除非用户明确选择“重新清空建库”。
- 需要 UI 提供“当前状态来源：恢复自文件 / 新建初始化 / 人工重置”。

### P0-9：必须新增可视化配置页面

客户已确认 Sheet3 所有数据需要做成单独可视化配置页面。

配置页面需要支持：

- 查看和编辑 L/R、L/L、R/H 三种模式。
- 每种模式下 12 个工位的用量。
- 每个工位每箱数量。
- 最低安全位。
- 最高安全位。
- 是否启用。
- 工位显示名、临时 NO、现场料口映射。
- 保存参数到文件。
- 下次启动加载最新配置。

建议修正：

- 不再把安全库存和用量写死在 `shortageconfig.h`。
- 增加配置文件格式，例如 JSON。
- 配置文件需要版本号和校验。
- 保存前校验：最高位必须大于最低位；每箱数量必须大于 0；用量不能为负；启用工位必须有有效映射。
- UI 保存后应提示是否立即应用；如果生产正在运行，修改配置可能需要禁止或要求停机确认。

### P1-1：代码工位 3 是临时映射

建议修正：

- 新配置页面必须显式保存“代码工位号 -> Sheet3 临时 NO/T -> 现场料口 -> 仙工/M4 点位”的映射。
- 当前阶段保持代码工位不变，但不要再依赖 Sheet1/Sheet2 旧位置推导。
- 后续如果 RDS/M4 改工位，只改配置映射，不应改库存计算核心逻辑。

### P1-2：产品/方式切换的门禁策略需要现场确认

当前逻辑：

- 产品切换需要两轮稳定确认。
- 产品切换后重新初始化 12 工位库存。
- 若还有旧产品真实任务未结束，新产品暂停派单。
- 生产方式切换保留库存，但重建 MES 基线，不追算切换边界产量。

风险：

- 如果现场切型时线边物料也同时换掉，重新初始化可能合理。
- 如果现场保留旧物料或混线生产，重新初始化可能失真。

客户已确认：

- 换型时采用“旧任务完成后再派新任务”。

建议修正：

- 旧产品/旧模式补料任务全部终态前，不允许新产品/新模式自动派单。
- 新模式生效后，应使用 Sheet3 对应 L/R、L/L、R/H 配置重新计算后续消耗。
- 换型时是否清空库存要结合客户现场操作：如果客户换型时也清空工位，应进入重新建库；如果不清空，则沿用持久化库存并切换用量策略。
- 该分支仍需现场操作流程补充确认，因为“换型是否清料”会影响库存账本。

### P1-3：通信恢复必须基于持久化状态处理

当前逻辑：

- 任一请求失败，本轮不计算、不派单。
- 恢复后的第一轮只重建 `actualQty` 基线。
- 断线期间的产量不追算。

优点：

- 不会因为断线期间状态未知而误扣。
- 可避免多轮旧数据叠加造成误派。

缺点：

- 断线期间真实消耗会漏算。

客户最新确认：

- 通信断线后，上位机必须保存之前所有状态。
- 因为缺料以上位机软件账本为准，所以恢复时不能简单丢弃或重新初始化。

建议修正：

- 通信断线时冻结最后已确认状态，并落盘。
- 恢复后读取最新 `actualQty`，和持久化的最后处理基线比较。
- 如果断线期间产品/模式信号稳定且可确认，可以按增量补扣。
- 如果断线期间产品/模式不可信，应进入“通信恢复待确认”状态，要求人工选择是否补扣、重建基线或重新清空建库。
- 不允许恢复后直接把库存重置为 0 或 `安全库存 + 一箱`。

### P1-4：倒料成功后的失败是否回滚，需要业务确认

当前逻辑：

- `ArmUnload` 成功后立即给库存加一箱。
- 后续收姿态、码垛或回站失败，不回滚库存。

这符合“物料已实际进入工位”的业务事实，但客户必须确认。

建议：

- 将“倒料完成”定义为库存入账点。
- 将“任务完成”定义为设备流程完成点。
- 两者在 UI 和日志中分开显示，避免客户误解。

### P1-5：连续补料没有上限

当前逻辑允许加一箱后仍缺料时继续追加下一箱，直到预计库存高于安全线。

风险：

- 初始库存估算错误或参数错误时，可能连续生成多个任务。
- 如果某工位传感、Excel 或 MES 数据错误，可能造成重复送料。

客户最新确认后，连续补料从“风险兜底”变成正式要求的一部分：

- 某工位低于最低位后，必须持续送料，直到库存达到或超过最高位。
- 如果同一工位一直缺料，应先同一工位送完，再送其他工位。

建议修正：

- 连续补料不再只按“下一箱是否仍缺料”判断，而应按“是否已达到或超过最高位”判断。
- 需要根据每箱数量计算理论所需箱数，但仍以倒料成功逐箱入账。
- 可以保留异常保护：连续补料箱数超过配置上限时报警，防止配置错误或状态损坏导致无限补料。

### P1-6：MES 地址配置和固定端点需要统一

资料中先出现 `.229`，后续 20260703 明确改为 `.228`。当前 `CustomSysScheduler` 默认端点是 `.228`，但 `DeviceManager::startLiveShortage()` 会把 `m_cfg.customSysEndpoint` 设置给调度器。

风险：

如果配置里仍保留旧 `.229`，MES 可能读错地址；PLC 则使用代码默认 `.228`，导致 MES/PLC 来源不一致。

建议：

- 真实模式启动前强制显示或校验当前 MES/PLC 地址。
- 真实模式最好使用同一处固定配置，不要测试面板、生产会话、默认值各自维护。

### P1-7：旧实现没有满足上位机账本持久化要求

当前同一进程内停止/启动真实模式会保留库存，但程序重启后会重新按 `安全库存 + 一箱` 初始化。

风险：

产线中断、电脑重启、程序崩溃后，缺料判断会偏离真实库存。

客户最新确认后，该项升级为 P0 级要求，详见 P0-8。保留本节用于说明旧实现风险。

建议：

- 不允许程序重启后自动按旧规则初始化。
- 必须从持久化状态恢复。
- 如状态文件缺失或损坏，必须进入人工确认流程，不能自动运行。

## 7. 建议修正优先级

### 立即修正

1. 废弃生产态 `安全库存 + 一箱` 初始库存，改为客户确认的 0 初始库存。
2. 设计初始化补料阶段：所有启用工位从 0 开始，先补至达到或超过最高安全位。
3. 将安全库存从单阈值改为最低位/最高位区间。
4. 废弃 Sheet1/Sheet2 回退和编译期用量策略，改为 Sheet3 可视化配置。
5. 增加本地持久化，覆盖断电重启、通信断线、程序重启。
6. 修复派单拒收后的自动重试机制。
7. 修复系统级 ERROR 当前任务终态通知，保证真实任务占用释放。
8. 新增同工位优先补满的补料计划层。
9. 增加以上逻辑对应的自动测试和现场恢复测试。

### 上线前必须确认或补齐

1. 最新 Sheet3 的完整字段、文件格式和三种模式名称。
2. PLC 信号如何映射到 Sheet3 的 L/R、L/L、R/H。
3. Sheet3 中用量为 0 的工位是否表示该模式不消耗、不补料。
4. 验证最低安全位和最高安全位逻辑：`stock < minSafetyStock` 触发补料，`stock >= maxSafetyStock` 停止补料。
5. 初始化补料阶段是否所有启用工位都必须补到最高位。
6. 同一工位优先补满时，其他工位等待是否可接受。
7. 断线期间如果产量增长，恢复后是否自动补扣，还是人工确认。
8. 换型时是否清空工位并重新从 0 建库。
9. 配置页面运行中是否允许修改参数。
10. 状态文件损坏或缺失时，现场人工流程是什么。

### 中期优化

1. 增加状态对账页面，允许授权人员修正上位机库存。
2. 增加配置版本管理和配置导入/导出。
3. 增加状态文件备份和恢复点。
4. 增加同工位连续补料异常保护。
5. 增加现场运行诊断日志导出。
6. 将真实模式和测试模式的数据源、地址、状态展示完全分离。
7. 后续如果客户愿意提供真实库存或硬件料位信号，可作为上位机账本校验源接入。

## 8. 建议补充测试清单

### 调度接线

- 主调度 Error 时真实缺料请求被拒收，Reset/Start 后必须重新入队。
- 当前真实任务系统级 ERROR 后，`ShortageMonitor` 必须释放占用。
- Pending 真实任务被 Error 清队列后，`ShortageMonitor` 必须释放占用并按库存重新评估。
- 倒料前失败：不加库存，恢复后仍缺料应重新派。
- 倒料后失败：库存已加，不回滚，任务终态释放占用。

### 库存计算

- 初始状态所有启用工位库存为 0。
- 初始化补料阶段会为启用工位生成补料计划，直到库存达到或超过最高安全位。
- Sheet3 三种模式 L/R、L/L、R/H 均可配置和加载。
- Sheet3 用量为 0 或禁用工位时，不扣减、不触发补料。
- 最低安全位触发补料，最高安全位停止补料。
- 同一工位连续补料优先于其他工位。
- 工位映射使用 Sheet3 临时 NO/T 和代码工位映射，不再从 Sheet1/Sheet2 推导。

### 通信与切换

- MES/PLC 任一失败，本轮不计算、不派单，并持久化通信暂停状态。
- 通信恢复后从持久化状态继续，不重新初始化。
- 恢复后 `actualQty` 增量是否补扣应有明确测试路径：可信则补扣，不可信则进入人工确认。
- 产品位多选/全 false，本轮失败。
- 方式位多选/全 false，本轮失败。
- 产品切换两轮确认。
- 换型时旧任务未完成，新任务不派。
- 换型后按客户流程决定是否清空并重新初始化建库。

### UI 和现场可见性

- 真实模式默认不显示 HTTP URL 给客户。
- UI 必须显示“以上位机库存为准”以及当前状态来源。
- UI 能区分“初始化补料、库存正常、低于最低位、补料中、已到最高位、通信暂停、配置异常、换型等待、状态恢复失败”。
- UI 必须有 Sheet3 配置页面和保存按钮。
- UI 必须能显示当前配置版本和状态文件恢复结果。
- 模拟模式切换不清真实 FIFO。
- 停止真实监听不等于停止主调度。

## 9. 推荐的现场联调顺序

1. 导入或手工录入最新 Sheet3 配置。
2. 客户现场清空所有工位物料。
3. 上位机执行“新建初始化”，确认 12 个启用工位库存均为 0。
4. 执行初始化补料阶段，验证各工位按配置补至达到或超过最高安全位。
5. 只开真实监听，不接主调度，连续观察 30 到 60 分钟，确认产量、模式、库存扣减正确。
6. 开启单工位真实入队，验证低于最低位触发、补至达到或超过最高位停止。
7. 验证同一工位持续缺料时，优先补完该工位，再处理其他工位。
8. 验证倒料成功后库存增加一箱。
9. 验证倒料前失败、倒料后失败、主调度 Error、通信失败恢复。
10. 验证程序重启和断电重启后恢复状态文件，不丢库存、不重复补料。
11. 验证换型时旧任务完成后再派新模式任务。
12. 再开放 12 工位真实模式。

## 10. 当前可对外表述口径

不建议对客户说“真实缺料已经可以上线”。更准确的口径是：

> 客户已确认真实缺料以上位机软件库存为准，现场运行前会清空所有工位，上位机从 0 库存开始维护状态。现有实现需要按 Sheet3 配置、上下限安全库存、状态持久化和同工位优先补满策略重新调整，并完成单工位到十二工位的分阶段联调。

更建议补充一句：

> 该方案对上位机可靠性要求很高，断电重启、通信断线、程序异常后都必须恢复之前保存的库存、任务和产量基线，不能重新估算或自动清零。
