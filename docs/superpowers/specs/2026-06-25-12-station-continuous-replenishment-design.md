## 1. 目标与边界

### 1.1 目标

系统接收工位缺料任务后，按严格 FIFO 顺序依次完成：

1. AGV 前往对应取料 LM；
2. 机械臂完成视觉定位、夹紧前扫码和取料；
3. AGV 前往对应倒料 LM；
4. 机械臂完成倒料并回到该工位配置的运行安全位；
5. AGV 前往对应空箱码垛 LM；
6. 机械臂按码垛缓存计算结果放置空箱；
7. 成功提交已放数量；
8. 有后续任务时直接执行队首任务，没有任务时 AGV 返回 LM1 待机。

### 1.2 当前边界

- 当前任务来源为上位机“模拟缺料”工位按钮，任务源记录为 `TaskSource::UiMock`。
- 调度主入口是 `LineManager`，旧的 `LineOrchestrator` 不作为当前主流程入口。
- 主流程一次只执行一个任务，不并行控制 AGV 和机械臂处理不同工位。
- FIFO 队列保存在进程内，程序重启后不恢复旧任务。
- 同一工位允许连续多次入队，每次点击都生成独立任务，不按工位去重。
- 当前码垛缓存由 `PalletScheduler` 通过 `QSettings` 保存；只有完整码垛动作成功后才增加已放数量。

## 2. 模块职责

```text
MainWindow
  ├─ 上位机操作、状态展示、FIFO 展示和日志展示
  └─ 只转发 Start、Stop、Reset Error 和模拟缺料操作
          │
          ▼
LineManager
  ├─ 整线 Idle / Running / ReturningHome / Error 状态
  ├─ TaskQueue 严格 FIFO
  ├─ 启停、回 LM1、清队列和系统级报警
  └─ 每次只把一个任务交给 TaskExecutor
          │
          ▼
TaskExecutor
  ├─ 解析工位与码垛配置
  ├─ 推进单个任务状态机
  ├─ 协调 AGV、机械臂、扫码器和码垛缓存
  └─ 区分任务级失败与系统级错误
          │
          ├─ AgvController：派单、取消和到达状态监控
          ├─ HuayanScheduler：取料、搜码移动、倒料和码垛动作
          ├─ NScanScheduler：主动扫码及重试
          └─ PalletScheduler：码垛点位计算、校验和已放数量缓存
```

模块边界要求：

- `MainWindow` 不直接编排设备动作。
- `LineManager` 不展开机械臂阶段细节。
- `TaskExecutor` 不保存长期 FIFO，也不自行修改固定工位配置。
- `lineconfig.h` 是工位 LM、示教函数、夹后策略、倒料后收姿态和取料 Z 余量的集中代码来源。
- `PalletScheduler` 只负责几何点位和数量缓存，不负责控制机械臂。

## 3. 任务与队列规则

### 3.1 任务字段

`Task` 当前包含以下业务字段：

| 字段 | 含义 |
|---|---|
| `taskId` | 本次程序运行期间递增的任务号，用于日志追踪 |
| `stationId` | 工位号，合法范围为 1～12 |
| `source` | 任务来源；当前主流程使用 `UiMock` |
| `state` | `Pending`、`Running`、`Succeeded`、`Failed` 或 `Canceled` |
| `step` | 面向 UI 的稳定业务步骤 |
| `stepIndex` | UI 展示使用的步骤序号 |
| `createdAt` | 入队 UTC 时间 |
| `statusText` | 当前状态说明 |
| `lastError` | 最近一次失败原因；成功任务为空 |

### 3.2 FIFO 规则

- `TaskQueue::enqueue()` 在队尾追加任务。
- `TaskQueue::takeNext()` 只取队首并将其标记为 `Running`。
- 当前任务完成安全收尾后，`LineManager` 才能取下一个任务。
- 同一工位的重复任务保持各自的任务号和入队位置。
- 当前任务执行期间收到新任务，只追加到队尾，不重排正在执行和已经排队的任务。
- 空闲回 LM1 途中收到新任务时，系统取消回站，再执行新队首任务；主动取消回站不作为故障。

## 4. 整线状态机

| 状态 | 含义 | 允许的主要操作 |
|---|---|---|
| `Idle` | 未启动 | 可以入队、可以 Start；入队后暂不执行 |
| `Running` | 正在执行任务或已启动等待缺料 | 可以继续入队、可以 Stop |
| `ReturningHome` | 队列为空，AGV 返回 LM1 | 可以入队；新任务会中止回站并开始送料 |
| `Error` | 系统报警，需要人工处理 | 拒绝缺料任务；只能先 Reset Error |

### 4.1 Start

- 只有 `Idle` 状态接受 Start。
- Start 后进入 `Running`。
- 已有 Pending 任务时立即执行队首。
- 没有任务时检查 AGV 是否已经在 LM1；不在 LM1 则派单返回 LM1，已在 LM1 则保持“等待缺料”。
- Error 状态点击 Start 只记录“请先 Reset Error”，不会启动。

### 4.2 Stop

Stop 是急停语义，不是暂停：

1. 当前 Running 任务标记为 `Canceled`；
2. 取消 AGV 导航；
3. 停止机械臂调度；
4. 清空全部 Pending 任务；
5. 整线进入 `Error`；
6. UI 显示报警原因“人工 Stop 急停”。

### 4.3 Reset Error

- 只在 `Error` 状态有效。
- 清除当前任务并恢复到 `Idle`。
- 不会自动重新 Start，也不会恢复 Stop 时已清除的 Pending 任务。
- 现场人员确认设备和作业区安全后，必须再次点击 Start。

### 5.2 夹紧后策略

- `None`：夹紧抬升后不再调用拍照函数，直接完成取料阶段。
- `CaptureFunc`：夹紧抬升后复用该工位 `captureFunc` 返回安全高度。
- `CustomFunc`：调用独立的 `afterGripFunc`；当前配置表没有工位使用此模式，但接口保留。

取料位与倒料位相同的工位为 1、2、11、12。取料完成后，这些工位直接进入倒料动作，不再重复派发相同 LM，也不额外执行通用的取料后收姿态步骤。

### 5.3 取料 Z 计算

当前公式为：

```text
下探量 = clamp(视觉 Z - 当前工位 grabZClearance, 0, 最大允许下探量)
```

- 工位 1～11 使用 417 mm。
- 工位 12 使用 380 mm。
- 视觉 Z 小于余量时，下探量为 0。
- 计算结果不得超过机械臂调度器定义的最大下探量。

这些数值是当前现场修改后的代码基线，不再使用旧文档中的统一 425 mm。

## 6. 单任务实际流程

### 6.1 配置解析

`TaskExecutor::start()` 首先读取：

- `StationTaskConfig`：工位 LM、机械臂函数、夹后策略和 Z 余量；
- `PalletAreaTaskConfig`：码垛 LM、码垛基准函数和松爪函数；
- `PalletScheduler` 当前码垛参数和已放数量。

任何必需配置缺失都升级为系统级 Error，禁止继续派单。

### 6.2 AGV 到取料位

1. 下发当前工位 `pickupLm`；
2. 必须先观察到本次导航进入 Waiting 或 Running；
3. 只有同时满足以下条件才判定到达：
   - `navStatus == Arrived`；
   - `navStation == pickupLm`；
   - `curStation == pickupLm`；
4. 单段导航超时为 120 秒；
5. Failed、Canceled、Timeout 或通信错误升级为系统级 Error。

“必须先看到本次导航运动”用于防止误用上一条导航残留的 Arrived 状态。

### 6.3 机械臂取料与视觉闭环

1. 调用该工位 `captureFunc` 到拍照/取料安全位；
2. 请求视觉结果；
3. 根据手眼转换结果进行平面搜索、角度修正和下探；
4. 到达夹紧前扫码暂停点；
5. 扫码通过后夹紧并抬升；
6. 按 `AfterGripMode` 决定是否执行夹紧后安全离开函数。

机械臂命令统一经过命令门控：已有待下发命令或执行中命令时拒绝覆盖；读取 FSM 失败时禁止放行；`ProgramStopped`、`RobotInMoving` 和脚本运行态必须等待。Stop 会递增回调序号，使已经排队的延迟回调失效，防止停止后继续下发旧命令。

### 6.4 夹紧前扫码和 Y 轴搜码

主流程默认扫码参数：

| 参数 | 当前值 |
|---|---:|
| 端口 | 30000 |
| 单次超时 | 2000 ms |
| 单轮最大尝试 | 3 次 |
| 重试间隔 | 500 ms |

扫码流程：

1. 在原夹取位置执行首轮扫码；
2. 首轮失败后，机械臂按工具坐标系 Y 轴移动到第一个搜索位置并重新扫码；
3. 仍失败时移动到第二个搜索位置并重新扫码；
4. 搜码成功后先回原夹取位置，再继续夹紧；
5. 全部失败后先回拍照位，再按任务失败执行安全收尾。

当前 Y 轴搜索目标为 `+20 mm` 和 `-20 mm`。扫码失败后的 180° 旋转补救能力仍保留在底层调度器中，但 `TaskExecutor` 当前默认关闭该功能，现场主流程不得依赖旋转补救。

### 6.5 到倒料位并倒料

- `pickupLm != unloadLm` 时，取料完成后先回运行安全位，再派发 `unloadLm`。
- `pickupLm == unloadLm` 时，跳过重复导航，直接开始倒料。
- 到达倒料位后先调用 `unloadPointFunc`，再调用 `unloadFunc`。
- 倒料完成后，调用当前工位 `stowAfterUnloadFunc`。
- 工位 3 必须调用现场代码配置的带过渡路径函数 `Func_daoliao3_huianquanwei`。

### 6.6 到码垛位并放置空箱

当前代码中的实际路由为：

| 使用工位 | 内部码垛键 | 码垛 LM | 码垛基准函数 | 松爪函数 |
|---|---|---:|---|---|
| 工位 1～11 | `PalletArea::SmallBox` | LM17 | `Func_pallet_shared_base` | `Func_songzhua` |
| 工位 12 | `PalletArea::LargeBox` | LM16 | `Func_pallet_s12_base` | `Func_songzhua` |

上表是当前物理派单和动作函数的代码依据。旧文档中相反的 LM16/LM17 对应关系已经删除。

主流程到达码垛区时，空箱已经被夹紧，因此调用 `startPalletPlaceFromClampedSafety()`，不会重复夹紧。标准码垛动作依次执行：

1. 调用码垛基准函数；
2. 读取码垛基准位当前 TCP；
3. 按下一点偏移移动 X、Y；
4. 根据托盘面离地高度、层高、释放高度、机器人基座离地高度和夹爪补偿计算目标 TCP Z；
5. 目标 TCP Z 高于当前码垛基准位 TCP Z 时拒绝执行，避免向高风险姿态抬升；
6. 下降到释放高度；
7. 调用 `Func_songzhua` 松爪；
8. 抬升；
9. 调用 `Func_yun_xing_zhong` 回运行安全位；
10. 发出码垛动作完成信号。

标准码垛动作已经包含松爪后的最终收姿态。`TaskExecutor` 收到动作完成信号后提交 `commitPlaced()`，提交成功直接完成任务，不再进入第二次 `StowAfterPallet`。

## 7. 码垛参数与缓存

### 7.1 当前默认参数

`PalletScheduler` 当前默认值如下；现场保存值通过 `QSettings` 覆盖默认值：

| 参数 | `LargeBox` | `SmallBox` |
|---|---:|---:|
| 码垛区域 X × Y | 1100 × 1100 mm | 1100 × 1100 mm |
| 托盘面离地高度 Z | 0 mm | 0 mm |
| 空箱 X × Y × Z | 580 × 380 × 288 mm | 450 × 270 × 108 mm |
| X/Y 间距 | 20/20 mm | 20/20 mm |
| X/Y 边缘预留 | 20/20 mm | 20/20 mm |
| 最大层数 | 8 | 8 |
| 默认释放高度 | 箱高 × 1.2 | 箱高 × 1.2 |
| 机器人基座离地高度 | 850 mm | 850 mm |

释放 TCP Z 的当前计算关系为：

```text
目标层释放地面高度 = 下一点 Z + 目标层上方释放高度
目标释放 TCP Z = 目标层释放地面高度 - 机器人基座离地高度 + 夹爪释放补偿
```

夹爪释放补偿由 C++ 编译期常量 `PALLET_GRIPPER_RELEASE_Z_OFFSET_MM` 提供。

### 7.2 码垛配置窗口

主界面“码垛配置”区域点击“打开码垛配置”后打开独立窗口。窗口包含“大箱码垛”和“小箱码垛”两个页签，二者分别操作 `LargeBox` 和 `SmallBox` 缓存。

当前按钮行为：

| 按钮 | 行为 |
|---|---|
| 保存配置 | 校验并保存当前输入，主流程立即复用同一个 `PalletScheduler` 实例 |
| 校验配置 | 检查尺寸、边缘、层数、释放高度和当前数量 |
| 填入默认现场值 | 只填充输入框，不自动保存 |
| 推荐释放高度 | 按箱高生成建议值，仍需现场人员确认后保存 |
| 计算下一点 | 预览当前已放数量对应的下一点，不推进缓存 |
| 执行一次码垛 | 执行一次真实机械臂码垛；完整成功后数量加 1 |
| 按当前层数仿真 | 生成点位表，不控制机械臂，不修改真实缓存 |
| 清除显示结果 | 只清空显示，不修改配置和数量 |
| 应用数量修正 | 人工修正已放数量并保存 |
| 清零当前区域 | 人工确认后把当前区域已放数量清零 |

真实单步码垛运行期间禁止直接关闭窗口。需要停止时，必须在华研调试面板点击“停止”，等待窗口提示动作已停止、数量未提交后才能关闭。

### 7.3 数量提交规则

- “计算下一点”和“按当前层数仿真”均不增加已放数量。
- 真实单步码垛和主流程码垛只有在机械臂完整执行基准位、XY、Z、松爪、抬升和回安全位之后才提交数量。
- 动作失败或人工停止时，本次已放数量不增加。
- 码垛动作成功但 `commitPlaced()` 失败属于系统级错误，禁止继续调度。
- 区域已满时拒绝计算下一点和继续提交，提示人工搬运并清零。

## 8. 任务完成、失败和报警

### 8.1 正常完成

- 码垛动作完整成功；
- `commitPlaced()` 成功；
- 当前任务标记为 `Succeeded`；
- 有 Pending 任务时直接执行队首，不回 LM1；
- 没有 Pending 任务时清除当前任务并返回 LM1。

### 8.2 任务级失败

视觉失败、扫码最终失败、搜码移动失败、机械臂业务动作失败或码垛放置失败，优先进入安全收尾：

1. 保存明确失败原因；
2. 调用默认安全收姿态；
3. 收姿态成功后将当前任务标记为 `Failed`；
4. 有后续任务时继续 FIFO；
5. 没有后续任务时返回 LM1。

“当前任务失败但继续队列”的前提是安全收姿态已经成功。

### 8.3 系统级 Error

以下情况进入整线 Error：

- AGV 导航失败、取消、超时或通信错误；
- 返回 LM1 失败或超时；
- 必需工位或码垛配置缺失；
- 码垛配置无效；
- `commitPlaced()` 失败；
- 任务失败后的安全收姿态再次失败；
- 人工点击 Stop。

进入 Error 时：

1. 取消 AGV；
2. 停止机械臂；
3. 清空 Pending 队列；
4. 保留明确报警原因；
5. 禁止新的模拟缺料任务；
6. 等待人工处理和 Reset Error。

## 9. 当前上位机行为

“调度监控”区域当前显示：

- 系统状态；
- 当前任务；
- 待送料数量；
- 报警信息；
- Start、Stop、Reset Error；
- 工位 1～12 的模拟缺料按钮；
- Running 与 Pending 任务组成的 FIFO 表格；
- 最近完成和最近失败。

FIFO 表格只显示当前未完成任务，不保存长期历史。长期过程通过日志追踪，统一前缀格式为：

```text
[T#任务号 S两位工位号][阶段]
```

示例：`[T#18 S03][AGV]`。

当前工位按钮每点击一次就上报一次缺料任务：

- Idle 状态：任务进入 Pending，等待 Start；
- Running 状态且执行器空闲：立即开始队首；
- Running 状态且已有任务：追加到 FIFO；
- ReturningHome 状态：取消回 LM1 后执行新任务；
- Error 状态：按钮被禁用并拒绝上报。

## 13. 停止验收的条件

出现以下任一情况，立即停止当前验证，不得通过重复点击继续尝试：

- AGV 实际站点与目标 LM 不一致；
- 机械臂调用了错误示教函数或动作方向与预期相反；
- 机械臂、夹爪、箱体、AGV 或周边设备存在碰撞趋势；
- 扫码搜索超出预定 Y 轴范围；

- 码垛失败却增加了已放数量；
- 码垛成功后增加数量超过 1；
- 目标 TCP Z 安全校验失效；
- 系统级 Error 后仍继续派单；
- 无法说明设备当前状态或无法安全恢复。

## 16. 条件性现场回归项

当前代码和参数是已经完成现场修改、验证的基线。以下内容不是“当前尚未确认”，但发生相关变化后必须重新执行现场验收：

- 任一 `Func_capture*`、`Func_daoliao*`、`Func_pallet_*`、`Func_fanzhuan`、`Func_songzhua` 或安全位函数变化；
- 机械臂基座、相机、夹爪或工具坐标系重新安装；
- 箱体尺寸、重量、材料、条码位置或托盘尺寸变化；
