# 手动充电一键安全预检设计

## 一、背景与目标

当前软件首次启动后，充电桩尚无完整安全快照。此时
`ChargePileController::shutdownRequired()`保守返回真，操作人员必须先点击
“查询状态（只读）”，等待确认安全后再点击“开始充电”。

本次目标是把这两个操作合并：操作人员完成现有现场安全确认并点击一次
“开始充电”后，软件自动执行一次充电桩只读查询；查询明确安全后自动继续原有
DO0置高和充电流程，不要求再次点击按钮。

## 二、范围约束

- 只改变手动“开始充电”入口，不改变自动充电和主调度逻辑。
- 不新增生产类、不新增界面控件、不改变现有按钮布局。
- 不删除充电桩控制器内部原有启动前完整预检和参数写入后复检。
- 不绕过LM1、主调度空闲、AGV导航状态、自动模式互斥、控制器忙碌、
  `Unknown`和`Fault`门禁。
- 自动查询只读，不发送DO0命令或充电桩写命令。
- 查询未明确安全时绝不继续启动。

## 三、方案比较

### 方案一：由DeviceManager保存一次待启动意图（采用）

`startManualCharge()`在其他业务条件满足、但充电桩缺少安全快照时，保存一次
“手动启动待预检”意图并调用现有只读查询。查询完成后由`DeviceManager`重新
校验全部业务条件；只有控制器进入`SafeComplete`且
`shutdownRequired()==false`时，才调用现有`requestChargeStartWithDo0(Manual)`。

优点是异步安全时序仍集中在业务边界，MainWindow只负责显示结果；手动查询按钮
不会误触发启动。改动范围仅限DeviceManager、MainWindow连接和对应测试。

### 方案二：由MainWindow监听查询完成后再次调用开始

界面保存“本次查询来自开始按钮”的标志。实现代码较少，但业务安全时序进入UI，
窗口事件、普通查询和关闭流程更容易发生耦合，不采用。

### 方案三：取消首次安全快照门禁，直接依赖控制器内部预检

充电控制器本身确实会在写命令前执行完整预检，但直接放宽
`shutdownRequired()`可能混淆“首次未查询”和“上一会话尚未安全恢复”，安全边界
不够清晰，不采用。

## 四、详细时序

1. 操作人员点击“开始充电”，沿用现有现场安全确认对话框。
2. `DeviceManager::startManualCharge()`先检查：
   - 主调度为Idle；
   - AGV快照有效且位于LM1；
   - AGV无导航任务或已经到达；
   - 自动充电关闭且没有自动会话；
   - 控制器不忙，状态不是`Unknown`或`Fault`；
   - 应用没有进入关闭流程。
3. 若充电桩已经具有明确安全快照，直接进入现有DO0置高流程。
4. 若控制器处于可查询的初始或普通Idle状态但尚未明确安全：
   - 保存一次手动启动待预检标志；
   - 调用现有`queryStatus()`；
   - 返回“请求已接受”，界面不要求再次点击。
5. 查询完成后：
   - 先清除待预检标志，保证结果只消费一次；
   - 查询失败时发布手动启动失败结果，不设置DO0；
   - 查询成功但未进入`SafeComplete`时发布“充电桩未确认安全”，不设置DO0；
   - 查询明确安全时重新执行第2步全部门禁，防止查询期间车辆、调度或自动模式
     状态发生变化；
   - 复核通过后调用现有`requestChargeStartWithDo0(Manual)`。
6. DO0确认、充电桩两次启动预检、E11处理和安全收尾均保持现有实现。

## 五、并发与取消

- 待预检期间控制器处于忙碌状态，开始按钮和查询按钮沿用现有逻辑自动禁用。
- 查询期间主调度、AGV位置、导航状态或自动模式发生变化，查询完成后重新校验并
  拒绝继续启动。
- 应用关闭会接管或终止查询；查询失败结果清除待启动意图，不会在关闭过程中
  迟到启动。
- 普通“查询状态（只读）”不设置待启动意图，查询完成后只更新状态。
- 不自动重试查询，不重复发送DO0置高，不重复发送充电桩Start。

## 六、界面反馈

`DeviceManager`增加一个手动启动异步结果信号。MainWindow收到失败结果时显示
“手动充电被拒绝”及具体原因；成功进入DO0流程时记录日志并刷新现有状态标签。
不新增弹窗步骤、进度条或按钮。

## 七、测试与验收

自动化测试至少覆盖：

1. 源码契约确认开始入口能够发起只读预检，并在查询成功后进入统一DO0入口。
2. 查询失败或快照不安全时不会调用DO0置高和充电桩Start。
3. 查询完成后业务条件失效时不会继续启动。
4. 普通查询完成不会触发手动充电。
5. 既有DO0、充电桩控制器、关闭安全、自动协调器和主调度旁路测试继续通过。

现场验收：

- 软件重启且未先点查询时，点击一次“开始充电”能够自动查询并在安全时继续。
- 自动查询不安全或失败时不打开DO0、不发送充电桩Start，并提示原因。
- 整个成功流程只发送一次DO0置高意图和一次充电桩正常Start命令。
