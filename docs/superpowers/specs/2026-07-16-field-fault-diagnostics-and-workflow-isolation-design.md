# 现场故障诊断、调度超时与取料隔离设计

**日期：** 2026-07-16

**状态：** 已实施并完成自动化验证；49601 根因仍等待现场失败日志确认

**实施策略：** 定点最小改动

**实施计划：** `docs/superpowers/plans/2026-07-16-field-fault-diagnostics-and-workflow-isolation.md`

## 1. 背景与目标

根据 `2026-07-15+log (2).txt` 的现场日志，本次处理四项问题：

1. 三号工位机械臂执行工具坐标系相对运动时返回安全空间错误，但仅凭当前日志无法确定厂家控制器拒绝目标的准确原因。
2. AGV 途中被遮挡后，导航时间超过当前 120 秒上限，整线调度进入系统级错误并停止。
3. “启动取料（阶段一）”测试入口复用了总调度修改过的 `HuayanScheduler` 配置，导致单独测试继承上一次生产任务的工位函数和扫码开关。
4. 视觉在同一视野内识别到当前工位和相邻工位的多个箱子时，现有选择逻辑没有先限定当前工位范围，存在抓取相邻工位目标的风险。

本设计的目标是保留已经验证过的机械臂阶段状态机和生产调度链路，只在明确的接入点增加诊断、延长超时、隔离测试配置并改进视觉目标选择。

## 2. 不在本次范围内的内容

- 不根据现有日志修改华研控制器安全空间、工具坐标系、用户坐标系或奇异点参数。
- 不把工具坐标系相对运动的 381～404 mm 当作视觉 ROI 数据，也不新增 350 mm 或其他机械臂运动拒绝阈值。
- 不更换 `HRIF_MoveRelL`，不拆分或重写现有机械臂运动序列。
- 不解决 AGV 遮挡的根本原因；本次仅将允许的等待时间调整为 5 分钟。
- 不复制第二套 `HuayanScheduler` 状态机，也不允许两个调度器同时控制同一台机械臂。
- 不为 12 个工位分别维护视觉矩形；现场先使用一组共用参数。

## 3. 证据与根因边界

### 3.1 机械臂错误

日志中的实际错误码是 **49601**，不是 49061：

```text
[16:49:55] [华沿] 错误：相对运动 Y失败：49601（Target orientation exceeded cartesian safety space）
[16:52:13] [华沿] 错误：相对运动 Y失败：49601（Target orientation exceeded cartesian safety space）
[16:56:11] [华沿] 错误：相对运动 Y失败：49601（Target orientation exceeded cartesian safety space）
```

三次失败对应的工具坐标系 Y 相对运动约为 381.2 mm、403.8 mm、388.9 mm。现场确认这些距离属于正常业务范围。错误由 `HRIF_MoveRelL` 同步返回，表示控制器拒绝的是即将执行的目标；因此肉眼看到的当前位姿仍在安全空间内，并不能排除下一目标、目标姿态、关节解算或控制器安全空间检查失败。

项目使用的 `HR_Pro.h` 与新增的 `HuayanRobotSDKSample` 均来自 SDK V1.0.15.0，接口定义一致。厂家示例确认：

- `poseId` 0～5 分别表示 X、Y、Z、Rx、Ry、Rz。
- `direction` 0 表示负向，1 表示正向。
- `toolMotion=1` 表示 TCP/工具坐标系相对运动。
- SDK 提供实际 TCP、指令 TCP、关节角和轴错误码读取接口，可用于失败现场诊断。

当前日志缺少被拒绝命令前后的 TCP、关节角、指令位姿及各轴错误码，尚不足以可靠修复 49601。本次先补齐失败诊断，现场复测后再依据新日志决定是否需要第二阶段修复。

### 3.2 AGV 导航超时

日志中存在两次明确的 120 秒超时：

```text
[15:31:22] [T#5 S11][AGV] 请求导航到 LM7
[15:33:22] [T#5 S11][ERROR] 系统级 ERROR：AGV 导航到 LM7 超时（120000 ms）

[15:35:33] [T#6 S11][AGV] 请求导航到 LM17
[15:37:33] [T#6 S11][ERROR] 系统级 ERROR：AGV 导航到 LM17 超时（120000 ms）
```

活动链路中的 `TaskExecutor::kAgvTimeoutMs`、`LineManager::kReturnHomeTimeoutMs` 以及保留的旧 `LineOrchestrator::kAgvTimeoutMs` 均为 120000 ms。现场确认遮挡通常不会持续很久，本次统一调整为 300000 ms。

### 3.3 单独测试继承总调度配置

`TaskExecutor::start()` 会把工位配置写入共享的 `HuayanScheduler`，并启用抓取前扫码：

- `setStationFunctions(...)`
- `setPalletFunctions(...)`
- `setPreGripScanEnabled(true)`

而测试按钮 `MainWindow::onHuayanStartStageOne()` 直接调用同一个对象的无参 `startStageOne()`，启动前没有重新注入测试配置。日志显示总调度执行三号工位后，后续手工启动阶段一仍调用 `Func_capture3`；即使工位1已经加入送料队列，手工测试仍调用 `Func_capture3`。根因是共享对象中的可变配置按“最后一次写入”生效，而不是测试入口按所选工位显式配置。

### 3.4 多目标选择顺序与工位边界

当前 `VisionHttpClient::parseInferenceReply()` 使用一次线性两两比较：深度差达到 20 mm 时选择更高目标，同层时选择更靠近视野中心的目标。该实现存在两个问题：

1. 没有先排除当前工位矩形以外的目标，相邻工位箱子更高时可能被选中。
2. “不同层比较”和“同层比较”混在同一个循环中，最终结果可能受服务端目标返回顺序影响。

业务规则已经确认：先用 XY 矩形确定当前工位候选，再在候选中选最高层，同层时才选最靠近视野中心的箱子。

## 4. 总体方案

采用定点最小改动：

- 机械臂运动链路只增加失败诊断，不改变运动行为。
- AGV 只统一调整等待常量和超时日志，不改变状态机。
- 单独测试入口每次显式构造完整测试配置；生产入口仍按现有方式每次显式构造生产配置。
- 视觉选择拆成“矩形过滤、最高层分组、同层最近中心”三个确定性步骤。

## 5. 详细设计

### 5.1 问题1：49601 失败现场诊断

在 `HuayanScheduler` 发出 `HRIF_MoveRelL` 之前读取并暂存一次命令前快照，但成功路径不输出快照日志。快照结构及其字段必须增加注释，至少包含：

- 本地命令序号，用于把命令、返回码和诊断块关联起来。
- 相对运动轴、方向、距离及 `toolMotion` 坐标系标识。
- 实际 TCP 位姿。
- 控制器指令 TCP 位姿。
- 六轴实际关节角。
- 机器人 moving、pause、error 标志、FSM 状态和主错误码。
- `HRIF_ReadAxisErrorCode` 返回的总错误码及六轴错误码。

仅当 `HRIF_MoveRelL` 返回非零时，再读取一次命令后状态并集中输出一次诊断块。每条失败命令最多输出 3～4 行：

1. 命令序号、轴、方向、距离、坐标系及 SDK 返回码。
2. 命令前实际 TCP、指令 TCP。
3. 命令前关节角，以及命令后的 flags/FSM/主错误码。
4. 仅在轴错误读取成功或诊断读取失败时输出轴错误/读取失败摘要。

日志去重以本地命令序号为单位，同一失败命令只输出一次。诊断接口读取失败不得覆盖原始 49601，也不得触发轮询重试；只追加一条读取失败摘要。正常运动不输出这些快照，因此不会形成持续日志刷屏。

本阶段验收结果是“获得足以定位 49601 的新现场日志”，不是宣称已经消除 49601。

### 5.2 问题2：AGV 等待时间统一为 5 分钟

以下超时常量统一改为带单位注释的 300000 ms：

- `TaskExecutor::kAgvTimeoutMs`
- `LineManager::kReturnHomeTimeoutMs`
- `LineOrchestrator::kAgvTimeoutMs`

行为保持如下：

- AGV 仍处于运行/等待状态时，最多等待 5 分钟。
- AGV 明确返回 `Failed`、`Canceled` 或自身 `Timeout` 时立即进入现有错误处理，不继续等满 5 分钟。
- 上位机 5 分钟超时时，日志记录目标 LM、实际等待毫秒数和配置的超时毫秒数。
- 不改变任务队列、返航条件、停机和复位状态转换。

### 5.3 问题3：单独阶段一测试与总调度隔离

#### 5.3.1 UI 与入口

在“启动取料（阶段一）”按钮旁增加工位下拉框，显示 1～12 号工位。下拉框成员变量、槽函数参数和测试入口接口都要说明其仅用于手工阶段一测试。

UI 只读取工位编号并调用设备/业务层测试入口，不在 `MainWindow` 内拼装机械臂函数名。

#### 5.3.2 测试配置

测试入口根据所选工位调用现有 `stationConfig(stationId)`，每次启动前显式注入：

- `captureFunc`，即 `Func_captureN`。
- `afterGripMode` 与 `afterGripFunc`。
- `grabZClearance`。
- 现有阶段一执行所依赖的其他工位字段。
- `setPreGripScanEnabled(false)`，明确关闭扫码。

配置完成后仍调用已经验证过的 `HuayanScheduler::startStageOne()`，不复制视觉闭环、下探、夹紧、抬升和抓取后动作状态机。

#### 5.3.3 生产配置保持不变

总调度继续在每个任务启动时通过 `TaskExecutor::start()` 注入完整工位/码垛配置，并调用 `setPreGripScanEnabled(true)`。因此：

- 手工测试不会依赖上一次生产任务残留配置。
- 下一次生产任务也不会依赖手工测试残留配置。
- 不需要创建第二个机械臂调度器。

#### 5.3.4 互斥保护

只有整线处于完全空闲、没有活动 `TaskExecutor` 且机械臂阶段状态机未运行时，才允许启动单独测试。测试运行期间禁用总调度 Start 和工位下拉框；总调度运行、返航或错误未复位时禁用单独测试。

如果业务层收到非法并发启动请求，应拒绝启动并发出明确日志，不能只依赖按钮禁用状态。

### 5.4 问题4：先 XY 工位范围，再选最高层 Z

#### 5.4.1 共用矩形参数

在视觉客户端头文件中增加现场易修改、带单位和用途注释的共用宏：

```cpp
// 当前工位候选矩形的 X 半宽，单位 mm；仅过滤视觉原始 offset_mm.x，不参与机械臂运动限位。
#define VISION_STATION_ROI_HALF_X_MM 500.0

// 当前工位候选矩形的 Y 半宽，单位 mm；仅过滤视觉原始 offset_mm.y，不参与机械臂运动限位。
#define VISION_STATION_ROI_HALF_Y_MM 500.0
```

初始有效范围为 X、Y 均在 -500～+500 mm 内，12 个工位共用。边界点按有效目标处理。现场根据新增候选日志调整宏时，文档中的默认值必须同步更新。

#### 5.4.2 确定性选择算法

目标选择必须拆为独立、可单元测试的逻辑，并给候选结构、选择结果、接口和中间变量增加注释：

1. 解析全部合法目标，保存原始 `offset_mm.x/y`、`depth_compensated`、角度和置信度。
2. 过滤掉 `abs(x) > 500` 或 `abs(y) > 500` 的目标。
3. 如果矩形内没有合法目标，发出既有 `noObjectDetected()`，不向机械臂发送偏移量。
4. 在矩形内候选中找到最小 `depth_compensated`，它代表最高层基准。
5. 将与最高层基准深度差不超过现有 `kSameLayerTolMm=20` 的目标组成同层候选集。
6. 在同层候选集中选择 `x*x + y*y` 最小的目标。
7. 完全相同的目标使用原始数组下标作为最终稳定兜底，不再让不同层和同层规则交替覆盖结果。

该顺序保证：矩形外的相邻工位箱子即使更高也不会入选；当前工位内优先最高层；同层才比较 XY 距离。

#### 5.4.3 视觉选择日志

每次推理响应输出一条候选摘要，包含：

- 候选总数和矩形内数量。
- 每个候选的数组下标、原始 X/Y、补偿深度 Z，以及 `inside/outside`。
- 最终选中下标，或“矩形内无合法目标”。
- 选择原因：最高层、同层最近中心或稳定兜底。

该日志只在现有视觉推理请求收到响应时输出，不按相机帧率持续打印。候选较多时仍合并为一条摘要，避免多行刷屏。

## 6. 数据流与状态约束

### 6.1 生产取料

`LineManager` → `TaskExecutor` → 注入所选工位生产配置并启用扫码 → `HuayanScheduler::startStageOne()` → 现有阶段状态机。

### 6.2 单独测试取料

测试面板工位下拉框 → 业务层验证整线和机械臂均空闲 → 注入所选工位测试配置并关闭扫码 → `HuayanScheduler::startStageOne()` → 同一套现有阶段状态机。

### 6.3 视觉目标

视觉 JSON → 合法性校验 → 共用 XY 矩形过滤 → 最高层分组 → 同层最近中心 → 现有坐标转换 → `rawCoordinatesReady`。

## 7. 错误处理原则

- 机械臂诊断读取失败不替代原运动错误，不自动复位控制器，也不自动重试危险动作。
- AGV 明确失败仍立即走现有系统级错误流程。
- 单独测试的工位编号无效、配置缺失或系统非空闲时拒绝启动，并说明原因。
- 视觉字段缺失、非数值或没有矩形内目标时按无目标处理，不使用默认零值制造虚假目标。
- 新增日志不得包含循环级状态刷屏；机械臂快照仅失败时输出，视觉摘要每次推理响应最多一条。

## 9. 测试与验收

### 9.1 自动化测试

视觉目标选择至少覆盖：

- 矩形外目标更高、矩形内目标较低时，选择矩形内目标。
- 同层两个目标选择离中心最近者。
- 不同层目标优先最高层，而不是更靠近中心者。
- 调换 JSON 目标顺序后，选择的物理目标不变。
- X/Y 恰好为 ±500 mm 时属于有效边界。
- 所有目标在矩形外、数组为空、关键字段缺失或非数值时返回无目标。

测试配置隔离至少覆盖：

- 选择工位1、3、12时分别注入对应 `Func_captureN` 和工位抓取后配置。
- 手工阶段一始终关闭扫码。
- 生产任务仍启用扫码并注入原有工位和码垛配置。
- 总调度非空闲或机械臂运行时，手工测试被拒绝。
- 手工测试后启动生产任务，生产配置不会继承测试值。

超时与诊断至少覆盖：

- 三处上位机导航超时均为 300000 ms。
- 明确的 AGV 失败状态不等待 300000 ms。
- 成功的 `MoveRelL` 不输出诊断快照。
- 失败的 `MoveRelL` 只输出一次关联同一命令序号的诊断块。
- 诊断读取失败时仍保留原始 SDK 错误码。
