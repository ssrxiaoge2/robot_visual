## 1. 目标

在不改变 `e1ffb3f` 既有十二工位主调度行为的前提下，把已经独立验证的现场缺料计算接入主调度。调度监控面板提供“模拟缺料 / 真实缺料”二选一；真实缺料任务与模拟任务共用现有 `LineManager`、严格 FIFO 和全部硬件执行流程。

生产缺料必须形成闭环：预计库存触及安全阈值时派单，只有机械臂实际倒料成功才增加一箱；倒料后仍缺料时，只向 FIFO 队尾追加下一箱。

## 2. 强制边界

### 2.1 不能改变的内容

- 不改变 `e1ffb3f` 的 Start、Stop、Reset Error、Error、ReturningHome 和 FIFO 行为。
- 不改变 AGV、视觉、扫码、机械臂动作、空箱码垛和安全恢复状态跳转。
- 不修改 `ShortageTestPanel`、`ShortageTestSession`、测试面板 UI、测试面板计算逻辑或已有测试面板测试。
- 不修改历史 spec/plan。
- 不使用 Python 作为本项目验收手段。
- 实施任务期间不提交 Git，由用户最终人工统一提交。

### 2.2 允许的最小增量

- 重写当前已与主调度断开的 `ShortageMonitor`，使其只承担生产真实缺料会话。
- 在不改变现有测试行为的前提下，为 `ShortageCalculator` 增加“实际倒料后加一箱”等最小生产接口。
- 为 `TaskExecutor`、`LineManager`、`DeviceManager` 增加倒料和任务终态通知，不改变既有调度决策。
- 在调度监控面板增加来源二选一和精简的十二工位状态表。

## 3. 架构与职责

```text
MES / PLC
   ├─ ShortageTestSession ─> ShortageTestPanel
   │                         只测试、只展示、绝不派单
   │
   └─ ShortageMonitor ─> DeviceManager ─> LineManager ─> 现有 FIFO/TaskExecutor
            ^                                      |
            └──── 倒料成功、任务成功/失败通知 ─────┘
```

- `CustomSysScheduler`：保留 HTTP 请求、MES/PLC JSON 解析和固定端点职责，不计算库存、不派单。
- `ShortageCalculator`：维护十二工位预计库存，执行产量扣减、阈值判断和倒料加箱；不操作 FIFO。
- `ShortageTestSession`：冻结，只服务测试面板。
- `ShortageMonitor`：生产专用会话；负责四请求聚合、模式稳定确认、运行期内存状态、工位任务占用、派单请求和任务结果对账。
- `TaskExecutor`：只在既有 `ArmUnload` 成功完成的状态转换点报告倒料事实；不计算库存。
- `LineManager`：保持现有严格 FIFO，只转发任务入队、开始、倒料、成功、失败或取消事实。
- `DeviceManager`：持有并连接生产会话；保证测试会话和生产会话互斥。
- `MainWindow`：只负责来源选择和状态展示，不执行网络、计算或调度规则。

## 4. 已确认的库存模型

### 4.1 初始化与扣减

本阶段每个工位独立维护预计库存：

```text
临时初始化：estimatedAvailable = safetyStock + boxQuantity
productionDelta = currentActualQty - previousActualQty
consumption = productionDelta * usagePerProduct(station, product, mode)
estimatedAvailable -= consumption
estimatedAvailable <= safetyStock：缺料
```

- 首个完整有效样本只建立 MES 基线，不扣减库存。
- 十二工位分别扣减，不在工位之间分摊总消耗。
- 预计库存允许为负数，不得截断为零。
- 只有 `CustomerSystem` 真实任务的倒料成功事件可以增加库存；`UiMock` 永远不能改变真实库存。
- 一次倒料成功只增加该工位配置中的一箱数量。

### 4.2 临时初始化假设

“安全阈值 + 一箱”不是已确认的客户真实库存，只是当前没有初始库存接口时的临时假设。它避免程序启动后十二工位立刻集中派单，但若现场实际无料，系统可能长期漏报初始空料。

在客户确认或真实库存接口完成前，启用真实缺料的现场前提是：操作人员已经确认各工位具备至少与该假设相符的基础物料。UI 和日志必须明确提示“库存为估算初值”。

## 5. 缺料派单与倒料闭环

### 5.1 工位状态

```text
正常
  -> 缺料待入队
  -> 已排队 / 执行中（尚未倒料）
  -> 已倒料待当前任务完成
  -> 正常，或再次缺料并追加下一箱
```

### 5.2 防重复与连续补料

- 工位首次缺料时申请向 FIFO 队尾添加一个真实任务。
- 主调度拒收时保留“缺料待入队”；调度恢复可接收后自动重试，拒收不改变库存。
- 同一工位存在尚未倒料的真实任务时，后续五秒轮询不得重复派单。
- `ArmUnload` 实际成功后立即加一箱并重新判断。
- 加箱后仍缺料时，立即向 FIFO 队尾追加一个下一箱任务；不插队、不重排既有任务。
- 下一箱只能等待，当前任务的收姿态、码垛等完整流程结束后，现有调度器才可按 FIFO 执行它。
- 不设置连续补料箱数上限：只要仍缺料，就按上述规则继续补料。
- 允许上一任务已经倒料但仍在收尾、下一箱已在 FIFO 等待；但同一工位不能同时存在两个“尚未倒料”的真实任务。

### 5.3 倒料事实与幂等保护

- 正常实现必须确保倒料成功信号只连接一次。
- 状态恢复或重试不得重新上报已经发生的倒料成功。
- 倒料成功只允许在 `ArmUnload` 成功完成并进入 `StowAfterUnload` 的明确状态转换点发出一次。
- `taskId` 幂等检查仅作为防止未来代码回归的最后保护，不能掩盖重复连接或错误状态流转。

## 6. 任务失败、Stop 与 Error

- 倒料前任务失败或被取消：不增加库存；释放该任务的工位占用，主调度恢复后若仍缺料则重新派单。
- 倒料后收姿态、码垛或后续步骤失败：物料已经进入工位，库存增加不得回滚；已经追加到 FIFO 的下一箱不得删除。
- Stop/Error 清理仍完全遵循现有主调度语义；生产缺料层只根据收到的任务终态释放或保留占用。
- 已经进入 FIFO 或正在执行的真实任务不因来源切换而删除或中断。
- 每个任务事件必须携带 `taskId`、`stationId` 和 `TaskSource`，生产层必须过滤非 `CustomerSystem` 任务。

## 7. 来源切换与会话生命周期

- 调度监控默认“模拟缺料”。
- 模拟模式启用现有十二个模拟按钮，不运行生产真实缺料会话。
- 选中“真实缺料”即自动停止可能运行的测试会话、禁用模拟按钮并启动生产真实缺料会话；不增加第二层授权按钮。
- 切回模拟模式只停止真实轮询和新增真实任务；已有真实任务继续执行。
- 模拟模式下已有真实任务倒料成功时仍按事实完成加箱和终态对账，但不得因此追加下一箱；再次进入真实模式后才重新评估并派单。
- 同一次程序运行内再次切回真实模式时，恢复原预计库存、MES 基线和工位任务状态，不重新初始化。
- 只有程序重启才按“安全阈值 + 一箱”重新初始化。本阶段不持久化。
- 测试面板只是调试功能，实际生产场景不使用；本项目不修改它，只调用已有停止接口实现互斥。

## 8. 产品、生产方式与通信

### 8.1 信号有效性

- `L71/L72/L73` 必须恰好一个为真，分别表示 88、88R、92。
- `L68/L69/L1998` 必须恰好一个为真，不使用优先级猜测。
- 产品或方式变化必须由连续两个完整有效轮次一致后确认。
- 一轮必须收齐一个 MES 和三个 PLC 请求；禁止跨轮混用、禁止迟到响应污染新轮次。

### 8.2 产品切换

- 本阶段确认新产品后，按新产品配置重新初始化十二工位并重建 MES 基线。
- 若仍有旧产品真实任务在执行或 FIFO 中，旧任务继续按现有主调度完成，不清队列。
- 等待旧产品真实任务全部进入终态期间，监测新产品状态但暂停新产品真实派单。
- 旧任务全部结束后，才允许新产品缺料进入 FIFO。
- 该方案为暂定方案，必须向客户确认。

### 8.3 仅生产方式切换

- 连续两轮确认新方式后，保留十二工位当前预计库存。
- 以确认轮的 `actualQty` 重建 MES 基线，避免强行归属切换边界产量。
- 后续增量按新方式用量扣减。

### 8.4 通信失败与恢复

- 任一请求失败、超时、JSON错误或位信号不唯一时，本轮不计算、不派单。
- 通信异常只暂停真实缺料判断，不影响已有调度任务。
- 恢复后的第一个完整有效样本只重建 MES 基线，不追算断线期间产量。
- 既有预计库存保留；产品变化仍按产品切换规则处理。

## 9. 调度监控 UI

调度监控增加“模拟缺料 / 真实缺料”互斥选择，默认模拟。真实模式增加顶部概要：运行状态、当前产品、生产方式、MES通信状态和“库存为估算初值”提示。

十二工位生产状态表固定为三列：

| 工位 | 库存/安全线 | 状态 |
|---:|---:|---|
| 3 | `48 / 50` | 缺料待入队 |

状态文案限定为：

- 正常
- 缺料待入队
- 已排队
- 执行中
- 已倒料待任务完成
- 通信暂停
- 配置异常
- 换型等待旧任务完成

生产面板不复制测试面板的六个 PLC 位、详细产量增量或测试控制按钮。FIFO 继续显示任务来源。

## 15. 需要客户确认

1. “安全阈值 + 一箱”的初始估算及启用前基础物料前提。
2. `预计库存 <= 安全阈值` 是否立即派单。
3. 一次倒料是否始终等于配置中的一箱。
4. 只要仍缺料就持续补料且不设箱数上限。
5. 同工位续补任务严格排在 FIFO末尾。
6. 换型时旧任务继续、新产品暂停派单。
7. 产品/方式连续两轮确认的延迟。
8. 通信恢复不追算断线产量。
9. 程序重启后重新初始化库存。
10. 倒料后收尾失败不回滚已补库存。
11. 三列生产状态表和客户可见名称是否合适。

这些项目在客户确认前均是本阶段临时决策，不得描述为客户最终规则。

## 16. 后续优化方向

- 接入客户真实初始库存，消除启动假设。
- 原子持久化各产品、各工位库存和在途任务。
- 分别保存 88、88R、92 库存，换型切回时恢复旧状态。
- 信号连续可信时补算短时断线期间产量。
- 异常重启后恢复任务，并处理“是否已经倒料”的不确定状态。
- 根据客户意见增加连续补料上限、告警或人工确认。
- 根据现场节拍评估是否调整 FIFO 优先级。
- 正式上线后隐藏或移除测试面板。
- 接入独立硬件倒料完成反馈，替代或校验软件动作完成回调。

## 17. 完成标准

- 真实缺料能够在调度监控中启停并安全进入现有 FIFO。
- 模拟缺料、测试面板和 `e1ffb3f` 既有主流程无行为回归。
- 库存只在真实倒料成功后增加，持续缺料按 FIFO队尾逐箱补料。
- 失败、换型、通信和来源切换均不会造成重复派单、错误加箱或清除既有任务。
- 自动验证全部通过，现场验收逐项记录。
- 客户未确认项和后续优化方向清晰可追溯。
