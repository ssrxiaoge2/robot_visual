## 2. 目标

在不改变现有送料任务、机械臂、视觉、扫码和码垛流程语义的前提下，为 `robot_visual` 增加以下能力：

1. 在现有“AGV 调试”面板下方、“华沿 SDK 调试”面板上方增加紧凑的“充电调试”面板。
2. 将已经通过 Python 现场验证的充电桩通信和五阶段充电流程移植为 Qt/C++ 非阻塞实现。
3. 提供仅在主调度未启动时使用的手动充电调试。
4. 提供由主调度授权、默认关闭的自动充电模式。
5. 在任务队列、电量阈值和 LM1 充电站之间安全协调，不丢失或重排待执行任务。
6. 对停止充电、程序关闭、通信中断和充电桩故障实施可追溯的安全处理。

## 3. 范围边界

### 3.1 本次包含

- 充电桩原始 Modbus RTU 经 TCP 透传通信。
- 充电状态查询、参数写入和回读、正常启动、监控、停止、缩回、复位。
- 手动开始、手动停止和只读状态查询。
- 自动充电开关及 15%、20%、80% 三个电量阈值。
- 自动充电与 `LineManager` 队列调度的互锁。
- 充电参数持久化，自动充电开关不持久化。
- 程序关闭前的充电安全收尾。
- 仙工 AGV 的 DO0 充电许可：充电前置高确认、充电期间低频监控、充电完成后置低。
- 协议、状态机、自动策略、调度接入和关闭保护测试。

### 3.2 本次不包含

- 不通过子进程调用 Python 脚本。
- 不增加强制启动能力。
- 不把手动伸出、手动缩回或脉冲伸缩按钮放入正式调试面板。
- 不修改 Roboshop 的 10% 低电量报警配置。
- 不修改现有送料任务内部步骤及机械臂、视觉、扫码和码垛动作。
- 不改变现有主调度 Stop 清空队列并进入 Error 的急停语义。
- 不在自动化测试中控制真实充电桩进行写操作。
- 不为单个 DO0 增加新面板、新协调器或新的业务类。

## 4. 已确认的现场参数

### 4.1 电量策略

| 项目 | 数值 | 判定 |
|---|---:|---|
| Roboshop 固定报警下限 | 10% | 电量小于或等于该值时记录严重报警并禁止开始下一任务 |
| 启动充电阈值 | 15% | 电量严格低于该值时申请充电 |
| 允许接单电量 | 20% | 充电中存在待执行任务且电量达到或超过该值时申请安全收尾 |
| 正常停止阈值 | 80% | 充电中没有待执行任务且电量达到或超过该值时申请安全收尾 |

界面必须校验：

```text
10% < 启动充电阈值 < 允许接单电量 < 正常停止阈值 <= 100%
```

### 4.2 充电桩参数

| 参数 | 默认值 | 说明 |
|---|---:|---|
| 充电桩地址 | 192.168.115.108 | PW31B TCP 服务端地址 |
| TCP 端口 | 8899 | PW31B TCP 服务端端口 |
| Modbus 站号 | 1 | 原始 RTU 帧站号 |
| 充电电压 | 58.4 V | 已通过 Python 现场验证 |
| 充电电流 | 50.0 A | 已通过 Python 现场验证 |
| 截止电流 | 默认关闭 | 未勾选时绝不写 4x27 |
| 充电桩最大时间 | 默认关闭 | 未勾选时绝不写 4x32 |
| 单帧响应超时 | 5 秒 | 现场验证命令使用值 |
| TCP 连接超时 | 3 秒 | Python 默认值 |
| 状态轮询间隔 | 5 秒 | 现场验证命令使用值 |
| 启动等待超时 | 90 秒 | 现场验证命令使用值 |
| 最长监控时间 | 500 秒 | 现场验证命令使用值；到时主动安全收尾 |
| 停止等待超时 | 20 秒 | Python 默认值 |
| 推杆动作超时 | 30 秒 | Python 默认值 |
| 安全无输出电流 | 1.0 A | 不高于该值才可判定为无输出 |
| 充电开始检测电流 | 0.5 A | 高于该值可判定已经开始充电 |
| 允许写入最高电压 | 100.0 V | 内部安全上限，不开放普通界面修改 |
| 允许写入最高电流 | 120.0 A | 内部安全上限，不开放普通界面修改 |

安全无输出电流不是可任意放大的调试参数。Python 现场实现以 `1.0 A` 作为
停止后允许缩回的权威边界，Qt/C++ 的统一校验、INI 加载和设置窗口均将其硬上限
固定为 `1.0 A`；不得使用 50 A 充电电流或其他大值替代此判据。

轮询与有限阶段超时必须同时满足：

```text
状态轮询间隔 <= 启动等待超时
状态轮询间隔 <= 停止等待超时
状态轮询间隔 <= 推杆动作超时
最长监控时间为0（无限）或 状态轮询间隔 <= 最长监控时间
```

每次有限阶段完成快照后，下一轮等待取“配置轮询间隔”和“距阶段截止点剩余
时间”的较小值。INI 中该组合非法时只回退超时与轮询组，不修改 15%、20%、
80% 电量阈值。

## 5. 总体架构

### 5.1 唯一充电控制器

新增 `ChargePileController`，作为充电桩唯一通信和控制入口，负责：

- TCP 连接和接收缓冲。
- Modbus RTU 帧生成、CRC 校验、响应解析和异常响应识别。
- 严格串行的一问一答请求队列。
- 完整充电状态机。
- 查询、开始、停止和关闭收尾请求的优先级处理。
- 输出可供界面和自动策略使用的结构化状态。
- 记录发送报文、接收报文、解析结果、耗时和故障原因。

手动界面、自动策略、主调度 Stop 和程序关闭都不能直接持有套接字或发送 Modbus 报文，只能向此控制器提交请求。

只读快照确认“无输出且缩到位”仍不一定能够解除全部写入不确定性。若缩回
线圈 ON 已确认而 OFF 未确认，或缩回写入结果仍不确定，机械到位不能证明线圈
电平已经释放；控制器必须继续保持 `Unknown` 和 `shutdownRequired()`，不得发布
`SafeComplete`。手动开始与自动授权入口都必须直接检查 `shutdownRequired()`，
不能只依赖可能尚未刷新的状态枚举。

### 5.2 独立自动充电协调器

新增 `AutoChargeCoordinator`，只负责策略判断，不包含任何充电协议：

- 接收 AGV 最新电量、当前位置和导航状态。
- 接收 `LineManager` 的运行状态、当前任务和队列快照。
- 接收自动充电开关状态。
- 按 15%、20%、80% 规则决定是否申请调度保持、返回 LM1、开始充电或停止充电。
- 将充电成功、失败和安全收尾结果反馈给主调度。

协调器不直接派发 AGV 导航。前往 LM1 仍由 `LineManager` 负责，避免出现两个 AGV 导航所有者。

### 5.3 现有类的最小接入

- `DeviceManager` 持有并连接唯一的 `ChargePileController` 和 `AutoChargeCoordinator`。
- `AgvController` 继续作为仙工 AGV Modbus 的唯一所有者，并在原类内封装 DO0
  置高、置低、只读确认和有限重试；其他类不得直接使用 DO0 寄存器地址。
- 手动和自动充电入口在 `DeviceManager` 的现有业务边界汇入同一套 DO0 前置
  门禁，不新增跨设备充电协调器，不改变 `ChargePileController` 已验证的内部状态机。
- `MainWindow` 只负责充电面板、参数对话框、状态显示和用户确认。
- `LineManager` 增加“因充电暂缓派单”的最小接口，并继续拥有 FIFO 队列、任务启动和返回 LM1 导航。
- `TaskExecutor` 及其他设备流程不加入充电逻辑。

### 5.4 AGV DO0 充电许可

DO0 是 AGV 自身的充电许可，不是充电桩工作状态，也不能替代充电桩的输出、
继电器、电流和推杆安全判据。现场确认“打开/关闭”分别对应高电平/低电平，
并且整个充电期间必须保持高电平。

仙工寄存器按地址空间分别处理：

| 操作 | Modbus 区域与文档地址 | 语义 |
|---|---|---|
| 打开 DO0 | `[0x]00060` 写 1 | 将 DO0 置为高电平，命令位由 AGV 自清零 |
| 关闭 DO0 | `[0x]00020` 写 1 | 将 DO0 置为低电平，命令位由 AGV 自清零 |
| 查询 DO0 | `[1x]00060` | 0 为低电平，1 为高电平 |

不得把以上三个地址误当作同一个线圈直接写 0/1。`AgvController` 对外只提供
具名异步接口，不暴露上述地址。

开始充电时：

1. 先读取 DO0；已经为高时不重复写入。
2. 为低时只发送一次置高命令。
3. 写响应失败或超时时不盲目重复写，改为读取实际状态。
4. 最多确认三次，间隔 500 毫秒。
5. 只有明确确认 DO0 为高，才允许调用既有充电桩启动入口。
6. 仍为低或无法确认时拒绝本次手动或自动启动，不向充电桩发送启动命令。

充电期间：

1. 进入充电会话后每 30 秒读取一次 DO0，不修改现有充电桩 5 秒状态轮询。
2. 明确读到低电平时，立即向既有充电状态机申请安全停止，不自动重新置高。
3. 单次或连续两次读取失败只记录；连续三次读取失败时申请安全停止。
4. 重复监控结果不得重复发送停止请求。

充电结束时：

1. 停止过程中继续保持 DO0 高电平。
2. 必须先由充电桩既有状态机完成停止、确认无输出、缩枪、复位和最终安全查询。
3. 安全完成后再通过 `AgvController` 关闭 DO0，并按开始时相同规则最多确认三次。
4. DO0 关闭失败只记录明确警告，不改变充电桩原有成功结果，不阻止调度恢复或
   应用退出。

软件启动或 AGV 重连后，只有在当前不存在本进程管理的充电会话且发现 DO0 已经
为高时，才执行轻量判断：

1. 对充电桩执行一次只读状态查询。
2. 明确确认无工作、继电器断开且电流安全时，自动关闭 DO0。
3. 检测到仍有输出，或充电桩状态查询失败时，保持 DO0 高并记录提示。
4. 此轻量判断不自动启动完整保守恢复，也不把 DO0 高电平解释为充电桩正在工作。

## 6. 互斥和请求优先级

### 6.1 手动与自动互斥

手动开始充电必须同时满足：

1. 主调度处于 Idle，尚未 Start。
2. AGV 最新监控显示当前位置为 LM1。
3. AGV 导航状态不是等待或运行。
4. 充电控制器处于可接受新会话的空闲状态。
5. 参数校验全部通过。
6. 操作人员完成一次现场安全确认。
7. AGV DO0 已按第 5.4 节明确确认处于高电平。

主调度已经 Start 后，即使当前队列为空，手动开始按钮也必须禁用。手动停止按钮在任何充电活动阶段保持可用。

### 6.2 请求优先级

从高到低依次为：

1. 程序关闭安全收尾。
2. 主调度 Stop。
3. 人工停止充电。
4. 关闭自动充电开关。
5. 自动策略因任务到达或达到阈值申请停止。
6. 手动或自动开始充电。
7. 只读状态查询。

开始请求不能打断任何活动会话。停止请求具有幂等性，重复停止不得产生并发报文或重复状态机。

## 7. 充电状态机

### 7.1 状态集合

控制器至少包含以下可观察状态：

- 空闲。
- 正在连接。
- 正在预检。
- 正在写入参数。
- 正在回读参数。
- 正在发送启动命令。
- 正在等待启动反馈。
- 正在充电监控。
- 正在发送停止命令。
- 正在等待无输出。
- 正在缩回。
- 正在等待缩到位。
- 正在复位。
- 安全完成。
- 故障。
- 状态未知。

界面文案使用中文。内部枚举名称由实施计划统一确定。

### 7.2 阶段一：连接和预检

1. 建立 TCP 连接。
2. 读取 3x01、3x02、3x13、3x14、3x18 和 3x20。
3. 校验不能同时出现“伸到位”和“缩到位”。
4. 启动前仅豁免厂家确认的 E2、E3、E4、E7、E8。
5. E1、E5、E6、E9、E11、E12、E13、E14 及其他未豁免故障必须阻止启动。
6. 如果设备已经有输出、继电器吸合或推杆状态与新会话不一致，不得直接发送新的启动命令，必须先查询并进入人工确认或安全恢复。

### 7.3 阶段二：写入和回读参数

1. 将 58.4 V 按协议乘以 10 写入 4x24，原始值为 584。
2. 将 50.0 A 按协议乘以 10 写入 4x25，原始值为 500。
3. 只有勾选“写入截止电流”时才写 4x27。
4. 只有勾选“写入充电桩最大时间”时才写 4x32。
5. 写入完成后必须回读并逐项比对。
6. 任一回读值不一致都必须终止启动，不能进入下一阶段。

### 7.4 阶段三：启动和等待反馈

1. 发送正常启动线圈，报文地址为 `0x0003`。
2. 不使用强制启动，不提前使用手动伸出线圈。
3. 在 90 秒内每 5 秒读取一次完整状态。
4. 满足以下任一条件即可进入监控：
   - 3x13 的伸到位信号为真。
   - 3x14 的工作状态为真。
   - 输出电流高于 0.5 A。
5. 等待期间继续记录 E2、E3、E4、E7、E8，但不以这些已确认豁免位阻止进入监控。
6. 若正常启动命令已经确认发送，等待启动反馈期间首次出现 E11“没有可用充电
   模块”，不得立即结束会话，也不得重复发送启动命令。
7. 从首次观察到 E11 起进入 30 秒受控等待，只执行完整只读状态查询：
   - 30 秒内 E11 消失，并观察到伸到位、工作状态或输出电流高于 0.5 A，
     则继续进入正常监控；
   - E11 持续达到 30 秒仍未满足开始条件，则进入既有安全收尾；
   - 等待期间出现 E11 之外的非豁免故障，立即进入既有安全收尾；
   - 已经观察到实际充电输出后再次出现 E11，不再适用 30 秒等待，立即安全收尾。

该例外只适用于“正常启动命令已经发送、尚未观察到实际充电输出”的启动等待
阶段。启动命令发送前的预检 E11 仍然阻止启动。

### 7.5 阶段四：充电监控

1. 每 5 秒读取完整状态。
2. 尚未观察到工作、继电器吸合或电流上升时，不能因为暂时 0 A 立即停止或缩回。
3. 满足以下任一条件时进入安全收尾：
   - 自动策略请求停止。
   - 人工停止。
   - 关闭自动充电开关。
   - 主调度 Stop。
   - 程序关闭。
   - 出现非豁免故障。
   - 3x18 出现 41 至 47 的停止事件。
   - 曾经观察到工作、继电器吸合或电流上升，随后变为无输出。
   - 达到 500 秒最长监控时间。

### 7.6 阶段五：停止、缩回和复位

1. 发送停止线圈，报文地址必须为 `0x0006`，不能使用厂家旧资料中的错误示例地址。
2. 轮询直至工作状态清零、继电器断开且输出电流不高于 1.0 A。
3. 未确认无输出时不得发送缩回命令。
4. 发送缩回线圈，报文地址为 `0x0001`。
5. 等待 3x13 的缩到位信号。
6. 缩回阶段只忽略 E8；E12、E13、E14 等机械故障及其他故障仍然必须拦截。
7. 缩到位后发送复位线圈，报文地址为 `0x0007`。
8. 复位后再次读取完整状态，确认无输出和缩到位。
9. 只有完成以上确认才发出“安全收尾完成”信号。

## 8. 通信安全规则

1. 发送的是带站号和 CRC 的 Modbus RTU 二进制帧，不添加 Modbus-TCP MBAP 头。
2. 同一连接任何时刻最多存在一个未完成请求。
3. 校验响应站号、功能码、字节数、异常码和 CRC。
4. 接收缓冲必须处理拆包和粘包，不能假定一次读取对应一帧。
5. 连续请求之间遵守 Python 脚本中的最小请求间隔。
6. 只读查询失败可以在重新连接后重试。
7. 写命令超时或连接中断时，不能直接重发启动、停止或机械动作命令，因为设备可能已经执行但响应丢失。
8. 写命令结果不确定时进入“状态未知”，重新连接后先执行只读查询，再依据真实输入、输出和电流决定后续动作。
9. 任何情况下都不得把“TCP 已断开”解释为“充电已经停止”。
10. 自动重连后绝不自动重复启动命令。

## 9. 自动充电调度规则

### 9.1 生效条件

自动策略仅在以下条件同时满足时生效：

- 自动充电开关已由操作人员确认开启。
- `LineManager` 已经 Start，状态不是 Idle 或 Error。
- AGV 监控数据有效。

只开启自动充电开关不会自动 Start 主调度。

自动开关开启且主调度已经 Start 后，如果尚未取得有效 AGV 监控数据，则协调器必须申请派单保持并显示“等待 AGV 电量和位置状态”，不能在无法判断电量时启动下一任务，也不能开始充电。取得有效监控数据后立即重新评估策略。

### 9.2 空闲且队列为空

1. 电量不低于 15%时，沿用现有逻辑在 LM1 待机，不启动充电。
2. 电量低于 15%且不在 LM1时，申请“因充电暂缓派单”，由 `LineManager` 返回 LM1。
3. 到达 LM1且导航停止后开始充电。
4. 没有新任务时充到 80%后安全收尾。
5. 收尾完成后保持 LM1 待机。

### 9.3 当前任务执行中电量低于 15%

1. 标记“当前任务完成后充电”。
2. 不强行中止当前 AGV 或机械臂动作。
3. 当前任务安全成功或普通失败并完成安全收姿态后，暂停从 FIFO 取出下一任务。
4. 即使已有待执行任务，也保留队列并先返回 LM1。
5. 到达 LM1后开始充电。
6. 系统级故障仍沿用现有 Error 语义，不自动尝试充电。

### 9.4 充电中收到任务

1. 新任务按现有规则进入 FIFO，不去重、不丢失、不重排。
2. 充电期间 `LineManager` 不取出队首任务。
3. 当前电量低于 20%时继续充电。
4. 当前电量达到或超过 20%时立即申请安全收尾。
5. 安全收尾完成后解除派单保持，并执行 FIFO 队首任务。
6. 任务在返回 LM1途中到达时，不取消本次低电量回站。

### 9.5 关闭自动充电

- 没有活动充电时，只撤销自动授权，不影响主调度。
- 正在充电时立即申请安全收尾。
- 收尾成功后，主调度仍在运行且队列非空时恢复派单；队列为空时保持 LM1 待机。
- 自动充电开关关闭后，不再因电量阈值自动开始下一次充电。

### 9.6 主调度 Stop

1. 保留现有 Stop 的急停语义：取消当前设备动作、清空队列并进入 Error。
2. 如果充电控制器处于活动或状态未知，额外申请充电安全收尾。
3. 主调度不等待充电成功才进入 Error；界面必须同时显示主调度错误和充电收尾进度。
4. 充电安全收尾失败时追加充电故障信息，不能覆盖原 Stop 原因。

### 9.7 10%安全边界

1. 15%启动阈值用于在 Roboshop 10%报警前预留余量。
2. 电量小于或等于 10%时立即记录严重报警，禁止开始下一任务。
3. 当前任务已经执行时，不在机械安全动作中强行中止，仍以完成当前安全动作并优先回 LM1为目标。
4. 如果 AGV 已经因低电量报警而不能导航，沿用现有 AGV 故障处理进入 Error并要求人工介入。
5. 上位机不能承诺车辆绝不会到达 10%；它只能通过 15%阈值、禁止下一任务和优先回站降低风险。

## 10. 主调度接入约束

`LineManager` 需要增加一个明确的“派单保持”概念，语义如下：

- 保持期间不调用 `takeNext()`，因此不会改变 FIFO 队列顺序。
- 保持期间允许继续接收缺料任务并更新队列显示。
- 因低电量申请保持后，即使队列非空也允许返回 LM1。
- 返回 LM1途中收到新任务不能取消本次回站。
- 充电安全完成并解除保持后，若队列非空则立即启动队首任务。
- 手动 Stop 和系统 Error 优先于保持，并继续执行现有清队列规则。

这一改动只改变“何时允许取下一任务”，不改变单个任务的任何执行步骤。

## 11. 界面设计

### 11.1 面板位置和紧凑布局

“充电调试”面板插入顺序：

```text
AGV 调试
充电调试
华沿 SDK 调试
```

紧凑主面板包含：

- 自动充电开关。
- “自动充电模式已开启/未开启”醒目提示。
- 自动决策文案。
- AGV 电量和当前位置。
- 15%、20%、80%三个可编辑阈值。
- 不可编辑的 10%安全下限。
- 充电阶段、实际输出电压和电流、推杆状态、故障摘要。
- “参数设置”“查询状态”“开始充电”“停止充电”按钮。

完整输入输出位、事件码、故障详情、最后通信时间和原始报文写入现有日志区，不扩大左侧面板。

### 11.2 参数设置对话框

“参数设置”打开独立模态对话框，包含：

- 充电桩地址、端口和站号。
- 充电电压和充电电流。
- 可选截止电流及启用复选框。
- 可选充电桩最大时间及启用复选框。
- 响应、连接、轮询、启动、监控、停止和推杆动作超时。
- “恢复默认”“取消”“保存”按钮。

只有勾选可选参数后才允许编辑其数值并写入对应寄存器。

### 11.3 查询状态

“查询状态”是纯只读操作，对应 Python 脚本的 `status` 命令，读取：

- 3x01 和 3x02：实际输出电压和电流。
- 3x13：干接点、红外、伸到位、缩到位、无线连接等输入。
- 3x14：等待充电、故障、已充满、工作、风扇、继电器等输出。
- 3x18：停止或完成事件。
- 3x20：故障码。

查询不写参数、不启动充电、不驱动推杆。活动充电会话期间的周期监控已经执行同样读取，因此按钮应禁用，避免插入额外请求。

### 11.4 控件可用性

- 活动充电期间锁定全部参数和阈值。
- 手动开始只在第 6.1 节全部条件满足时可用。
- 手动停止在活动充电期间始终可用。
- 自动模式开启时禁用手动开始。
- 主调度 Start 后禁用手动开始。
- 自动开关开启前弹出一次授权确认。
- 手动开始前弹出一次现场安全确认。
- 停止操作不增加确认弹窗。

## 12. 参数持久化

以下参数保存并在下次启动时恢复：

- 充电桩地址、端口和站号。
- 充电电压、电流。
- 截止电流启用状态和值。
- 充电桩最大时间启用状态和值。
- 全部超时和轮询参数。
- 15%、20%、80%三个电量阈值。

自动充电开关状态绝不持久化。每次程序启动固定为关闭，并显示“自动充电模式未开启”。

加载持久化参数时必须再次执行范围和关系校验。配置损坏或非法时回退到第 4 节默认值并记录日志。

## 13. 程序关闭保护

### 13.1 普通关闭

1. `MainWindow` 拦截关闭事件。
2. 如果充电控制器空闲且没有未知状态，允许正常关闭。
3. 如果正在查询，取消查询并关闭连接后退出。
4. 如果正在充电、推杆可能伸出、有输出或状态未知，拒绝立即关闭并进入“正在安全停止”界面状态。
5. 控制器停止接受新的开始和查询请求，执行停止、确认无输出、缩回、复位和最终查询。
6. 安全完成后由程序重新触发关闭。
7. 充电桩安全完成后尽力关闭 DO0；DO0 关闭失败只记录，不改变第 6 项的退出结论。

### 13.2 收尾失败

- TCP 断线、停止超时、无输出无法确认、缩回失败或复位失败都不能显示“已安全关闭”。
- 界面显示“充电桩状态未知，必须人工检查”，保留故障原因和最后状态。
- 普通关闭继续被阻止。
- 提供需要二次明确确认的“强制退出”入口，防止应用永久无法退出。
- 强制退出提示必须说明：退出程序不代表充电桩已经停止，也不代表推杆已经缩回。
- 强制退出记录操作时间、输出电压、电流、推杆状态、事件码、故障码和失败原因。

## 14. 故障影响范围

### 14.1 手动调试故障

- 显示在充电面板并写入现有日志。
- 主调度保持 Idle，不额外改变其状态。
- 如果故障发生在开始命令之后，仍应尽最大可能进入安全收尾。

### 14.2 自动充电故障

- 通知 `LineManager` 进入 Error。
- 禁止继续派单。
- 保留并显示充电安全收尾状态。
- 进入 Error 后不自动重启充电，必须人工检查并执行现有 Reset Error。
- 自动充电期间丢失 AGV 电量或位置监控时申请安全收尾并进入 Error，不能仅依赖旧电量继续充电。

### 14.3 状态未知

- 状态未知不是空闲，也不是安全完成。
- 禁止新的开始充电和新的主调度任务。
- 重连后先只读查询。
- 只有确认无输出且缩到位，或完成完整安全收尾后，才能离开状态未知。

## 15. 日志要求

复用现有日志区域和日志文件。每条充电通信或状态迁移至少记录：

- 时间。
- 本次充电会话编号。
- 手动或自动来源。
- 目标地址、端口和站号。
- 当前充电阶段。
- 发送和接收十六进制报文。
- CRC 和响应校验结果。
- 解析后的电压、电流、输入、输出、事件和故障。
- 请求耗时、超时和重连次数。
- 开始、停止、缩回、复位的触发来源。
- 自动策略当时的电量、队列数量和阈值。
- 失败原因及是否已经确认无输出和缩到位。

日志必须能够回答：何时开始、写入什么参数、当时是否在 LM1、为何停止、停止是否确认、推杆是否缩回、是否发生强制退出。

## 17. 现场验收

现场写操作必须由人员确认后按以下顺序执行：

1. 只读状态查询稳定，电压、电流、输入、输出、事件和故障解析与充电桩一致。
2. 手动模式确认必须位于 LM1且主调度未启动。
3. 手动完整充电及停止、缩回、复位成功。
4. 自动开关默认关闭，程序重启后仍保持关闭。
5. 主调度启动且空闲时，电量低于 15%返回 LM1并开始充电。
6. 当前任务执行中低于 15%时，完成当前任务后暂停下一任务并充电。
7. 充电中有新任务时，达到 20%安全收尾后执行 FIFO 队首任务。
8. 没有新任务时达到 80%安全收尾并留在 LM1。
9. 关闭自动开关时安全收尾并按队列状态恢复调度。
10. 主调度 Stop 保留现有急停和清队列语义，同时触发充电安全收尾。
11. 充电中关闭程序时，必须完成安全收尾后才能普通退出。
12. 模拟通信断线和非豁免故障，确认不会重复启动，并进入状态未知或 Error。
13. 日志能够完整追溯写入参数、启动、停止、无输出确认、缩回、复位和强制退出。
14. 手动和自动充电均确认 DO0 先置高、充电期间保持高、充电桩安全完成后置低。
15. 启动等待阶段制造一次可恢复 E11，确认 30 秒内只读观察、不重复启动，恢复后
    能继续充电；持续 E11 则在等待到期后安全收尾。

## 18. 完成标准

满足以下全部条件才视为自动充电功能完成：

- 紧凑充电面板和独立参数对话框符合第 11 节。
- 手动与自动模式互斥。
- 自动开关每次启动默认关闭。
- 15%、20%、80%策略和 10%安全边界符合第 9 节。
- 车辆只在 LM1开始充电。
- Python 已验证的通信、故障豁免和五阶段安全收尾得到等价实现。
- 充电桩只有一个通信和控制所有者，不存在并发报文。
- 任务队列在充电等待期间不丢失、不重排。
- 程序关闭不能绕过充电安全收尾。
- 手动和自动充电都必须先确认 DO0 高电平；充电桩安全完成后尽力关闭 DO0。
