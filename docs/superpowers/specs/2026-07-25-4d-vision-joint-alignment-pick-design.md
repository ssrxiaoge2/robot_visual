# 4D 视觉联合对准抓取闭环设计

**日期：** 2026-07-25  
**工程：** `robot_visual` 上位机  
**范围：** C++ 上位机视觉目标确认后的机械臂对准、视觉复核、Z 稳定验证和下探衔接  
**状态：** 待用户审核  

## 1. 背景

当前上位机通过 Python 视觉服务获取目标的 `offset_mm.x`、`offset_mm.y`、`depth_compensated` 和 `angle`。`VisionHttpClient` 使用 C++ 内置的手眼矩阵，将相机坐标系中的 XYZ 转换到工具坐标系；`HuayanScheduler` 再依据现场验证结果对 Y 和 Rz 方向取反，分别下发工具系 X、Y、Rz 相对运动。

现行流程能够通过多轮视觉反馈逐渐逼近目标，但存在以下现场问题：

1. X、Y、Rz 被拆成三个独立动作，每个动作都经历减速、停止、状态轮询和再次启动，机械臂表现为一卡一卡。
2. 每轮修正完成后重新获取视觉结果，最多可循环 15 轮；当前 Python 视觉帧率约为 1.x FPS，流水线延迟约 12 帧、4 至 5 秒，多轮闭环会显著拉长节拍。
3. 运动后的 HTTP 最新结果可能仍对应运动前积压画面，仅凭一次响应或 `frame_id` 增加不足以证明画面已经反映当前机械臂位置。
4. Rz 大角度结果如果叠加旧帧，存在重复旋转风险。现有代码已经增加两帧确认和同一目标最多一次大角度旋转保护，本设计必须保留。
5. 多轮自动修正可能掩盖手眼标定、TCP、位姿组合、视觉延迟或目标关联错误。

本设计在不修改 Python 视觉服务、不改变现有目标选择规则、不升级 6D 的前提下，将生产抓取路径改为有界的两阶段整位姿闭环。

## 2. 已确认的现场前提

1. 当前阶段只保留 4D：X、Y、Z、Rz；Rx、Ry 保持当前工位拍照姿态。
2. 使用 `visionclient.cpp` 中内置的 C++ 手眼标定矩阵，不使用标定目录中的另一套矩阵。
3. 每个工位的拍照位固定不变。
4. 拍照位位于当前工位最高层料箱之上。
5. 仅针对当前任务工位内、通过现有 C++ 目标规则确认和锁定的合法目标，拍照位到目标正上方的运动空间确认安全。
6. 目标为静止料箱，不需要传送带跟随或运动中视觉伺服。
7. Python 暂不增加目标跟踪、最终目标选择或新接口；更换新工控机后再单独评估。
8. C++ 当前的最高层优先、同层选择、工位 ROI、锚点可信范围、目标锁定和 Rz 大角度保护保持原样。
9. 视觉稳定验证最大等待时间固定为 8 秒。超过 8 秒即停止调度，不再延长；未来更换硬件后只允许缩短该时间。
10. 本轮不增加三维运动包络、完整碰撞模型、MoveJ 路径碰撞预测、复杂轨迹规划器等重型能力。

## 3. 设计目标

1. 将首次目标对准从 X、Y、Rz 三次独立相对运动改为一次联合 MoveJ。
2. 首次联合对准后复核同一个锁定目标，不允许自动切换目标。
3. 允许有限次数的联合 MoveL 精修正，次数可配置，默认一次。
4. XY、Rz 最终对准确认与 Z 稳定验证共用一个 4 至 8 秒观察窗口，避免重复叠加视觉等待。
5. 达到精修正次数后仍未收敛，立即停止调度，不自动返回拍照位、不重选目标、不夹紧。
6. 保留现有 Z 深度物理定义、抓取余量、Z 下探硬上限和夹紧流程。
7. 为现场调试提供足够日志，能够区分视觉、手眼转换、位姿组合、机器人运动和视觉延迟问题。

## 4. 非目标

本轮不包含：

- Python 视觉算法修改；
- Python 目标跟踪 ID；
- Python 最终目标选择；
- HTTP 协议字段修改；
- Rx、Ry 估计或 6D 抓取；
- 连续视觉伺服；
- 运动中实时视觉反馈；
- 自动返回拍照位并重新选择目标；
- 超过 8 秒的视觉等待；
- 三维碰撞环境建模；
- MoveJ 整条路径的软件碰撞预测；
- 机械臂逆解质量评分系统；
- 复杂轨迹规划器。

## 5. 现行逻辑与新方案对比

### 5.1 总体对比

| 对比项 | 现行逻辑 | 新方案 |
|---|---|---|
| Python 视觉服务 | 输出相机测得的 XY、箱口深度 Z 和图像平面角度 | 保持不变 |
| 手眼矩阵 | C++ 内置矩阵将相机 XYZ 转换到工具坐标系 | 保持不变 |
| 目标选择 | C++ 负责工位 ROI、最高层、同层选择、锚点锁定 | 保持不变 |
| 首次对准输入 | 工具系 X、Y、Rz 相对修正量 | 同一组工具系修正量 |
| 首次对准方式 | `MoveRelL(X)`、`MoveRelL(Y)`、`MoveRelL(Rz)` 依次执行 | 将工具系修正组合成 Base 绝对预抓取位，一次 `WayPoint MoveJ` |
| 首次对准 Z | 不参与 XY/Rz 微调 | 保持 `ΔZ=0`，不在首次对准中下降 |
| Rx、Ry | 不由视觉修改 | 保持拍照位实际 Rx、Ry |
| 运动次数 | 每轮最多 3 个独立动作，可循环多轮 | 首次 MoveJ 固定一次，精修正 0 至 2 次 |
| 生产闭环上限 | `maxGrabIterations` 默认最多 15 轮 | 新参数控制联合精修次数，范围 0 至 2，默认 1 |
| 视觉复核 | 每轮逐轴运动后返回 `WaitForVision` | 首次联合运动后进入统一稳定验证窗口 |
| 旧帧处理 | 有 `frame_id` 去重，但逐轮等待仍可能读到积压帧 | 机械臂静止后使用 4 至 8 秒窗口和最近真实帧联合判断 |
| XY/Rz 判断 | 每次视觉结果立即决定是否继续逐轴修正 | 在稳定窗口中判断；未收敛时只允许配置次数内的联合精修正 |
| Z 稳定 | XY/Rz 收敛后单独进入 Z 稳定验证 | XY/Rz 最终确认与 Z 稳定共用同一观察窗口 |
| Rz 大角度 | 两帧确认，同一锁定目标最多执行一次 | 完整保留 |
| 修正失败 | 可能回到 `WaitForVision` 继续下一轮，直到达到 15 轮 | 达到联合精修次数仍不收敛，立即停止调度 |
| 自动重试整轮 | 当前多轮闭环本质上会继续尝试 | 不自动重试，不返回拍照位，不重新选目标 |
| Z 下探 | 视觉深度减抓取余量，沿工具 Z 下探 | 保持现有算法和保护 |
| 视觉最大等待 | 当前 Z 稳定窗口最大约 8 秒 | 8 秒继续作为硬上限 |

### 5.2 现行生产时序

```text
到达固定拍照位
→ 获取视觉目标
→ C++ 选择并锁定目标
→ 判断 XY/Rz 是否收敛
→ 未收敛：
   MoveRelL 修正 X
   → 等待完全停止
   → MoveRelL 修正 Y
   → 等待完全停止
   → MoveRelL 修正 Rz
   → 等待完全停止
→ 返回 WaitForVision
→ 等待并重新获取视觉
→ 再次判断 XY/Rz
→ 最多重复 15 轮
→ 收敛后进入 Z 稳定验证
→ Z 稳定后下探
→ 夹紧
```

Z 稳定验证期间如果后续帧重新发现 XY/Rz 失准，现行代码会清空 Z 样本并返回 `WaitForVision`，重新进入上述多轮逐轴视觉对准闭环。

### 5.3 新方案生产时序

```text
到达固定拍照位
→ 读取实际 TCP 位姿和当前 J1～J6
→ 获取视觉目标
→ 使用现有 C++ 规则选择并锁定目标
→ 使用 C++ 内置手眼矩阵得到工具系 X/Y/Z
→ 必要时完成 Rz 大角度两帧确认
→ 计算 Base 绝对预抓取位
→ 一次 WayPoint MoveJ 联合完成 XY/Rz
→ 进入 4～8 秒对准与 Z 稳定验证窗口
→ XY/Rz 收敛且 Z 稳定：
   进入最终 Z 下探
→ XY/Rz 未收敛且尚有精修次数：
   一次 WayPointRel MoveL 联合修正 XY/Rz
   → 重新进入同一稳定验证窗口
→ 达到精修次数仍未收敛：
   停止调度
→ Z 下探完成后夹紧
```

### 5.4 行为变化的核心意义

现行逻辑是“视觉误差驱动的多轮逐轴点动闭环”；新方案是“视觉位姿驱动的一次联合粗对准，加有限次数联合精修正”。

新方案不是取消视觉闭环，而是把无界倾向的多轮逐轴闭环收敛为有明确次数和失败出口的整位姿闭环。

## 6. 坐标与位姿计算

### 6.1 Python 输出语义

Python 当前输出：

```text
offset_mm.x：图像右侧为正的相机 XY 结果
offset_mm.y：图像上方为正的相机 XY 结果
depth_compensated：相机到箱口平面的深度
angle：箱体图像平面角度
```

Python 不处理夹爪长度、机器人安装偏移或 Base 绝对位姿。

### 6.2 C++ 工具系转换

`VisionHttpClient` 使用 C++ 内置的 `T_tool_cam`：

```text
P_tool = T_tool_cam × P_camera
```

得到：

```text
toolX
toolY
toolZ
normalizedRz
```

现场执行方向继续沿用：

```text
ΔX = toolX
ΔY = -toolY
ΔRz = -normalizedRz
```

### 6.3 首次预抓取位计算

机器人调用固定拍照函数并确认停止后，读取：

```text
实际 TCP：X、Y、Z、Rx、Ry、Rz
当前关节：J1～J6
```

首次对准不改变工具 Z、Rx、Ry：

```text
ΔZ = 0
ΔRx = 0
ΔRy = 0
```

目标位姿组合为：

```text
T_base_pregrasp
=
T_base_capture
× 平移(ΔX, ΔY, 0)
× 绕工具 Z 旋转(ΔRz)
```

组合顺序表示先沿拍照时工具坐标系完成 XY 平移，再在目标上方绕 TCP 中心调整 Rz。

禁止使用以下简单相加替代位姿组合：

```text
BaseX += toolX
BaseY += toolY
BaseRz += ΔRz
```

工具轴不一定与 Base 轴完全重合，欧拉角也不应作为普通数值直接叠加。位姿组合优先使用华沿 SDK 已有姿态变换接口，避免自行假设欧拉角顺序。

## 7. 运动分层

### 7.1 首次联合粗对准

使用：

```text
接口：HRIF_WayPoint
运动类型：MoveJ
目标：Base 坐标系完整预抓取位
TCP：当前配置 TCP
UCS：Base
逆解参考：当前 J1～J6
```

选择 MoveJ 的原因：

- 当前工位固定拍照位到当前工位合法目标上方的路径已确认安全；
- 首次 XY 距离和 Rz 角度可能较大；
- MoveJ 更适合大范围位置和姿态联合变化；
- 控制器可统一协调关节，避免长距离笛卡尔直线运动过于费劲。

### 7.2 联合精修正

首次 MoveJ 后如果 XY/Rz 未收敛且仍有允许次数，使用：

```text
接口：HRIF_WayPointRel
运动类型：MoveL
相对模式：叠加值
启用轴：X、Y、Rz
禁用轴：Z、Rx、Ry
输入：toolX、-toolY、-normalizedRz
```

精修使用 MoveL 的原因：

- 此时机械臂已经位于目标上方；
- 残差应明显小于首次修正；
- TCP 路径和姿态变化需要更可控；
- 一条联合命令可以避免 X、Y、Rz 分别启停。

## 8. 视觉复核与稳定验证

### 8.1 统一稳定窗口

首次 MoveJ 或每次联合精修正完成后，进入统一的“对准与深度稳定验证窗口”。

窗口规则：

```text
机械臂必须保持静止
最少观察时间：当前约 4 秒
最大观察时间：8 秒硬上限
按 frame_id 去除重复 HTTP 缓存响应
使用最近 3 个真实不同 frame_id 判断 Z 稳定
```

Python 当前存在约 12 帧、4 至 5 秒流水线延迟。因此不能把“收到一个更大的 `frame_id`”直接解释为画面已经反映当前机械臂位置。最少观察时间用于刷新流水线；达到最少时间后，再使用最近真实帧进行判断。

未来更换新工控机后，可以基于实测缩短最少和最大等待时间，但最大值不允许超过 8 秒。

### 8.2 窗口判断

窗口同时检查：

- 目标仍为首次锁定目标；
- XY 是否进入运行参数配置的收敛阈值；
- Rz 是否进入运行参数配置的收敛阈值；
- 最近 3 帧 Z 极差是否满足现有稳定规则。

结果：

```text
XY/Rz 收敛且 Z 稳定
→ 进入最终 Z 下探

XY/Rz 未收敛且精修次数未达到配置值
→ 执行一次联合精修正
→ 重新进入稳定窗口

XY/Rz 未收敛且精修次数已用完
→ 停止调度

目标丢失、目标被可信规则拒绝、Z 不稳定或等待超过 8 秒
→ 停止调度
```

### 8.3 Rz 大角度保护

完整保留现有行为：

- `abs(Rz)` 达到大角度阈值时，第一帧只记录，不运动；
- 下一真实帧方向一致、幅值差在容差内，才允许执行；
- 同一锁定目标周期内最多执行一次大角度 Rz；
- 后续旧帧或角度歧义不得导致累计旋转。

## 9. 修正次数配置

新增：

```text
最大联合精修正次数 maxFineCorrectionCount
范围：0～2
默认：1
```

语义：

| 配置值 | 自动运动上限 |
|---:|---|
| 0 | 仅一次首次 MoveJ，不允许精修 |
| 1 | 一次首次 MoveJ，加一次联合 MoveL 精修 |
| 2 | 一次首次 MoveJ，加最多两次联合 MoveL 精修 |

首次 MoveJ 固定只能执行一次，不计入该参数。

删除旧 `maxGrabIterations=15` 配置及其阶段一逐轴闭环实现，因为旧参数表示当前多轮逐轴视觉对准的轮数，新参数表示首次联合对准后的整位姿精修次数。两者语义不同，保留旧字段或旧执行分支容易造成现场误配置，甚至让旧值 15 意外进入新生产流程。

设置界面不增加第二行次数配置。现有“最大矫正次数”所在位置直接替换为“联合精修正次数”，绑定 `maxFineCorrectionCount`，范围 0～2、默认 1。旧 INI 键 `vision/maxGrabIterations` 不再读取，并在下一次保存设置时移除。

本次删除范围仅限旧阶段一 15 轮 X/Y/Rz 逐轴视觉对准循环及其专用配置、状态和辅助函数。目标选择、手眼转换、锚点锁定、Rz 大角度保护、深度处理、搜索下移、Z 稳定验证、最终下探、扫码和夹爪等其他逻辑均不得借此重构或改变行为。

初版不新增“复核专用 XY/Rz 修正上限”，继续复用：

- 当前 XY 收敛阈值；
- 当前 Rz 收敛阈值；
- 当前单次 XY 调整安全上限；
- 当前 Rz 归一化与大角度保护；
- 最大联合精修次数。

现有设置界面已经具备 XY 和 Rz 独立收敛阈值，但当前调度代码的 Rz 判断仍使用固定 `1°` 常量。新流程必须让设置中的 Rz 收敛阈值真正参与判断。

## 10. 状态机

建议明确区分以下生产状态：

```text
移动到固定拍照位
等待初始视觉
等待 Rz 大角度确认
计算预抓取位
首次联合 MoveJ
对准与 Z 稳定验证
联合精修正
最终稳定验证
Z 下探
夹紧
```

关键状态变量：

```text
首次联合对准是否已执行
已执行联合精修正次数
本轮允许的最大联合精修正次数
稳定窗口起始 frame_id
稳定窗口已观察真实帧
锁定目标锚点
本轮大角度 Rz 已执行次数
```

新任务开始、停止、复位、阶段失败和任务完成时，必须清空本轮联合对准、精修次数、稳定窗口和 Rz 大角度状态。

## 11. 失败处理

以下任一情况发生时停止调度：

- 目标不属于当前任务工位；
- 目标被现有可信规则拒绝；
- 锚点锁定目标丢失；
- 位姿组合失败；
- SDK 拒绝 MoveJ 或 MoveL；
- 机器人报错、暂停、急停或运动超时；
- 稳定窗口超过 8 秒；
- Z 无法稳定；
- 达到最大联合精修次数后 XY/Rz 仍未收敛；
- Z 计划下探量超过现有硬上限。

停止后：

- 不再下发运动命令；
- 不执行 Z 下探；
- 不闭合夹爪；
- 不自动切换目标；
- 不自动返回拍照位；
- 不自动重新开始整轮抓取；
- 停止所有等待定时器和未派发命令；
- 保持机械臂停在当前安全高度；
- 输出明确失败阶段、视觉帧、目标锚点、修正次数和残差。

复杂的机器人三维包络、路径碰撞预测和轨迹规划只记入远期安全增强，不进入初版。

## 12. 模块职责

### 12.1 VisionHttpClient

保持：

- HTTP 请求与解析；
- C++ 内置手眼矩阵；
- 目标候选过滤与现有选择；
- 工位 ROI；
- 最高层和同层规则；
- 锚点锁定；
- Rz 归一化；
- 工具系结果输出。

### 12.2 HuayanScheduler

负责：

- 读取拍照位实际 TCP 和 J1～J6；
- 组合 Base 绝对预抓取位；
- 首次联合 MoveJ；
- 联合精修 MoveL；
- 稳定窗口；
- 精修次数；
- 收敛、失败和下探状态转移；
- 日志和停止处理。

### 12.3 运行设置

继续使用现有视觉、Rz、Z 和安全参数；新增最大联合精修正次数，范围 0 至 2，默认 1。

### 12.4 机器人命令封装

新增两种清晰的命令语义：

```text
绝对预抓取 MoveJ：
输入 Base 完整位姿和当前参考关节角

工具系联合精修 MoveL：
输入 ΔX、ΔY、ΔRz
```

两者必须继续进入现有统一命令前状态检查、SDK 下发、运动轮询、到位、超时和错误处理，不得绕过现有命令队列直接调用 SDK。

## 13. 日志要求

- 稳定窗口实际耗时；

- 当前精修次数和配置上限；

## 14. 验证策略

### 14.1 自动验证

覆盖：

- 工具系平移与 Rz 组合顺序；
- Rx、Ry 保持；
- 首次对准 `ΔZ=0`；
- Y 和 Rz 取反；
- 当前关节角作为 MoveJ 逆解参考；
- 精修次数 0、1、2 的状态转移；
- 达到次数后不再下发运动；
- 8 秒超时停止；
- 旧 `maxGrabIterations=15` 字段、设置项和阶段一逐轴循环已删除；
- 配置的 Rz 收敛阈值真正生效；
- 大角度 Rz 最多执行一次；
- 停止、复位、新任务时状态清零；
- 目标丢失、SDK 错误和 Z 不稳定时禁止下探。

### 14.2 真机上线顺序

第一步，只计算不运动：

```text
到拍照位
→ 识别目标
→ 记录预抓取位
→ 不运动、不下探
```

第二步，低速验证单方向：

```text
夹爪打开
关闭自动 Z 下探
降低速度倍率
分别验证 X、Y、Rz 方向
```

第三步，验证联合 MoveJ：

```text
选择当前工位合法目标
→ 联合执行 XY/Rz
→ 不下探
→ 人工确认终点和路径
```

第四步，启用稳定窗口和联合精修：

```text
仍不下探
→ 验证 4～8 秒窗口
→ 验证精修次数 0、1、2
→ 验证达到次数后停止
```

第五步，恢复现有 Z 稳定、下探和夹紧流程。

## 15. 初版验收标准

1. 选中的目标与现有版本一致。
2. 首次对准只下发一条 MoveJ。
3. 精修正次数不超过配置值。
4. 不再出现 X、Y、Rz 分别启停。
5. 新生产路径不再受最多 15 轮逐轴闭环控制。
6. Rz 不因旧帧重复累计旋转。
7. 视觉超过 8 秒不稳定时停止。
8. 达到精修次数仍不收敛时停止。
9. Z 下探只在目标锁定、XY/Rz 收敛和 Z 稳定后发生。
10. 停止后不自动回拍照位、不换目标、不夹紧。
11. 现有 Z 深度、抓取余量和下探硬保护行为保持一致。
