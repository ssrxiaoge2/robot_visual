# 阶段一 Z 深度跨帧稳定验证设计

## 背景

现场日志显示，机械臂完成 X、Y、Rz 闭环对准并保持静止时，同一料箱的视觉工具系 Z 仍可能在相邻推理结果之间波动二十毫米以上。当前上位机在首次满足 X、Y、Rz 阈值后，直接采用该帧 Z 计算下探量，因此某一帧的深度异常会直接变成夹爪高度误差。

本次改动只解决“对准后采用单帧 Z”这一问题，不改变视觉算法输出字段、手眼矩阵、`grabZClearance`、X/Y/Rz 运动方向以及已有最多 15 次闭环矫正。

## 目标

1. X、Y、Rz 对准后，机械臂保持静止，不立即执行 Z 下探。
2. 使用算法响应中已有的 `frame_id` 和 `timestamp` 识别真实新帧，重复读取的缓存响应不得计入样本。
3. 机械臂静止至少 4 秒后，使用最近 3 个真实新帧的 Z 极差判断稳定性；最大值与最小值之差不超过 5 毫米时，采用 3 帧中位数作为最终工具系 Z。
4. 最多等待 8 秒；仍未出现稳定的连续 3 个真实新帧时，阶段一失败并禁止 Z 下探。
5. 稳定验证期间若 X、Y 或 Rz 再次超出原有对准阈值，清空 Z 样本并恢复原有闭环矫正。
6. 稳定验证期间未检测到目标、目标被可信规则拒绝或视觉请求报错时，禁止进入普通“无目标搜索下移”。

## 状态机设计

在 `WaitForVision` 与 `DescendZ` 之间增加 `ValidateStableZ` 状态。

```text
WaitForVision
  ├─ X/Y/Rz 未对准 → MoveToGrab → WaitForVision
  └─ X/Y/Rz 已对准 → 清空样本 → ValidateStableZ

ValidateStableZ
  ├─ X/Y/Rz 失准 → 清空样本 → 按原逻辑 MoveToGrab
  ├─ frame_id 未变化 → 缓存重复响应，不计数，100ms 后重查
  ├─ frame_id 递增但真实时间不足 4 秒 → 保留最近 3 帧窗口并继续请求
  ├─ 已静止至少 4 秒且最近 3 个真实帧极差 ≤ 5mm → 中位数写入 m_grabOffset.z → DescendZ
  ├─ 最近 3 帧不稳定且真实时间不足 8 秒 → 滑动窗口并请求下一帧
  └─ 已等待 8 秒仍不稳定 → 阶段失败，不下探
```

进入 `ValidateStableZ` 后的结果必须是对准完成之后重新请求的结果，触发对准的那一帧不计入 3 帧样本。这样可以明确满足“上位机等待多帧再取值”，也能减少运动刚停止时旧帧或过渡帧的影响。

## 采样与计算

- 最少静止时间：4 秒，不再依赖容易变化的 FPS。
- 稳定计算窗口：最近 3 帧。
- 最大等待时间：8 秒。
- 稳定极差：5 毫米。
- 缓存轮询间隔：100 毫秒。`frame_id` 没有递增时不计入样本，只做短间隔重查。
- 计算方式：对最近 3 个 Z 排序，取中间值。

使用中位数是为了在 3 帧中有一帧轻微偏离时，避免均值被异常值拉动。极差条件仍保证三帧整体足够接近。

Python 服务的 `/inference` 返回后台线程维护的最新缓存结果，请求次数不等于新帧数量。当前算法已经输出 `frame_id` 和 `timestamp`，上位机必须使用它们去重。按真实 4 秒控制后，2 FPS 时约采集 8 帧，3 FPS 时约采集 12 帧，不需要随现场帧率修改常量。

## 安全与异常处理

- `ValidateStableZ` 仅发起视觉请求，不下发机械臂运动指令。
- 只有稳定窗口通过后才能进入 `DescendZ`。
- 验证失败使用现有统一阶段错误出口，停止当前阶段。
- 验证期间的“无目标”不能复用 `onVisionNoObject()` 的搜索下移逻辑。
- 现有 Z 下探硬上限、`grabZClearance` 计算和到位超时保持不变。
- 每次开始阶段一、停止阶段或退出失败路径时清空稳定样本，避免跨任务复用旧值。

## 现场日志

新增日志应包含：

- 开始 Z 稳定验证；
- 每帧序号、当前 Z、最近窗口及极差；
- X/Y/Rz 失准并恢复闭环；
- 验证通过后的中位数；
- 8 秒仍不稳定的失败原因；
- 验证期间无目标时明确说明“拒绝搜索下移”。

这些字段用于现场判断问题来自视觉深度波动还是后续 TCP/夹爪补偿，不改变上位机和算法之间的原始字段协议。

## 本次不包含

- 不修改 Python 视觉算法。
- 不增加 Rx、Ry 输出或机械臂动作。
- 不修改手眼矩阵和 TCP 标定。
- 不调整夹爪 Z 补偿 `grabZClearance`。
- 不改变现有 X、Y、Rz 闭环最大迭代次数。
