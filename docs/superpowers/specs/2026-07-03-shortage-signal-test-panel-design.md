# 缺料信号源测试面板独立化设计

**日期：** 2026-07-03  
**状态：** 已确认，待实施  
**参考来源：** `2026-06-25-12-station-continuous-replenishment-design.md` 第 19 节、同名实施计划任务 17–23、`xiancahngxitong/缺料信号.pdf` 及 2026-07-03 现场澄清。  
**替代关系：** 本文只纠正“缺料信号源”测试面板。原文档保持历史原貌；涉及本面板的冲突要求以本文为准。

## 1. 目标与边界

“缺料信号源”面板是现场 MES/PLC 通信及缺料计算的独立测试工具，不是主调度的缺料来源选择器。

本项目负责：

- 读取并展示 MES、PLC 数据；
- 使用与生产调度相同的纯计算规则验证 12 工位缺料判定；
- 显示每个工位为何缺料、未缺料或无法计算；
- 保证测试结果绝不进入 `LineManager`、FIFO 或硬件主调度。

本项目不负责：

- “模拟缺料 / 现场缺料”切换；
- 现场缺料授权、自动派单和任务完成反馈；
- 生产状态持久化；
- 修改原 12 工位调度流程。

## 2. 已确认事实

- MES 地址以现场实测为准：`http://192.168.115.228:5084/api/MesData/day`。
- PLC 基址仍为 `http://192.168.115.228:5084/api/PlcData/GetLBitRegister`。
- `actualQty` 是累计产品数，每晚 20:00 清零。
- 12 个工位共同完成一个产品；每生产一个产品，每个工位分别消耗本工位对应数量，不在 12 个工位间分摊。
- `L71/L72/L73` 分别表示产品 88/88R/92；三者必须恰好一个为真。
- `L68/L69/L1998` 表示生产方式；三者必须恰好一个为真。当前方式策略为 L68/L69 每个工位单件消耗 2，L1998 每个工位单件消耗 1。
- `xiancahngxitong/安全库存.xlsx` 已存在并包含 sheet1 及 88、88R、92 三个产品表；当前 `shortageconfig.h` 为 0 是任务 17 未完成 Excel 转录造成的实现缺陷。实施时必须按工位/品号映射固化每箱数量、用量和安全库存，sheet2 空值按共同主品号回退 sheet1。

## 3. 架构与隔离

```text
CustomSysScheduler（HTTP/JSON）
        |
        v
ShortageTestSession（测试轮询、独立临时状态）
        |
        v
ShortageCalculator（纯计算规则）
        |
        v
MainWindow 测试面板（只读展示）
```

`ShortageTestSession` 必须是测试专用对象。它不得暴露 `shortageRequested` 一类可直接接入主调度的信号，也不得调用 `LineManager::reportShortage()`。测试状态只存在于当前测试会话：点击开始时初始化，点击停止或程序退出后丢弃。

测试通道与生产通道不得同时轮询。未来真实缺料调度启用时，测试会话自动停止且“开始检测”不可用；本项目先预留明确的占用状态接口，不在本项目内实现生产调度。

## 4. 测试计算模型

每个工位维护测试用 `estimatedAvailable`：

```text
首次初始化：estimatedAvailable = safetyStock + boxQuantity
本轮产量增量：delta = currentActualQty - previousActualQty
本轮工位消耗：consumption = delta * usagePerProduct
预计可用物料：estimatedAvailable -= consumption
estimatedAvailable <= safetyStock：计算结果为“缺料”
```

该模型只用于验证计算，不产生任务，不模拟倒料完成，也不增加一箱数量。测试重新开始时重新初始化。

边界规则：

- 首个有效样本只建立 MES 基线，不扣减库存。
- 产品变化经连续两个有效轮次确认后，清空旧产品测试状态，并按新产品重新初始化。
- 仅方式变化经连续两个有效轮次确认后，保留当前预计可用物料，以确认时 `actualQty` 建立新方式基线。
- 产品位或方式位不唯一时，本轮无效，不使用优先级猜测。
- 20:00 附近 `actualQty` 回退识别为日计数清零，保留 12 工位预计可用物料，并以新值继续建立增量。
- 非换班时段回退、溢出、超时或解析错误均停止本轮计算并显示原因。
- 配置缺失时仍允许通信测试，但不扣减、不判定缺料。

## 5. UI 设计

面板标题改为“缺料信号计算测试”。

保留：

- “开始检测”“停止检测”；
- 连接/轮询状态；
- `actualQty`、产品、方式、六个 L 位；
- 当前产量增量和当前单件用量。

删除：

- “模拟缺料 / 现场系统”单选按钮；
- 任何现场派单授权控件；
- URL 文本显示；
- 品号等不利于现场快速判断的冗余列。

12 工位表固定为五列：

| 工位 | 预计可用 | 安全线 | 箱量 | 状态 |
|---|---:|---:|---:|---|

状态文本必须为可定位原因，例如“等待首轮基线”“正常”“缺料（仅测试）”“配置缺失”“产品信号不唯一”“通信中断”。表格允许出现负数，以暴露倒料未接入时的持续欠料，不得截断为 0。

## 6. 错误处理

- 任一轮四个请求未全部成功，不混用跨轮响应。
- 迟到响应必须通过会话代号和轮次号丢弃。
- 停止检测后所有迟到响应无效。
- 错误只影响测试面板，不停止或清理主调度。
- 测试面板日志统一使用 `[ShortageTest]` 前缀，明确“仅测试、不派单”。

## 7. 验收与测试

自动测试必须覆盖：

- `.228` MES 默认地址且不存在 `.229` 旧值；
- 首轮基线、正常扣减、刚好到安全线、负库存展示；
- 12 工位分别扣减而非分摊总消耗；
- 配置缺失时不判定缺料；
- 两轮确认换型/换方式、L 位不唯一；
- 20:00 清零与异常回退；
- stop 后迟到响应、跨轮响应；
- 测试代码不存在 `reportShortage`、`TaskSource::CustomerSystem` 或 FIFO 接线；
- UI 不再包含来源切换，表格恰为五列。

现场人工验收顺序：

1. 开始检测并核对 MES `.228` 连接正常；
2. 核对产品、方式和 L 位；
3. 使用可控配置验证 12 工位预计可用物料分别下降；
4. 验证达到安全线仅显示“缺料（仅测试）”，FIFO 无新增；
5. 停止检测并确认状态不再变化。

## 8. 强制代码注释

实现必须详尽说明：测试会话不派单、12 工位逐工位消耗、首次基线、产品/方式稳定确认、20:00 清零、配置缺失、负库存展示、会话/轮次防迟到响应，以及测试状态不持久化。注释不得把“开始检测”描述为“启用现场缺料”。

## 9. 完成标准

- 测试面板可以独立验证通信和计算；
- 与主调度不存在派单连接；
- UI 能明确解释每个工位为何未触发；
- 所有自动测试通过，现场检查不产生任何 FIFO 任务。
