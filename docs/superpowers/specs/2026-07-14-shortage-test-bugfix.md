# 缺料信号现场实测问题修复说明

## 1. 修复目的

本次修复针对 `2026-07-13-live-shortage-ledger` 实现后的现场实测问题。目标是在“缺料配置与完整逻辑测试”窗口中完成缺料配置、手工输入、现场采样、补料计划、任务事件、失败保护、持久化恢复和正式环境隔离验证，为后续接入主流程和现场调试提供清晰、可重复的验证入口。

所有界面说明、运行日志、验证步骤和通过条件使用中文。后续实施 plan 中的代码片段以及实际代码，对新增或修改的枚举及枚举值、结构体及字段、函数接口及参数和返回值、成员变量所有权、关键状态分支和跨模块接线增加中文注释。

## 2. 现场问题原文

1. 目前验证项需要列举需要验证的项目，并为每一项提供操作步骤和验证通过标准。
2. 手工源执行“现场清零建账—启动现场采样”时没有 `actualQty` 设置，无法验证；界面宣称不依赖真实 MES/PLC，实际却启动了真实采样。
3. 现场源执行“现场清零建账—启动现场采样”后，首次启动理论上应该产生补料，但界面没有显示补料。
4. 当前 UI 测试按钮较多、操作不便、逻辑不完整，导致很多缺料场景尚未测试到位。
5. 当前测试窗口不能最小化和最大化，不方便在测试窗口与主页面之间切换；新增验证窗口也必须支持最小化、最大化和切换。

## 3. 根因调查结论

### 3.1 手工源只是外观控件

当前“手工源/现场源”单选框只设置互斥显示，没有连接输入源切换逻辑。页面没有产品、模式、`actualQty` 编辑控件，也没有“提交手工样本”动作。因此，测试控制器虽然提供 `applyManualSample(...)`，UI 无法调用它。

### 3.2 手工源会误启动真实采样

当前“启动现场采样”按钮直接连接 `ShortageTestController::startFieldSampling()`，没有检查所选输入源。选择“手工源”后点击该按钮，仍会启动共享的真实 `ShortageSampleCoordinator`，访问真实 MES/PLC。

### 3.3 首次补料已经生成，但页面没有展示和推进

现场遗留的 `test-events.jsonl` 证明：0 建账后，首次稳定样本 `actualQty=2352` 已使核心 Engine 创建 1 号自动补料单，状态为 `AwaitingDispatch`，活动工位为 1，12 个低位工位进入等待顺序。

现有页面只在打开窗口时复制一次快照，没有订阅 `snapshotChanged` 更新摘要和 12 工位表；表格列也不足以显示最低/最高、用量、计划和补料单状态。因此核心已经产生补料意图，但操作员看到的仍是初始静态页面，形成“没有补”的现场判断。

独立测试不会进入主 FIFO、不会控制硬件，这是正确的隔离边界。测试中的“补料”必须通过测试任务事实推进，并明确显示“等待派单、运行、已倒料、终态”，不能把未控制真实硬件误解为没有执行核心逻辑。

### 3.4 原测试页没有完成原设计契约

`2026-07-13-live-shortage-ledger-design.md` 要求测试页支持手工样本、现场样本、状态保存/重载/清空、全部任务事实和实时状态。当前实现只有八个事件按钮，缺少手工输入、状态操作、倒料后失败、重复倒料、重启，以及快照驱动的动态显示。

### 3.5 窗口虽然非模态，但缺少完整窗口按钮和唯一实例管理

当前窗口使用 `show()`，不会像 `exec()` 一样阻塞主页面，但 `QDialog` 默认标题栏没有明确启用最小化和最大化按钮；主窗口也没有保存唯一窗口指针，重复点击入口会创建多个窗口。现场因此难以稳定地最小化、最大化并在主页面之间切换。

## 4. 修复范围

- 修复现有“完整逻辑测试”页的手工源、现场源、实时快照、补料状态和全部测试事件。
- 新增独立文件实现的“缺料验证控制台”，通过第三个 Tab 的入口打开。
- 新验证控制台不混入既有测试 UI，不复制库存或补料算法。
- 第三个 Tab 由单一可见性开关控制；现场验证结束后可以隐藏入口，不影响参数配置页和原完整逻辑测试页。
- 现有测试窗口和新验证控制台均支持最小化、最大化、关闭和与主窗口互相切换。
- 补齐 C++/Qt Test 自动测试以及现场验证步骤，不使用自动测试冒充现场实机通过。

## 5. 不在本次范围

- 不让独立测试任务进入主 FIFO。
- 不在独立测试中控制 AGV、机械臂、扫码或真实倒料。
- 不改变 `actualQty` 清零算法、补料非抢占算法和主 FIFO 追加规则。
- 不把测试状态复制到正式状态。
- 不修改真实 MES/PLC 协议地址和寄存器映射。
