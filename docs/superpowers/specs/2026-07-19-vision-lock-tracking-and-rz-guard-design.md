# 视觉锁定连续跟踪与 Rz 大角度保护设计

**日期：** 2026-07-19
**状态：** 已实施并完成自动化验证，2026-07-19 现场复测后追加矩形锚点可信范围修正
**关联日志：** `log/2026-07-19+log.txt`、`log/2026-07-19+log (1).txt`
**关联现场图片/视频：** `log/` 目录下 2026-07-19 现场图片与 `781586172.mp4`
**关联上一版设计：** `docs/superpowers/specs/2026-07-18-anchor-vision-target-trust-design.md`

## 1. 背景

2026-07-18 现场验证后，固定拍照锚点与目标锁定方案整体方向有效：底层目标可以被选择，也不会再轻易选择到旁边工位。但 2026-07-19 现场继续测试时发现三个新问题：

1. `10:58` 到 `10:59` 左右，同层两个目标之间反复切换，机械臂在两个箱子之间摇摆，最终视觉闭环迭代超时。
2. `11:15` 左右，视觉持续返回 `Rz=90°`，机械臂多次执行 `Rz -90°`，现场表现为累计旋转接近 `360°`，最后 SDK 返回 `49601（Target orientation exceeded cartesian safety space）`。
3. `11:08` 左右，阶段一已经视觉对准并开始 `Z 下探 1034.8mm`，约 31 秒后触发“机器人未在预期时间内完成动作”。当前默认命令到位等待超时为 30 秒，对长距离 Z 下探偏短。

本次修正不推翻 7.18 的“固定拍照锚点”思路，而是在现场日志暴露出的边界处做收紧：

- 初始目标选择继续使用“最高层 + 固定侧 Y”来决定本轮抓左侧还是右侧。
- 一旦目标已锁定，闭环阶段不再使用固定侧 Y 重新抢目标，而是只按上一帧锁定目标的 `lockdist` 最近原则连续跟踪。
- Rz 大角度继续保留“两帧确认”，但新增同一锁定目标周期内的大角度累计执行次数保护。
- Z 下探使用单独到位等待超时，避免 1 米级下探被 30 秒默认超时误杀。

2026-07-19 下午继续复测后，Rz 重复旋转和 Z 下探超时暂未复现，但发现新的目标归属边界：旁边或临近堆放的高箱可能进入旧的圆形锚点可信范围。旧规则使用 `sqrt(anchorX² + anchorY²) <= 450mm`，只要斜向直线距离小于半径，高箱就会参与最高层竞争。现场工位、推车和料箱实际更接近矩形边界，因此本文件追加修正：锚点可信范围从圆形半径改为 X/Y 独立矩形范围。

## 2. 现场证据

### 2.1 同层两个目标摇摆

`log/2026-07-19+log.txt` 中 `10:58:22` 关键日志：

```text
#0 ... anchor=(52.7,-2.3) ... lockdist=233.7 可信
#1 ... anchor=(9.1,-260.8) ... lockdist=28.5 可信
选中=#0 原因=锁定同层固定侧
```

这说明闭环阶段已经有上一帧锁定目标时，代码仍然把“同层固定侧”应用到锁定跟踪中，导致选中了离锁定目标更远的候选。现场表现就是机械臂先向一个箱子移动，下一帧又被固定侧规则拉到另一个箱子。

### 2.2 Rz=90° 累计旋转

`11:15` 附近日志显示：

- `11:15:07`：`Rz 大角度跳变已连续确认 Rz=90.0，允许执行旋转`，随后执行 `Rz 负向 90.0`。
- `11:15:31`：再次确认 `Rz=90.0`，再次执行 `Rz 负向 90.0`。
- `11:15:52`：第三次确认 `Rz=90.0`，再次准备执行 `Rz 负向 90.0`，随后 SDK 返回 `49601`。

现有参数：

```cpp
static constexpr double kLargeRzJumpThreshold = 80.0;
static constexpr double kLargeRzJumpDeltaTolerance = 15.0;
```

它们只限制“单次大角度是否需要连续两帧确认”，不能限制“同一目标周期内累计执行了几次大角度旋转”。如果视觉帧率较低、视觉结果滞后、或者视觉算法连续返回旧帧，代码会把每两帧 `90°` 当成一次新的确认，从而重复旋转。

### 2.3 Z 下探默认超时偏短

`11:07:44` 日志显示：

```text
视觉对准完成（X=-0.5 Y=-0.6 Rz=0.0），开始 Z 下探
Z 下探 1034.8mm
```

`11:08:15` 触发：

```text
步骤超时，机器人未在预期时间内完成动作
```

从下发到超时约 31 秒，符合当前 `PendingCommand::timeoutMs = 30000` 的默认值。该问题不一定是机器人异常，更可能是长距离 Z 下探动作本身超过默认等待时间。

### 2.4 旧圆形锚点可信范围会放过斜向旁站高箱

`log/2026-07-19+log (1).txt` 与现场图片显示：当前工位附近如果额外堆放了其他箱子，且该箱子高度更高，旧圆形锚点范围可能把它当作可信候选。典型问题不是箱子离拍照点特别近，而是它沿斜向进入半径范围：

```text
旧规则：sqrt(anchorX² + anchorY²) <= VISION_ANCHOR_MAX_TRUST_XY_MM
```

例如 `anchorX=320mm`、`anchorY=120mm` 时，直线距离约 `342mm`，小于旧 `450mm` 半径，因此会被视为可信；但从现场业务看，X 方向已经偏出本工位宽边，更像旁边工位或异常堆放目标。

因此本次追加修正不采用地面划线硬 ROI，也不引入固定槽位，而是在现有锁定策略前增加“拍照锚点 X/Y 矩形可信范围”：

```text
abs(anchorX) <= VISION_ANCHOR_MAX_TRUST_X_MM
且
abs(anchorY) <= VISION_ANCHOR_MAX_TRUST_Y_MM
```

这条规则只负责把明显偏出当前工位外圈的候选挡在目标竞争外，后续仍沿用“最高层优先、锁定后连续跟踪”的已验证逻辑。

## 3. 目标

1. 修复同层两个目标在闭环阶段左右摇摆的问题。
2. 保留现场已验证有效的初始目标选择策略：最高层优先，同层按固定侧 Y 选定本轮目标。
3. 锁定后只跟踪上一帧锁定目标附近候选，选 `lockdist` 最小者，禁止再次使用固定侧 Y 抢目标。
4. 普通视觉抖动或短暂漏检不立即停机，继续沿用连续丢失帧保护。
5. 防止 `Rz=90°` 因视觉旧帧、帧率滞后或角度歧义被重复执行，避免累计旋转接近 `360°`。
6. 将阶段一 Z 下探命令到位等待超时单独加大，不放大全局默认超时。
7. 日志必须能说明本次选择/拒绝的原因，方便现场继续追溯。

## 4. 非目标

- 不修改视觉服务接口、模型、推理脚本或返回 JSON 结构。
- 不重新标定手眼矩阵。
- 不改变 `Func_captureN`、`Func_jiajin` 等示教器函数。
- 不改变 7.18 已验证的初始目标选择业务策略。
- 不把所有机械臂动作超时统一放大；只处理阶段一 Z 下探。
- 不尝试在本轮根治华研 SDK 的 `49601` 内部判定；本轮只减少上位机重复 Rz 和错误目标造成的触发概率。

## 5. 修正后的目标选择规则

### 5.1 初始锁定帧

当 `TargetSelectionContext::lockEnabled == true` 且 `hasPreviousAnchorTarget == false` 时，说明本轮取料还没有锁定目标。

选择规则保持 7.18 现场验证版本：

1. 解析全部合法视觉候选。
2. 使用固定拍照锚点计算候选 `anchorX`、`anchorY` 和诊断用 `anchorDistance`。
3. 只保留锚点 X/Y 矩形可信范围内的候选，即 `abs(anchorX) <= VISION_ANCHOR_MAX_TRUST_X_MM` 且 `abs(anchorY) <= VISION_ANCHOR_MAX_TRUST_Y_MM`。
4. 优先选择最高层。
5. 如果最高层同层有多个目标，使用固定侧规则定边，当前默认是 `raw Y` 最小。
6. 选中后记录 `lockAnchorX`、`lockAnchorY`，进入闭环锁定状态。

这一阶段中，`Y` 的作用是“开局定边”：当当前工位同层有两个箱子时，用固定规则决定本轮抓哪一个，避免初始目标随机。

默认矩形参数：

```cpp
#define VISION_ANCHOR_MAX_TRUST_X_MM 300.0
#define VISION_ANCHOR_MAX_TRUST_Y_MM 450.0
```

这两个值按当前现场“推车宽边较窄、长边较长”的理解设置，属于现场可调参数。如果现场确认机械臂工具系 X/Y 与推车长宽方向相反，优先交换或调整这两个宏，不需要改目标选择算法。

### 5.2 闭环跟踪帧

当 `TargetSelectionContext::lockEnabled == true` 且 `hasPreviousAnchorTarget == true` 时，说明机械臂已经开始朝某个箱子修正。

新规则：

1. 解析全部合法视觉候选。
2. 计算每个候选相对上一帧锁定目标的 `lockDistance`。
3. 只保留同时满足以下条件的候选：
   - `trusted == true`
   - `lockDistance <= lockTrackRadius`
4. 如果没有候选，增加连续丢失帧数：
   - 未达到 `maxLockMissingFrames`：返回 `LockTargetMissing`，不切换目标。
   - 达到 `maxLockMissingFrames`：返回 `LockTargetLost`，阶段一失败。
5. 如果存在候选，直接选择 `lockDistance` 最小者。
6. 不再调用 `chooseFixedSideCandidate()`，不再使用固定侧 Y。
7. 选中后清零连续丢失帧数，并用本帧候选的 `anchorX`、`anchorY` 更新锁定目标位置。

这一阶段中，`Y` 不再参与选择。闭环跟踪的本质是“继续抓刚才锁定的那个”，所以应以 `lockdist` 连续性为准。

### 5.3 为什么不增加“两目标歧义即停”

现场业务前提是：在当前工位可信范围内，同层两个目标都属于可抓取目标。若两个目标都在范围内，且都接近上一帧锁定位置，直接选择 `lockdist` 更小者更符合产线需求。

因此本轮不做“两个目标距离接近就停机”。真正需要拒绝的是：

- 当前工位可信范围内没有锁定目标附近候选。
- 连续多帧找不到锁定目标。
- 候选明显离上一帧锁定目标过远。

这样可以避免限制太死导致产线频繁停摆，同时不会自动切换到旁边工位。

## 6. Rz 大角度保护规则

### 6.1 现有保护保留

现有 `kLargeRzJumpThreshold` 和 `kLargeRzJumpDeltaTolerance` 继续保留：

- `abs(Rz) >= 80°` 时，第一帧不执行 Rz，等待下一帧确认。
- 下一帧方向相同且幅值差小于等于 `15°` 时，认为大角度连续确认，可以执行一次。

这层保护用于过滤单帧 Rz 跳变。

### 6.2 新增累计执行次数保护

新增同一阶段一目标锁定周期内的大角度 Rz 执行计数：

- 只有实际准备执行 `abs(effectiveRz) >= kLargeRzJumpThreshold` 的 Rz 微调时，才增加计数。
- 普通小角度 Rz 不计入该计数。
- 建议第一版阈值为 `1`，即同一锁定目标周期内最多执行一次大角度 Rz。

当同一锁定目标周期内已经执行过一次大角度 Rz，后续视觉又返回 `abs(Rz) >= 80°` 时：

1. 不再下发 Rz 旋转。
2. 记录日志说明：疑似视觉旧帧、帧率滞后或 90° 角度歧义。
3. 本轮 `effectiveRz` 置为 `0.0`，避免继续累计旋转；该帧不再设置大角度等待标志，允许 XY 已收敛时继续进入 Z 下探。

第一版采用“跳过重复大角度 Rz，继续 XY 闭环”的策略，而不是直接停机。原因是现场问题更像视觉旧帧导致的重复角度，直接停机会影响节拍；同时跳过 Rz 可以彻底阻止 360° 累计旋转。

### 6.3 计数生命周期

大角度 Rz 计数在以下时机清零：

- 阶段一启动。
- 阶段一结束、停止、复位或进入下一阶段。
- 视觉目标锁定重置。

计数不应在每一帧视觉结果后清零，否则无法阻止重复 `90°`。

## 7. Z 下探超时规则

阶段一 Z 下探继续使用现有安全上限：

```cpp
HUAYAN_MAX_Z_DESCEND_MM = 1078.0;
```

本轮只调整等待到位超时：

- `PendingCommand::timeoutMs` 默认仍保持 `30000ms`。
- `StageStep::DescendZ` 创建 `PendingCommand` 时单独设置 `timeoutMs = 120000`。

这样长距离 Z 下探最多等待 120 秒；普通 X/Y/Rz 微调、函数调用和其他动作不受影响。

## 8. 日志要求

### 8.1 目标选择日志

闭环跟踪选中目标时，日志应继续包含：

- 候选数。
- 锁定目标坐标。
- 最近锁定距离。
- 丢失帧数。
- 每个候选的 `anchor`、`lockdist`、可信状态。
- 最终选择原因。

锁定后按最近目标选择时，原因使用：

```text
锁定目标连续
```

不应再出现：

```text
锁定同层固定侧
```

除非该原因被保留为历史兼容枚举但不在闭环跟踪分支使用。

### 8.2 Rz 日志

第一次检测到大角度：

```text
[阶段一] 检测到疑似 Rz 大角度跳变 Rz=90.0，等待下一帧确认，本轮不执行 Rz 旋转
```

连续确认并首次允许执行：

```text
[阶段一] Rz 大角度跳变已连续确认 Rz=90.0，允许执行旋转（本目标大角度次数 1/1）
```

重复出现大角度时：

```text
[阶段一] 已执行过 Rz 大角度修正 1/1，当前 Rz=90.0 疑似视觉旧帧或角度歧义，本轮跳过 Rz 旋转
```

### 8.3 Z 下探日志

Z 下探日志保留现有距离说明，并可补充超时值：

```text
[阶段一] Z 下探 1034.8mm（...，到位超时 120000ms）
```

## 9. 验收标准

1. 构造 2026-07-19 日志中的摇摆场景：上一帧锁定目标 `lockdist=28.5`，另一个同层候选 `lockdist=233.7`，闭环必须选择 `lockdist=28.5` 的候选。
2. 初始帧同层两个目标仍按固定侧 Y 选择，保证开局定边逻辑未被破坏。
3. 闭环帧不再出现 `LockTrackingFixedSide` 选择原因。
4. Rz 大角度第一次仍需要两帧确认。
5. 同一目标周期内第二次及后续 `Rz=90°` 不再下发 Rz 微调。
6. 普通小角度 Rz 不计入大角度次数。
7. Z 下探命令单独使用 `120000ms` 到位等待超时。
8. 自动化测试通过，现场日志能明确说明选择目标、跳过重复 Rz 或 Z 超时设置。

## 10. 风险与后续

- 如果视觉接口后续能提供 `frame_id`、`timestamp` 或 `image_id`，应进一步升级为“机械臂动作完成后只接受新帧”，这是解决视觉旧帧的更根本方式。
- 如果现场发现跳过重复 `Rz=90°` 后夹爪方向不满足抓取要求，应改为“第二次大角度直接停机报警”，而不是继续旋转。
- 如果不同工位的正常 `lockdist` 分布差异很大，后续可把 `VISION_LOCK_TRACK_RADIUS_MM` 从全局宏演进为工位级配置。
