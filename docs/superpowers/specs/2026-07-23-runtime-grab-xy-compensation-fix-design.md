# 运行时抓取 X/Y 补偿不生效修复设计

## 背景

运行参数设置中的“抓取 X 补偿”和“抓取 Y 补偿”可以正常编辑、校验、保存并传递到 `HuayanScheduler::m_runtimeSettings`，但阶段一抓取动作仍使用 `huayanScheduler.cpp` 中的编译期常量：

- `kGrabXCompensation = 30.0`
- `kGrabYCompensation = -17.0`

因此，设置界面显示和持久化的数据与机械臂实际执行的数据断开，修改参数后抓取动作仍使用旧的固定值。

## 目标

- 设置保存成功后，从下一次抓取开始使用新的 X/Y 补偿值。
- 正式生产流程与独立抓取测试统一生效。
- 补偿判零、运动方向、运动距离及日志显示均来自同一份运行时设置快照。
- 不改变设备运行期间禁止修改设置的现有安全约束。

## 方案

采用最小修复：在 `HuayanScheduler` 阶段一抓取补偿执行路径中，直接读取：

- `m_runtimeSettings.pickup.grabXCompensationMm`
- `m_runtimeSettings.pickup.grabYCompensationMm`

删除对应的 X/Y 编译期补偿常量，避免出现运行时配置与硬编码值并存。

不新增补偿缓存成员，也不扩展抓取函数参数。运行参数只能在调度器空闲时应用，因此单次抓取期间 `m_runtimeSettings` 不会变化，直接读取快照具备稳定性。

## 数据流

1. 设置对话框生成包含 X/Y 补偿的 `RuntimeSettings`。
2. `SettingsManager` 校验并持久化设置。
3. `DeviceManager` 在设备空闲时将完整快照应用到 `HuayanScheduler`。
4. 下一次阶段一抓取在 Z 下探完成后读取快照中的 X 补偿，生成工具坐标系相对运动指令。
5. X 补偿完成后读取快照中的 Y 补偿，生成下一条相对运动指令。
6. 小于忽略距离的补偿仍按现有规则跳过。

正式生产和独立抓取测试均由同一个 `HuayanScheduler` 阶段一状态机执行，因此无需维护两套实现。

## 错误与安全处理

- 保留现有运行参数有限数值校验。
- 保留 `kOffsetIgnoreDistance` 判零规则。
- 保留现有方向映射：非负值使用正方向，负值使用反方向，运动距离取绝对值。
- 保留调度器忙碌时禁止应用设置的约束。
- 本修复不修改安全移动上限、超时或机械臂坐标系定义。

## 测试

遵循测试驱动开发：

1. 先扩展 `huayan_scheduler_contract_tests`，要求抓取 X/Y 补偿执行路径引用对应运行时字段，并禁止保留两个硬编码常量。
2. 在旧实现上运行该测试并确认因仍使用硬编码值而失败。
3. 实施最小代码修改。
4. 重新运行定向测试，确认通过。
5. 完成 MSVC Release 构建并运行全部 CTest，确保设置、调度、独立抓取和生产流程相关测试无回归。

## 非目标

- 不改变设置界面布局或参数名称。
- 不允许在机械臂任务运行期间热更新补偿值。
- 不修改补偿默认值 `30.0 mm` 与 `-17.0 mm`。
- 不改变 X/Y 工具坐标轴方向定义。
