# 充电统一一键安全预检实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 用一个串行预检意图统一手动开始、自动授权和主调度自动开始，使每次
实际启动都在DO0置高前取得新安全快照，并按已确认规则区分设备安全失败和条件取消。

**架构：** 不新增生产类。`DeviceManager`唯一保存并消费预检意图；
`ChargePileController`继续只负责串行只读查询和原充电状态机；
`AutoChargeCoordinator`继续表达低电启动意图；`MainWindow`只显示异步结果。
纯判断放入现有`chargebusinessrules`，便于不连接真实设备的确定性测试。

**技术栈：** C++17、Qt 6.8.3、Qt Network、Qt SerialBus、Qt Test、CMake、
JOM、MSVC 2022 64位。

- 预检查询明确安全前不得置高DO0，不得发送充电桩Start。

- [ ] **步骤4：实现不放宽最终安全门禁的纯判断**

在`chargebusinessrules.cpp`中实现：

```cpp
QString manualChargePreflightRejectionReason(
    const ManualChargeStartContext &context)
{
    ManualChargeStartContext preflight = context;
    preflight.controllerShutdownRequired = false;
    return manualChargeStartRejectionReason(preflight);
}

QString automaticChargeEnablePreflightRejectionReason(
    const AutomaticChargeEnableContext &context)
{
    AutomaticChargeEnableContext preflight = context;
    preflight.controllerShutdownRequired = false;
    return automaticChargeEnableRejectionReason(preflight);
}

ChargePreflightOutcome classifyChargePreflightOutcome(
    const bool queryOk,
    const ChargePileController::State controllerState,
    const bool controllerShutdownRequired,
    const bool businessConditionsStillValid)
{
    if (!businessConditionsStillValid)
        return ChargePreflightOutcome::Canceled;
    if (!queryOk
        || controllerState != ChargePileController::State::SafeComplete
        || controllerShutdownRequired) {
        return ChargePreflightOutcome::DeviceSafetyFailure;
    }
    return ChargePreflightOutcome::Safe;
}
```

这里只允许首次Idle进入查询，不允许直接进入DO0；查询后的最终续接仍调用原
`manualChargeStartRejectionReason`或`automaticChargeEnableRejectionReason`。

- [ ] **步骤8：实现查询结果续接与失败分类**

`handleChargePreflightFinished()`第一行保存并清除当前意图，随后：

1. 根据意图重新采集业务条件：
   - `ManualStart`重新调用原`manualChargeStartRejectionReason()`；
   - `EnableAutomatic`重新调用原
     `automaticChargeEnableRejectionReason()`；
   - `AutomaticStart`调用
     `automaticStartContinuationRejection()`，明确检查自动授权仍开启、
     主调度不是Idle/Error、AGV快照仍新鲜、当前位置仍为LM1且导航状态仍为
     None或Arrived、应用没有进入关闭流程。
2. 调用`classifyChargePreflightOutcome()`。
3. `Canceled`：
   - 手动/授权发布失败结果；
   - 自动实际启动只向协调器反馈拒绝；
   - 不调用`raiseExternalSystemError`。
4. `DeviceSafetyFailure`：
   - 手动发布失败结果；
   - 自动授权保持关闭并发布失败结果；
   - 自动实际启动先反馈拒绝，再调用
     `m_lineManager->raiseExternalSystemError()`一次，错误文本包含
     “自动充电启动前安全查询失败或状态不安全，需要人工处理”。
5. `Safe`：
   - 手动调用`requestChargeStartWithDo0(Manual)`，并按同步接受结果发布
     `manualChargePreflightFinished`；
   - 自动授权调用`m_autoChargeCoordinator->setEnabled(true)`，再发布
     `automaticChargeEnablePreflightFinished(true, ...)`；
   - 自动实际启动调用`requestChargeStartWithDo0(Automatic)`。

对DO0入口同步拒绝沿用现有回执和日志，不把它伪装成查询设备安全失败。

- [ ] **步骤9：接入Stop、应用关闭和界面反馈**

`stopChargePile()`若存在预检意图，调用`cancelChargePreflight()`并返回真；在途
只读查询可以自然完成，但迟到结果只能作为普通状态更新。

`requestApplicationShutdown()`在请求控制器关闭前取消预检；`AutomaticStart`
必须反馈拒绝以释放协调器待启动锁。

`cancelChargePreflight()`对操作员主动关闭自动功能、Stop和应用关闭只清理意图并
写日志，不发布会导致MainWindow弹警告的手动/授权失败信号；只有查询实际完成后
得到设备失败或条件失效结果，才通过两个界面信号反馈。`AutomaticStart`无论由
何种取消触发，都必须向协调器反馈一次拒绝，避免`startIntentPending`遗留。

MainWindow连接两个新信号：

```cpp
connect(m_devMgr, &DeviceManager::manualChargePreflightFinished,
        this, [this](bool accepted, const QString &message) {
    if (!accepted) {
        QMessageBox::warning(
            this, QStringLiteral("手动充电被拒绝"), message);
    }
    updateChargePanel();
    updateChargeControls();
});

connect(m_devMgr,
        &DeviceManager::automaticChargeEnablePreflightFinished,
        this, [this](bool enabled, const QString &message) {
    if (!enabled) {
        QMessageBox::warning(
            this, QStringLiteral("自动充电授权未生效"), message);
    }
    updateChargePanel();
    updateChargeControls();
});
```

用户主动关闭或应用关闭造成的取消只写日志，不弹设备故障警告。查询期间把现有
`m_chargeDecisionText`设置为“正在确认充电桩安全”。
