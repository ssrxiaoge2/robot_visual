# 自动充电DO0与E11增量实施计划

> **执行要求：** 必须使用 `superpowers:executing-plans` 按任务执行；本计划只有
> 两个任务，每个任务完成代码审查、测试和提交后再进入下一任务，不再为每个小步骤
> 创建子代理。

**目标：** 在不改变已通过现场验证的充电主流程、主调度和界面的前提下，以最小
范围增加仙工AGV的DO0充电许可，并修正启动等待阶段E11立即收尾的问题。

**架构：** 不新增生产类。DO0寄存器通信全部封装在现有 `AgvController`，
`DeviceManager`只在现有手动/自动充电入口和完成出口增加异步门禁；
`ChargePileController`仅修改启动等待阶段的E11判断，其他阶段和安全收尾保持原样。

**技术栈：** C++17、Qt 6.8.3、Qt SerialBus、Qt Network、Qt Test、CMake、JOM、
MSVC 2022 64位。

在 `AgvController` 中增加以下常量和状态，不创建通用IO管理器：

实现顺序固定为：

1. `ensureDo0()`先读 `[1x]00060`。
2. 当前值已经等于目标值时直接成功，不发送写命令。
3. 当前值不同时，高目标只写 `[0x]00060=1`，低目标只写 `[0x]00020=1`。
4. 写响应成功、失败或超时后都进入只读确认，不根据写回显猜测最终电平。
5. 只读最多三次、间隔500毫秒；不得重复发送同一个置高或置低命令。
6. 操作完成或断线时清理忙碌状态和定时器，并且只发布一次完成信号。
7. `queryDo0()`是独立只读操作；DO0确认操作在途时明确拒绝，避免并发拥有同一结果。

- [ ] **步骤5：在DeviceManager现有边界接入DO0**

接入规则：

1. `startManualCharge()`保留全部既有LM1、Idle、导航和控制器门禁，通过后调用
   `requestChargeStartWithDo0(Manual)`，不再直接调用控制器启动。
2. `automaticChargeStartRequested`调用同一入口；只有DO0确认高且控制器真正接受
   会话后，才向 `AutoChargeCoordinator::onAutomaticChargeStartResult()`反馈成功。
3. `Opening`期间重复开始一律拒绝。人工停止、关闭自动开关、主调度进入Stop/Error
   或应用关闭只设置取消标志；DO0确认回调到达后不再启动，并尽力置低DO0。
4. 控制器接受会话后进入 `Active`，启动30秒定时器。每次超时调用
   `queryDo0()`；读到低立即只申请一次 `requestSafeStop(Fault)`，连续三次读取失败
   时执行相同操作，成功读到高则清零失败计数。
5. `chargeSessionFinished`先停止DO0监控并立即请求置低，然后把原来的完成结果转发
   给自动协调器；置低失败只写日志，不修改 `safe`、来源和消息。
6. 应用关闭收到充电桩 `safe == true` 后，等待本次DO0置低尝试完成再发布原来的
   `applicationShutdownFinished(true, message)`；无论DO0确认成功与否都允许退出。
   充电桩 `safe == false` 时保持原逻辑，不把DO0结果提升为安全。
7. 软件启动或AGV重连后，仅在没有待启动或活动会话时查询DO0。若为高，则发起一次
   现有充电桩只读查询；快照明确无工作、继电器断开且电流不高于
   `m_chargeSettings.safeCurrentA`时尽力置低，否则保持高并记录。
8. 不改变 `AutoChargeCoordinator`、`LineManager`、`MainWindow` 和
   `ChargePileController`源码。

```cpp
const bool chargingOutputObserved =
    m_snapshot.extended
    || m_snapshot.working
    || m_snapshot.relayOn
    || m_snapshot.outputCurrentA > m_settings.chargeDetectCurrentA;

    m_snapshot.faultWord & ~kPrestartIgnoredErrors;
```

2. 含E11且已经观察到实际输出：立即安全停止。

4. 从首次E11起未满30000毫秒：只安排下一轮完整快照，不重复启动、不进入监控。
5. 达到30000毫秒仍有E11：安全停止。
6. E11消失且满足启动条件：进入原有 `Monitoring`。
7. E11消失但没有启动条件：继续使用原90秒启动超时；不得重置或延长原启动命令。
8. `pollMonitoring()`和`validatePrestartSnapshot()`保持原有逻辑，确保充电后E11立即
   停止、预检E11继续拒绝。

代码和自动化验证完成后，只准备以下有人监护复测，不在自动执行阶段控制真实设备：

1. 手动开始：确认DO0先变高，再出现充电桩启动命令；结束终检后DO0变低。
2. 自动开始：确认与手动入口执行完全相同的DO0顺序。
3. 充电期间DO0保持高；人工使其变低时只触发一次既有安全停止，不自动重新置高。
4. 启动等待出现短暂E11时，30秒内没有第二次启动命令；E11清除后能够继续充电。
5. E11持续30秒或充电开始后再次出现E11时，执行原五阶段安全收尾。
6. 软件重启且无活动会话时DO0为高：充电桩明确无输出才自动关闭DO0。
