### 4.3 自动关闭旁路专项

执行：

```powershell
ctest -C Debug -R "^(auto_charge_coordinator_tests|line_manager_charge_hold_contract_tests|navigation_timeout_contract_tests|standalone_pickup_contract_tests)$" --output-on-failure
```

结果：4/4 通过，退出码为 0。

对 `src/linemanager.cpp` 的基线差异逐段复核后确认：

- 派单保持在 `tryStartNext()` 调用 `takeNext()` 前检查，保持期间不会取出或回滚队首。
- 任务完成和普通失败后的新分支仅在 `m_chargeDispatchHold` 为真时返回 LM1。
- 返航途中收到新任务时，只有充电保持为真才保留返航；默认路径仍取消返航并执行既有任务。
- Stop、Error 和 Reset 只在保持实际为真时额外清理保持，原有急停、清队列和状态转换语义不变。
- 到达 LM1 后“未保持且存在队列则恢复派单”的状态，只能由一次已建立的充电保持解除后产生；自动功能从未启用时，既有 `reportShortage()` 仍走原取消返航和派单路径。
- `raiseExternalSystemError()` 是充电子系统故障的新增显式入口，自动功能关闭且没有充电故障时不会被调用。

## 八、最终审查修订结果（2026 年 7 月 26 日）

最终安全审查发现并修复三项边界：

1. 安全无输出电流此前允许配置到 120 A，可能把 50 A 实际输出误判为无输出。
   现统一将 `safeCurrentA` 硬上限固定为 Python 权威值 1.0 A。
2. 有限阶段此前可能在接近截止点时继续等待完整轮询间隔。现增加时序组合校验，
   并由确定性纯函数计算下一轮等待的较小值。
3. 安全快照此前可能在缩回线圈恢复上下文未解决时发布 `SafeComplete`。现保持
   `Unknown`，并在手动开始、自动授权和界面参数锁三处直接检查
   `shutdownRequired()`。
